## 5.5 Seller Reporting & Data Delivery

This section introduces the ads reporting system, metric standard specifications, and the data delivery framework.

### 5.5.1 Reporting System Overview

The ads reporting service provides ad performance data for sellers and internal teams, mainly consisting of:

- **Seller Centre Reports**: Seller-facing, displaying impressions, clicks, spend, and GMV at item/campaign/ad granularity
- **Internal Analysis Reports**: For PM/data analyst teams, supporting multi-dimensional cross-analysis
- **Take Rate Reports**: Tracking the ratio of ad revenue to platform GMV

### 5.5.2 Take Rate Analysis

Take Rate is the core metric for measuring ad monetization efficiency:

| Metric | Formula | Basis |
|--------|---------|-------|
| Gross Take Rate | Ad Costs / Platform GMV × 100% | platform_gmv = buyer_checkout_gmv |
| Net Take Rate | Net Ads Revenue / Platform GMV × 100% | Minus rebates, expired amounts |

**Core Analysis Table**: `ads_advertise_take_rate_v2_1d`, containing core ad metrics (impressions, clicks, orders, revenue) and platform tracking metrics (entrance impressions, platform impressions, GMV, NMV).

> For table column details, see [DataMap: ads_advertise_take_rate_v2_1d](../../datamap/mp_paidads.ads_advertise_take_rate_v2_1d__reg_s0_live/)

### 5.5.3 Data Delivery Framework

Data delivery is a cross-project reusable governance framework that standardizes the expression and delivery of data assets:

**Delivery Modes**:
- **API**: Real-time / near-real-time data interfaces
- **Hive Tables**: Offline batch data
- **Dashboard**: Visualization dashboards
- **CSV**: Ad-hoc data exports

**DRD Specification** (Data Requirement Document):
A data requirement document must include: knowledge context, scope metadata, dimension/concept/metric references, data assets and join paths, lifecycle and versioning, acceptance criteria.

**Metric Governance**:
- Metric classification: `metric_class = common` (shared) / `project` (project-level)
- Common dimensions reference `common-dimension-dictionary` via `dimension_key`
- Common metrics reference `common-metric-dictionary` via `metric_key`
- Project-level metrics extend via `project_override` / `project_usage_notes`

### 5.5.4 GMV Reconciliation

Reconciliation is a critical process to ensure consistency between ads attribution GMV and platform GMV.

**Reconciliation Rules**:
1. Unify GMV concepts (seller_gmv vs buyer_checkout_gmv)
2. Unify timezone and event boundaries (order placement vs payment)
3. Recommended reconciliation granularity: region + shop_id + date
4. Precision: round to 1 decimal place to eliminate floating-point residuals

**Known Issue**: Agent GMV upstream still uses the legacy `merchandise_subtotal_amt` path, occasionally causing `ads broad gmv > shop seller gmv`.

> For GMV reconciliation details, see [DPM GMV Reconciliation Guide](../../../team/20.paid-ads-dpm/ads_knowledge_base/shared/guides/gmv-reconciliation-guide_cn.md)
> For data delivery framework, see [DPM Data Delivery](../../../team/20.paid-ads-dpm/ads_knowledge_base/module/data_delivery_cn.md)
