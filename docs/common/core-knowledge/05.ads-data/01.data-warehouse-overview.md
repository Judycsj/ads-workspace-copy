## 5.1 Ads Data Warehouse Overview

This chapter introduces the overall architecture, layering conventions, naming conventions, and core table list of the Shopee Ads Data Warehouse. For the engineering architecture of data services (Kafka/Hive flow), see [§3.6 Ads Data](../03.ads-engine/06.ads-data.md).

### 5.1.1 Data Architecture Concepts

The Ads Data Warehouse is organized around two core concepts:

- **Data Domain**: Organized around clear business topics (e.g., Ads Setup, Trace, Traffic), providing logical grouping for related data assets. It is the basic unit for data asset management, development governance, and responsibility attribution.
- **Analysis Topic**: Focuses on data analysis for specific problem areas (e.g., Take Rate, AB experiment performance), often requiring integration of data across multiple data domains. Analysis topics are dynamic and evolve with business needs.

### 5.1.2 Data Warehouse Layer Convention

The Ads Data Warehouse adopts a standard layered architecture, from bottom to top:

| Layer | Full Name | Definition | Usage Scenario |
|-------|-----------|------------|----------------|
| **ODS** | Operational Data Store | Raw data layer, directly ingested from business systems or logs | Data source integration, rarely queried directly |
| **DIM** | Dimension | Dimension layer, stores descriptive attributes of entities (ads, advertisers, items, etc.) | Join with DWD tables to filter event data; look up entity attributes at a specific point in time |
| **DWD** | Data Warehouse Detail | Detail layer, stores business event details and measures related to dimensions | Ad-hoc analysis for root cause investigation; build temporary metrics not yet provided by other layers |
| **DWS** | Data Warehouse Summary | Summary layer, aggregates business events by common dimensions | Use pre-computed metrics to improve query performance; obtain enterprise-wide aligned metrics |
| **ADS** | Application Data Store | Application layer, integrates metrics from single or multiple data marts | Provide input to downstream products (Campaign Station, Seller Centre); look up specific entity metrics for reports |

Example tables for each layer:

- **DIM**: `dim_advertise`, `dim_advertiser`, `dim_campaign`
- **DWD**: `dwd_advertise_performance_di`, `dwd_advertise_tracking_item_hi`, `dwd_advertiser_deduction_di`, `dwd_advertise_order_attribution_di`
- **DWS**: `dws_advertise_performance_1d`, `dws_advertise_item_performance_1d`, `dws_advertiser_balance_td`
- **ADS**: `ads_advertise_mkt_1d`, `ads_advertiser_mkt_1d`, `ads_advertise_take_rate_v2_1d`

> Full field details for each table can be found in the [DataMap Index](../../datamap/)

### 5.1.3 Table Naming Convention

**Entity Naming**:

| Entity | Name | Description |
|--------|------|-------------|
| Ad | `advertise` (abbreviation `ads`) | Ad delivery unit |
| Advertiser | `advertiser` | Seller's identity as an advertiser |
| Campaign | `campaign` | Ad group sharing budget and strategy |
| Item | `item` | Promoted product |
| Entrance | `entrance` | Frontend area where ads are displayed |
| Location | `location` | Specific display position within the area |

**Naming Conventions by Layer**:

| Layer | Format | Example |
|-------|--------|---------|
| ODS (DB Table) | `ods_[ingestion method]_{database name}__{table name}_{frequency}__{region}_{security}_{environment}` | `ods_shopee_order_v4_db__order_v4_tab_df__reg_s1_live` |
| ODS (Log) | `ods_log_[business]_{module}_{frequency}__{region}_{security}_{environment}` | `ods_log_search_ads_tracking_hi__reg_s0_live` |
| DIM | `dim_{dimension name}_[extension]__{region}_{security}_{environment}` | `dim_common_item__reg_s0_live` |
| DWD | `dwd_{domain}_{granularity}_{event}_[remark]_{frequency}__{region}_{security}_{environment}` | `dwd_advertise_performance_di__reg_s0_live` |
| DWS | `dws_{dimension}_{event}_[remark]_{window}__{region}_{security}_{environment}` | `dws_advertise_performance_1d__reg_s0_live` |
| ADS | `ads_[remark]_{window}__{region}_{security}_{environment}` | `ads_advertise_take_rate_v2_1d__reg_s0_live` |

**Field Naming Convention**: Entity abbreviation (e.g., `advertise` → `ads`), separated by underscores.

The following fields have standard enum value definitions (see column_info of each table for specific value lists):

| Field | Description |
|-------|-------------|
