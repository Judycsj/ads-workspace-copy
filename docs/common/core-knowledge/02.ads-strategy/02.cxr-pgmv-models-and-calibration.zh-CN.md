## 2.2 CXR & PGMV 模型和校准/CXR & PGMV Models and Calibration

### 2.2.1 CXR & PGMV 模型的定位及挑战/Positioning and Challenges of CXR & PGMV Models

[§1.3.2.2](../01.ads-overview/03.system-pipeline-modules.zh-CN.md#1322-价值预估) 介绍了广告系统价值预估的三个核心模型（pCTR、pCVR、pGMV）。本章将深入展开这些模型的建模细节。其中 **CXR** 是 pCTR 和 pCVR 等点击/转化率预估模型的统称（C = Click/Conversion， X = 各类转化事件， R = Rate），**PGMV** 则是成交金额预估模型。

**预估模型体系：**


| 模型         | 英文全称                              | 说明                                             | 建模类型 |
| ---------- | --------------------------------- | ---------------------------------------------- | ---- |
| pCTR       | Predicted Click-Through Rate      | 预测用户点击广告的概率                                    | 分类   |
| pCVR / pCR | Predicted Conversion Rate         | 预测点击后发生转化（下单）的概率。行业通用术语为 pCVR，系统内部简写为 pCR，两者等价 | 分类   |
| pGMV       | Predicted Gross Merchandise Value | 预测广告带来的成交金额 GMV，在已有 order 前提下预估                | 回归   |


**核心挑战：**

预估模型的精度直接影响广告主 ROI、平台广告收益和商品售卖效率，主要面临以下挑战：

- **样本稀疏**：转化事件（尤其 order）相比点击和曝光数量级更低， pCVR 和 pGMV 的训练信号稀疏
- **分布偏移**：线上流量分布持续变化，模型需要良好的泛化能力和及时的校准机制
- **多目标权衡**： pCTR、pCVR、pGMV 三个模型需在同一网络中联合建模，目标间存在竞争与协同

#### 2.2.1.1 Product Ads pCTR 模型说明/Product Ads pCTR Model

Product Ads 线上链路中出现的 `pctr` 是复用 Organic pCTR，但是广告会按照广告计费口径做 pCTR 校准模型，因此，Product Ads pCTR 有独立的训练样本（AFP Scene 82，见 §2.2.5.2）和独立的 serving 链路（CTR TrainData 路径 `.../train_data_parquet/ctr/all`）。

在 §2.2.5.1 的 eCPM 公式中：

```text
ecpm = pctr * (direct_pcr_7d * cali_direct_pgmv_7d + shop_pcr_7d * cali_shop_pgmv_7d) * target_cir
```

其中 `pctr` 来自独立的 pCTR 模型，`direct_pcr_7d` / `shop_pcr_7d` 来自 UniCR 模型。两者是不同的模型，分别预估点击概率和点击后转化概率。

OrgPredict 特征（slot 1003 `I_pctr_online`、slot 1004 `I_pcr_online`）是上一轮模型的预估分数作为 UniCR 的输入特征，仅在 Search 入口有效，这与 pCTR 模型本身是独立模型不矛盾。

#### 2.2.1.2 Product Ads pCTR 与 pCR 校准策略/Product Ads pCTR and pCR Calibration Strategy

Product Ads 的 pCTR 和 pCR（UniCR 的 CR head）各有不同的校准策略：

| 模型 | 校准机制 | 说明 |
|---|---|---|
| **pCTR** | 当前以模型自身输出为主，无独立的在线后校准系统 | pCTR 作为 eCPM 公式的基础乘子，主要通过模型训练本身保证校准质量；离线评估中检查 PCOC 和 ECE |
| **pCR (UniCR direct/shop)** | 通过 pGMV cali 间接校准 | UniCR 的 CR 输出参与 pGMV 计算（`pGMV = price * sold_cnt * CR_7d`），pGMV 层面由 SIR/ItemCali 系统做在线后校准（§2.2.5.6）。CR 本身在评估时检查 PCOC（见 §2.2.5.3 check_metrics），但无独立的在线后校准层 |
| **pGMV** | SIR + ItemCali + 大促修正 | 完整在线后校准系统（§2.2.5.6），是当前校准投入最重的环节 |

换言之，Product Ads 当前的校准重心在 pGMV 层面，pCTR 和 pCR 主要依赖模型训练质量和离线评估门限保障校准精度，暂无独立的在线后校准系统。

### 2.2.2 广告归因和模型 Label/Ad Attribution and Model Labels

[§1.2.5](../01.ads-overview/02.online-advertising-fundamentals.zh-CN.md#125-广告归因模型) 介绍了广告归因的通用框架： Click/View 归因类型、Last Touch 优先级规则，以及 Direct 与 Broad 两种归因方式。本节将在此基础上，说明 ROI2 产品如何落地这些归因规则，以及归因结果如何转化为模型训练的 Label。

**ROI2 归因口径：**

基于 [§1.2.5.3](../01.ads-overview/02.online-advertising-fundamentals.zh-CN.md#1253-direct-vs-broad-归因) 的 Direct/Broad 分类， ROI2 将归因范围从 Direct Ads Order 扩展到 Broad Ads Order， bundling 付费流量和自然流量，以更完整地衡量广告价值（AdvV）：


| 归因类型             | 判断逻辑                          | 说明                  |
| ---------------- | ----------------------------- | ------------------- |
| Direct Ads Order | 按时间逆序在用户 7 天点击序列中查找 itemID 匹配 | 转化商品与点击广告商品一致       |
| Shop Ads Order   | itemID 无匹配后，查找 shopID 匹配      | 转化商品与点击广告同一店铺（不同商品） |
| Broad Ads Order  | Direct ∪ Shop（两者互斥，交集为空）      | ROI2 广告的考核口径        |


归因窗口：两种订单均采用 **7 天归因窗口**。

归因判定流程：

```
Order 发生 → 根据 userID 查找 7 天内点击序列
  → 按时间逆序查找 itemID 匹配 → Direct Ads Order
  → 若无 itemID 匹配，查找 shopID 匹配 → Shop Ads Order
  → 都无匹配 → 不归因
```

**从归因到模型 Label：**

归因规则决定了哪些 order 算作广告转化，进而定义模型的训练 Label。以 Unicr 模型为例：


| Label                               | 用途                    |
| ----------------------------------- | --------------------- |
| direct 7d CR                        | 7 天直接转化率，用于线上 Serving |
| shop 7d CR                          | 7 天店铺转化率，用于线上 Serving |
| direct 3d/7d prob、direct 1d/3d prob | 延迟转化概率建模辅助目标          |
| shop 3d/7d prob、shop 1d/3d prob     | 延迟转化概率建模辅助目标          |


其中 `direct` 和 `shop` 两类 Label 分别对应上述两种归因类型，而 `3d/7d prob`、`1d/3d prob` 等辅助目标用于缓解 7 天归因窗口带来的延迟反馈问题（详见 [§2.2.3](#223-样本生产和模型例行)）。

**为什么 direct 和 shop 要独立建模？**

Direct 转化（点击商品 = 购买商品）和 Shop 转化（点击商品 A → 购买同店商品 B）是两种本质不同的用户行为：

- **转化路径不同**： Direct 是"种草即拔草"的短路径决策； Shop 涉及店铺浏览、跨商品比较等额外环节，转化漏斗更长
- **特征信号不同**： Direct 转化主要由商品本身的吸引力驱动（价格、评分、图片）， Shop 转化更依赖店铺维度的特征（店铺品类丰富度、用户对店铺的历史偏好）
- **转化率量级不同**： Shop CR 通常远低于 Direct CR，混合建模会导致高频类别主导梯度，低频类别欠拟合

独立建模使每个 Label 有各自的 prediction head，模型可以学到不同归因类型下用户行为的差异化模式。线上 Serving 时，两个预估值也分别用于 ROI2 的 AdvV 计算。

> **关于合并 vs 拆分的实验**：当前 KB 未记录是否做过 direct/shop 合并建模的 AB 对比实验。从架构设计角度，拆分建模的决策基于上述三点本质差异（路径、特征信号、转化率量级），属于先验驱动的设计选择。若需了解是否有历史实验数据支撑，**需人工补充**。

### 2.2.3 样本生产和模型例行/Sample Production and Model Routine

**延迟反馈样本处理**：对于点击后不满 7 天的样本，其负标签可能包含假负样本。为兼顾模型时效性（竞价环境实时变化），通常宁愿使用部分标签有误的最新样本，也不放弃时效性。

**模型例行更新流程（3 阶段）：**


| 阶段                          | 说明                                                                                        |
| --------------------------- | ----------------------------------------------------------------------------------------- |
| **Stage 1 - Seed Round 训练** | 仅使用完全归因样本（T-8 前数据），加载 T-8 checkpoint，训练 T-7 数据，生成完全归因模型 checkpoint                        |
| **Stage 2 - 增量训练**          | 加载 Stage 1 生成的 T-7 Seed checkpoint，增量训练 6 天（T-6 至 T-1）非全归因样本，生成 Online Serving checkpoint |
| **Release**                 | 将 Stage 2 生成的 Online Serving checkpoint 发布到线上服务                                           |


这种"全归因 Seed + 增量非全归因"的组合策略，兼顾了模型准确性（Seed 模型消除假负样本）和时效性（增量训练利用最新数据）。

**延迟反馈多窗口设计原因/Why Multiple Time Windows：**

UniCR 使用 1h、6h、1d、3d、7d 五个窗口，每个窗口的选择有明确的业务和技术依据：

| 窗口 | 选择原因 |
|---|---|
| **1h** | 捕捉即时购买行为（冲动消费、限时促销），线上可用于实时竞价场景中的快速估值反馈 |
| **6h** | 覆盖当日浏览后购买的典型路径（"逛完再买"），是 1h 与 1d 之间的平滑过渡 |
| **1d** | 覆盖"当天犹豫、隔天下单"场景，1d 回流率已覆盖约 85% 的最终转化 |
| **3d** | 覆盖比价、发薪周期、周末集中购买等中期决策行为 |
| **7d** | ROI2 广告归因窗口上限，是业务最终口径；但 7d 样本存在假负样本问题 |

这种级联设计（`CR_7d -> CR_3d -> CR_1d -> PCR_6h -> PCR_1h`）使模型能够在标签完整性和时效性之间灵活选择。

**Seed 与 Increment 梯度路径差异/Gradient Path Differences Between Seed and Increment：**

Seed 和 Increment 不仅数据窗口不同，梯度回传路径也有本质差异：

| 阶段 | 梯度路径 | 可更新参数范围 | 设计意图 |
|---|---|---|---|
| **Seed** | 全网络梯度回传，无 `stop_gradient` 限制 | 完整网络：backbone（MMOE-STAR Expert）+ 所有 Tower | 用完整归因数据从 model bank 重建稳定参数基线 |
| **Increment** | 在 MMOE-STAR backbone 输入处施加 `tf.stop_gradient` | 仅 Tower 参数（CR/Delay/O2P/ACT 各塔） | 用不完整归因数据微调 Tower，避免假负样本污染共享 Expert |

这意味着 Increment 阶段的 backbone Expert 权重被冻结，只有各任务塔在新鲜数据上更新。这一设计防止了标签噪声（假负样本）通过梯度传播到共享表征层，同时保持了 Tower 的时效性适应。

### 2.2.5 商品卡 UniCR 与 pGMV 模型/Product Ads UniCR and pGMV Models

Product Ads 精排阶段使用 **UniCR** 作为核心转化率与 pGMV 预估模型。UniCR 不只是判断“一次点击会不会转化”，而是预估点击后的商业价值，并把校准后的价值输入出价和 rerank。

核心 pGMV 公式为：

```text
pGMV = item_price * sold_cnt_smoothed * CR_7d
```

其中 `sold_cnt_smoothed` 在 `x <= 2` 时保持原值，在 `x > 2` 时使用 `2 + log(x - 1)`。UniCR 同时建模 direct 与 shop 两路价值：

| 输出族 | 示例 | 线上作用 |
|---|---|---|
| Direct CR / pGMV | `direct_pcr_7d`、`direct_pgmv_7d` | 点击广告商品本身带来的价值 |
| Shop CR / pGMV | `shop_pcr_7d`、`shop_pgmv_7d` | 同店其他商品带来的价值 |
| 延迟反馈 Head | `direct/shop_pcr_{1h,6h,1d,3d}` | 用短窗口转化反馈提升时效性 |
| Order2Pay / ATC | `direct/shop_order2pay`、`ads_direct/shop_atc` | 辅助购买意图任务 |

Product Ads pGMV 长期面对五类问题：多场景流量（`search`、`dd`、`ymal`、`pp`）、7 天转化延迟反馈、direct/shop 多任务学习、长行为序列建模，以及大规模特征体系下的 train-serving 一致性治理。

**Product Ads 粗排模型/Product Ads Prerank Model：**

Product Ads 精排前有粗排（Prerank）阶段，负责从召回候选中快速筛选出精排候选（当前上限约 400 个 item）。粗排模型相比精排（UniCR）有以下关键差异：

| 对比维度 | 粗排（Prerank） | 精排（UniCR） |
|---|---|---|
| 候选量级 | 数千级 | 约 400 |
| 模型复杂度 | 轻量级，减少特征数和网络深度 | 完整 MMOE-STAR 多任务架构 |
| 行为序列 | 通常缩短或简化 | click 500 / cart 128 / order 128 |
| 延时要求 | 严格（毫秒级） | 相对宽松 |
| 输出 | 粗排分数，用于截断候选 | 多任务输出（CR/pGMV/O2P/ATC） |

> 粗排模型的详细架构和特征配置在当前 KB 中未展开，具体实现见代码仓库 `paidads-alg` 中的 prerank 相关模块。

**正负样本不均衡处理/Positive-Negative Sample Imbalance Handling：**

广告转化事件天然存在严重的正负样本不均衡。以 ID 地区 UniCR 训练数据为例（§2.2.5.3 样本后验）：

| Target | 正样本率 | 正:负比例 |
|---|---|---|
| `direct_pcr_7d` | 3.51% | 约 1:28 |
| `shop_pcr_7d` | 0.53% | 约 1:188 |
| `ads_shop_atc` | 1.66% | 约 1:59 |

UniCR 当前应对正负样本不均衡的主要策略：

1. **多任务辅助学习**：通过 ATC（加购率约 17.77%）和 Order2Pay（正样本率约 80%）等高频辅助任务，为稀疏的 CR 目标提供更稠密的梯度信号
2. **样本级权重（`label_weight`）**：根据标签回流状态动态设置权重，未回流的样本 `label_weight=0`，避免假负样本参与训练
3. **条件概率级联**：将 CR_7d 通过 1h/6h/1d/3d 级联分解，短窗口正样本率更高，梯度更稳定
4. **多窗口联合训练**：`final_loss = cr_loss + order2pay_loss + delay_feedback_loss + act_loss`，四组 loss 均使用 BCE 并按样本权重加权，不额外做 oversampling 或 undersampling
5. **Seed + Increment 训练范式**：Seed 使用完整归因数据确保标签质量；Increment 冻结 backbone 仅更新 Tower，降低假负样本对共享参数的影响

当前未使用 focal loss、SMOTE 等显式不均衡处理技术。主要通过多任务学习和训练范式设计间接缓解不均衡问题。

#### 2.2.5.3 训练范式、延迟反馈和评估/Training Routine, Delayed Feedback, and Evaluation

**Embedding 与 Dense 分组设置学习率/Different Learning Rates for Embedding vs Dense：**

用两个独立 Optimizer 分别管理：embedding 推荐 `AdagradOptimizer(lr=0.01)`，dense 推荐 `AdamOptimizer(lr=1e-3)`；或对梯度乘缩放系数实现 LR 倍率。EGO `task.yaml` 在 `optimizer` 块分组配置。Increment 阶段 backbone 已被 `stop_gradient` 冻结，无需额外设置其 LR。

延迟反馈通过条件概率级联建模：

```text
CR_7d <- 主塔输出
CR_3d = cr_3d_prob * CR_7d
CR_1d = cr_1d_prob * CR_3d
PCR_6h = prob_6h * CR_1d
PCR_1h = prob_1h * PCR_6h
```

当长窗口 label 尚未回流时，对应短窗口条件概率通过 `label_weight=0` 和条件性 `stop_gradient` 阻断，避免假负梯度。源 KB 记录了 2026-04-12 的 ID 离线评估快照：`direct_pcr_7d` AUC 0.8551、`shop_pcr_7d` AUC 0.9093、`direct_order2pay` AUC 0.7716、`shop_order2pay` AUC 0.7973，1h/6h/1d/3d/7d 延迟 Head AUC 也保持在相近区间。这些数值是历史示例，不是当前线上 SLO。

#### 2.2.5.5 模型架构和 Domain 建模/Model Architecture and Domain Modeling

UniCR 是基于 `MMOE-STAR` 的多任务、多 domain 架构：

```text
特征编码
-> EpNet domain-aware gating
-> FINT 二阶特征交叉
-> MMOE-STAR 多任务主干
-> CR / delay / ATC / Order2Pay 多个输出塔
-> price * sold_cnt * CR_7d 组合 pGMV
```

| 模块 | 作用 |
|---|---|
| `AutoDisLayer` | 将连续特征编码成 embedding |
| `OneHotToEmbeddingLayer` | 将 one-hot 统计转换为稠密 embedding |
| `HardBucketizeLayer` | 对 OrgPredict 分数做硬分桶后 embedding |
| `SimpleAttentionV3` | 从行为序列中抽取目标相关兴趣 |

**SimpleAttentionV3 计算公式/SimpleAttentionV3 Formula：**

`SimpleAttentionV3` 是 DIN（Deep Interest Network）风格的 target attention 机制，用于从用户行为序列中提取与目标商品相关的兴趣表达。其核心计算流程：

```text
输入：
  target: (batch, 4, 16)    -- 目标商品的 4 个 ID embedding (item_id, shop_id, subcat, thirdcat)
  sequence: (batch, L, 4, 16) -- 行为序列中每个商品的 4 个 ID embedding

Step 1: 逐 field 计算 attention weight
  对每个 field f in {item_id, shop_id, subcat, thirdcat}:
    a_f(i) = MLP([target_f, seq_f(i), target_f - seq_f(i), target_f * seq_f(i)])
    -- MLP 输入为 target 与序列第 i 个元素的 concat、差值和元素积
    -- 输出标量 attention score

Step 2: 归一化（不做显式 softmax，直接用原始 score 加权）
  weight(i) = sum_f(a_f(i))   -- 多 field score 求和

Step 3: 加权池化
  output = sum_i(weight(i) * concat(seq(i)))  -- 加权聚合序列 embedding
```

与标准 DIN 的区别：SimpleAttentionV3 对多个 ID field（itemid/shopid/subcat/thirdcat）分别计算 attention score 后求和，而非在拼接后的完整 embedding 上计算单一 score。这种多 field 分别打分的设计允许模型分层捕捉不同粒度的兴趣匹配（商品级 vs 类目级 vs 店铺级）。

> 注：以上为基于代码类名 `SimepleAttentionV3` 的推导描述，具体实现细节（如 MLP 层数、激活函数）以源码为准。
| `EpNetLayer` | 对特征 embedding 做 domain-aware gating |
| `fint_interaction_layer` | 建模二阶特征交叉 |
| `MMOESTAR` | 在 domain 和 task 之间共享 expert，同时保留 domain-aware 输出 |
| `Order2PayLayer` / `ActLayer` / `ProbHourLayer` | 辅助购买意图和延迟反馈 Head |

`STAR` domain 来自 `ctx_entrance` 映射，而不是原始流量文本：

| Entrance ID | Domain index | 含义 |
|---|---:|---|
| other | 0 | 默认 / fallback |
| 1 | 1 | Search |
| 3 | 2 | Daily Discover |
| 4 | 3 | YMAL |
| 8, 9, 10, 11 | 4 | Product Page 及相关入口 |

ID 与 L2 的有效主特征族基本一致，但 L2 通过 `REGION_DENSE_SLOT=46354`、`REGION_SPARSE_SLOT=30585`、`num_regions=8`，以及 region-aware `HardBucketizeLayer` / `AutoDisLayer` 保留 region-conditioned 处理。BR 仍是源码级待确认项。

#### 2.2.5.6 pGMV 校准系统/pGMV Calibration System

Product Ads pGMV cali 是一套在线后校准系统，用来把 UniCR 原始 pGMV 映射到更接近真实 GMV 的区间：

```text
UniCR raw pGMV
-> SIR / ALL 粒度校准
-> ItemCali item 粒度 scale
-> 大促时间修正
-> 门控、融合和限幅
-> cali_direct/shop_pgmv_7d_v2 及大促版本
```

| 组件 | 代码 / 数据 | 作用 |
|---|---|---|
| SIR | `layers/sir_new_v2.py`，slots `16501~16523`，FSE `ads.cali_segment_data_v3` | 分段单调线性校准 |
| ItemCali | `layers/item_cali.py`，slots `6136~6182`，FSE `ads.cali_item_data_v3_agg_rt` | item 级 `GMV / pGMV` scale，带订单数和异常 scale 门控 |
| 大促修正 | `layers/fix_ar_ratio_v2.py`，slots `6200`、`6201`、`8888` | 修正大促期间到达口径 GMV 与点击归因 GMV 的错位 |
| 融合门控 | `item_cali_main.py` | 仅在订单数和 scale 条件满足时使用 `0.5 * ItemCali + 0.5 * SIR` |
| 限幅 | 模型侧 clipping 阈值 | 按地区和场景限制校准幅度 |

SIR 融合 1h 与 24h 统计：MY/ID/VN/PH/BR 使用 `[0.9, 0.1]`，SG/TH/TW 使用 `[0.8, 0.2]` 以增强稳定性。SG/TH 使用 5 桶，其他地区使用 10 桶；5 桶数据 pad 到 11 维以对齐 10 桶形状。

ItemCali 计算方式：

```text
scale = item_GMV_sum / item_pGMV_sum
final_score = 0.9 * (pGMV * scale_1d) + 0.1 * (pGMV * scale_3d)
```

它只在 `broad_order_cnt >= 15` 且 `scale_3d < 2/3 or scale_3d > 2` 时参与融合，否则退回 SIR。大促修正使用：

```text
prom_ratio = 点击归因口径 GMV / 到达口径 GMV
SIR_prom = SIR_normal * prom_ratio
```

大促窗口为按 region offset 调整后开始时间附近的 `[-120h, +24h)`；窗口外 `prom_ratio` 强制为 1。

**pCTR 校准目标和方法/pCTR Calibration Target and Methods：**

pCTR 是所有 eCPM 公式的基础乘子（`ecpm = pctr * value * target_cir`），其校准偏差直接影响竞价公平性和平台收入。

| 维度 | 说明 |
|---|---|
| 校准目标 | 使 `E[pCTR] ≈ E[actual CTR]`，即整体 PCOC 接近 1.0 |
| 主要评估指标 | 整体 PCOC、分桶 PCOC、ECE（Expected Calibration Error）、Brier Score |
| 当前校准机制 | Product Ads pCTR 当前主要依赖模型训练本身保证校准质量，无独立的在线后校准系统（不同于 pGMV 有 SIR/ItemCali） |
| 关注切片 | region、entrance、placement；不同切片的 PCOC 差异需要关注 |

**pCVR 校准问题拆解/pCVR Calibration Issue Analysis：**

pCVR（即 UniCR 的 `direct_pcr_7d` / `shop_pcr_7d`）的 PCOC 不准可能由以下因素导致：

| 因素 | 影响路径 | 说明 |
|---|---|---|
| **延迟反馈假负样本** | 训练标签偏差 -> 模型系统性高估 negative | 7d 窗口内标签未完整回流导致部分正样本被标为负，尤其 Shop 路延迟回流更显著（Shop 1h 回流率约 66.5% vs Direct 约 84.5%） |
| **样本分布偏移** | 训练与线上分布不一致 | Seed 数据为 T-8，与线上 T-0 存在分布偏移；Increment 可部分缓解但标签不完整 |
| **Direct/Shop 正样本率差异** | 梯度主导不均衡 | Shop CR 约 0.53% 远低于 Direct CR 约 3.51%，Shop 路的校准难度更大 |
| **场景间分布差异** | 模型难以同时校准所有场景 | Search 有 OrgPredict 特征、DD/YMAL/PP 无，导致不同场景的预估偏差方向可能不同 |
| **OrgPredict 仅 Search 有效** | 非 Search 场景信息缺失 | OrgPredict 被 mask 为 0 的场景中，模型对排序先验的依赖断裂 |

**复用 Organic pCTR 的问题分析/Issues with Reusing Organic pCTR：**

虽然 Product Ads 有独立的 pCTR 模型，但系统中部分环节可能参考了 Organic pCTR（如 OrgPredict 特征 slot 1003）。直接复用 Organic pCTR 作为广告 pCTR 存在以下问题：

| 问题 | 说明 |
|---|---|
| **广告标签差异** | 广告和自然结果的点击模式不同：广告有 badge、位置偏差、出价影响；Organic CTR 反映的是无广告干预下的点击概率 |
| **样本空间不同** | 广告仅展示在付费流量位，样本分布与 Organic 不同；用户对广告位的心智也不同 |
| **校准偏差传导** | 如果 Organic pCTR 存在系统性偏差，直接复用会把偏差带入广告 eCPM 计算 |
| **缺乏广告专属信号** | 出价方式（CPC/ROI）、placement、pricing_type 等广告独有信号无法被 Organic 模型捕捉 |

因此 Product Ads 使用独立的 pCTR 模型（AFP Scene 82），OrgPredict 仅作为 UniCR 的输入特征使用。

**校准系统的主要问题总结/Main Issues of the Calibration System：**

当前 pGMV cali 系统的主要问题和局限：

| 问题类别 | 具体表现 | 影响 |
|---|---|---|
| **SIR 分桶粒度粗** | 仅 5~10 个桶，同桶内异质性高 | 同桶内不同价格段/类目的 item 被同等对待 |
| **ItemCali 门控严格** | 需 `broad_order_cnt >= 15` 且 scale 异常才启用 | 大量长尾 item（低单量）无法享受 item 级校准 |
| **1h/24h 统计融合的延迟** | 1h 统计有噪声，24h 统计有延迟 | 实时性与稳定性的 trade-off |
| **大促修正依赖人工配置** | `prom_ratio` 参数需运营提前 2 天手动写入 FSE | 配置延迟或遗漏会导致大促期间校准失效 |
| **cali 与模型独立** | cali 是后处理，无法反馈到模型训练 | 模型本身的系统性偏差需靠 cali 外部修正 |
| **pCTR/pCR 无独立 cali** | 校准重心完全在 pGMV 层 | pCTR 或 pCR 的系统性偏差无法被针对性修正 |

**缺陷与解决方案对照/Known Deficiencies and Solutions：**

| 缺陷 | 当前解决方案 | 局限 |
|---|---|---|
| SIR 分桶稀疏 | `merge_bucket` 合桶约束（最小样本量、最小 GMV、单调递增） | 合桶后桶数更少，局部校准精度受损 |
| 长尾 item 无 ItemCali | Fallback 到 SIR | SIR 粒度粗，长尾 item 校准偏差大 |
| 大促 ratio 滞后 | 运营提前配置 + L-BFGS-B 历史拟合 | 无法自适应调整，新品类/新大促模式适用性差 |
| 限幅过宽或过窄 | 按地区和场景设置不同 thre | 阈值为经验值，缺乏自适应机制 |

**将校准融入 PGMV 模型的可行策略/Strategies for Integrating Calibration into the PGMV Model：**

当前 UniCR 采用**外挂后校准**（SIR + ItemCali），如果希望将校准能力内化到 pGMV 模型本身，有以下两条可行路径：

| 策略 | 说明 | 优缺点 |
|---|---|---|
| **新增辅助 loss** | 在 pGMV 模型中新增一个辅助 loss，直接优化 PCOC（`sum(pred) / sum(actual)` → 1.0）；通过梯度反传让模型自身学习校准能力 | 无需额外推理开销；但 PCOC 作为全局目标难以做细粒度分桶控制 |
| **级联轻量小网络** | 在 pGMV 输出层后新增一个轻量小网络，专门做端到端的校准映射；相当于把 SIR/ItemCali 逻辑集成进模型 | 可做 item/segment 粒度校准；引入额外推理延时和参数 |

两种策略均为**探索方向**，尚未在生产环境上线。

**pricing_type / placement 特征评估/pricing_type and placement Feature Evaluation：**

`pricing_type`（出价方式）和 `placement`（广告展示位置）已作为特征加入 UniCR 模型（通过 Extra slot 和 Sparse slot）。其中 `I_Placement_reader`（slot 1011）记录广告展示位置类型。

当前 KB 中**未记录这两个特征的独立效果评估数据**（如加入前后的 AUC/PCOC 变化）。从 feature importance 评估结果看，这两个特征不在 Top 10 高重要度特征中，排名相对靠后，**具体效果评估数据需人工补充**。

**Item 粒度 PCoC 分析方法/Item-Level PCoC Analysis Method：**

在 item 粒度评估 pGMV 校准质量时，推荐以下分析步骤：

1. **基础聚合**：按 `item_id` 聚合 `sum(final_pred_pgmv)` 和 `sum(actual_total_gmv)`，计算 `item_pcoc = sum(pred) / sum(actual)`
2. **分桶分布**：将 item 按 `item_pcoc` 分桶（如 [0,0.5), [0.5,0.8), [0.8,1.2), [1.2,2.0), [2.0,+inf)），统计各桶 item 数和 GMV 占比
3. **切片下钻**：按 `region`、`entrance`、`category` 切片，分析哪些切片的 item PCOC 偏差最大
4. **对比 raw vs cali**：对比 `raw_pred_pgmv` 和 `cali_pred_pgmv` 的 item PCOC，评估 cali 对 item 粒度校准的改善效果
5. **结合 ItemCali 门控**：区分 `broad_order_cnt >= 15` 和 `< 15` 的 item 群体，分别评估 PCOC
6. **尾部 item 分析**：关注 PCOC > 2.0 或 < 0.5 的 item，分析其共性特征（如低单量、新品、特殊类目）

#### 2.2.5.7 数据契约和分析口径/Data Contracts and Analysis Definitions

Product Ads UniCR 与 cali 分析当前入口表是：

```text
mkplpaidads_search_ads.item_basic_info_for_cali_and_case
```

该表是点击归因明细表，用于分析业务规模、价值结构和预测质量。已确认的预测字段：

| 语义字段 | 当前字段 | 用途 |
|---|---|---|
| `raw_pred_pgmv` | `direct_pgmv_7d_sum` | cali 前原始模型预估 |
| `cali_pred_pgmv` | `cali_direct_pgmv_7d_sum` | 校准后预估 |
| `final_pred_pgmv` | `final_pgmv_sum` | 首轮分析默认预测字段 |

仍需 schema 确认的字段包括 `pred_shop_pgmv_7d`、`actual_direct_gmv_7d`、`actual_shop_gmv_7d`、`actual_total_gmv`、`dt / region / entrance / placement`，以及 `request_id / item_id / shop_id` 等点击粒度主键。

推荐分析顺序：

1. 规模：点击量、请求数、item 数、shop 数、真实 GMV 和预测 pGMV。
2. 结构：direct / shop GMV 占比、预测结构与真实结构。
3. 预测质量：`PCOC_final`、`PCOC_direct`、`PCOC_shop`、总偏差和 WMAPE。
4. 切片：`region`、`region x entrance`、`region x entrance x placement`。
5. 排序质量：分桶单调性、Top bucket GMV capture、分桶 PCOC。

标准派生指标：

```text
PCOC_final = sum(final_pred_pgmv) / sum(actual_total_gmv)
WMAPE      = sum(abs(final_pred_pgmv - actual_total_gmv)) / sum(actual_total_gmv)
```

在 schema 未确认前，不要把 `final_pgmv_sum` 强行等同于简单的 `direct + shop` 相加。

**校准评价指标体系/Calibration Evaluation Metrics**

校准（calibration）衡量模型预估值作为概率的准确性，与排序指标（AUC/GAUC）互补但不同——AUC 衡量排序能力，**AUC 高不等于校准好**。以下指标适用于 pCTR、pCVR 和 pGMV 的校准评估：

| 指标 | 公式 | 说明 |
|---|---|---|
| **PCOC** (Predicted/Observed Ratio) | `sum(predicted) / sum(actual)` | 整体校准偏差，理想值 1.0；分桶 PCOC 可检测局部偏差 |
| **ECE** (Expected Calibration Error) | `sum(n_k / N * abs(avg_pred_k - avg_actual_k))` | 按预估分桶后各桶 pred-actual 差异的加权平均，越小越好 |
| **Brier Score** | `mean((predicted - actual)^2)` | 同时反映校准和排序，二分类场景适用（pCTR/pCVR） |
| **Reliability Diagram** | 校准曲线（predicted vs actual by bucket） | 可视化工具，理想曲线为 y=x 对角线 |
| **分桶单调性** | 按预估分桶后 actual rate 是否单调递增 | 验证预估排序方向正确 |
| **WMAPE** | `sum(abs(predicted - actual)) / sum(actual)` | 适用于连续值场景（pGMV） |

各预估模型的校准评估重点：

| 模型 | 主要校准指标 | 备注 |
|---|---|---|
| **pCTR** | 整体/分桶 PCOC、ECE、Brier Score | pCTR 是所有 eCPM 公式的基础乘子，校准偏差直接影响竞价公平性和收入 |
| **pCVR** (UniCR direct_pcr/shop_pcr) | 整体/分桶 PCOC、ECE、Brier Score | 需按延迟窗口（1h/6h/1d/3d/7d）分别评估 |
| **pGMV** | PCOC_final/direct/shop、WMAPE、分桶 PCOC | 已有 SIR/ItemCali 在线校准系统和 DataSuite 看板 |
| **Shop Ads pCTR/pCR** | 整体 PCOC、ECE | `§2.2.6.1` 中的事后校准和按国家校准表产出需定期评估 |

**Loss 突增诊断方法/Loss Spike Diagnosis Method：**

当 UniCR 训练过程中出现 loss 突增时，推荐以下诊断排查流程：

| 排查步骤 | 具体操作 | 说明 |
|---|---|---|
| 1. 确认 loss 组成 | 检查 `cr_loss`、`order2pay_loss`、`delay_feedback_loss`、`act_loss` 各项是否分别异常 | 定位是哪个 loss 组导致突增 |
| 2. 检查 label 回流 | 查看 LabelJoin 作业是否正常完成，`mkplpaidads_offline.ads_cr_${region}_daily_virtual` marker 是否就绪 | Label 回流失败会导致大量假负样本 |
| 3. 检查样本数据 | 对比异常日与正常日的样本量、正样本率、各 `label_weight` 分布 | 样本量骤变或正样本率异常均可导致 loss 突变 |
| 4. 检查特征覆盖 | 通过 `slot_quality_stats_new` 查看 null_rate / zero_rate 是否突变 | 上游特征数据中断会导致模型输入异常 |
| 5. 检查 checkpoint | 确认 seed/increment checkpoint 加载是否正确，是否存在 checkpoint 损坏 | 加载错误的 checkpoint 会导致初始 loss 异常 |
| 6. 检查数据链路 | 确认 Kafka 消费、HBase 拼接、FP 转换各环节是否正常 | 任一环节中断都可能影响样本质量 |

> 注：当前 KB 中未记录自动化的 loss 突增告警和自动诊断工具，排查主要依赖人工检查各环节日志和监控。

**pGMV 预估与实际 GMV 差异评估/pGMV vs Actual GMV Gap Assessment：**

pGMV 预估与实际 GMV 之间的差异来源可以分为以下层次：

| 差异来源 | 说明 | 评估方式 |
|---|---|---|
| **模型排序误差** | 模型对不同 item 的相对价值排序不准 | AUC / GAUC：排序指标越高，高价值 item 越能被排在前面 |
| **模型绝对值偏差** | `E[pGMV] != E[GMV]`，系统性高估或低估 | PCOC：偏离 1.0 的程度表示系统性偏差 |
| **校准残差** | SIR/ItemCali 修正后仍存在的偏差 | 对比 `raw_pred_pgmv` 和 `cali_pred_pgmv` 的 PCOC 改善幅度 |
| **pGMV 公式分解误差** | `price * sold_cnt_smoothed * CR_7d` 三个因子各自的预测误差 | 分别评估 CR PCOC、price 覆盖率、sold_cnt 平滑合理性 |
| **归因口径差异** | 点击归因 vs 到达归因 GMV 的天然错位 | 仅在大促期间显著，由 `prom_ratio` 修正 |

当前 KB 中**未记录具体的 pGMV vs actual GMV 差异评估数据**（如按 region/entrance 的 PCOC 时序趋势）。评估数据请参考 DataSuite PCOC 看板 `f1379dc0-6a0d-42d0-ba27-b3c3586f3b84`。

**pGMV 与 Uplift 的关系/pGMV and Uplift Interaction：**

Uplift 模型（增量效果模型）曾与 UniCR 主模型集成，但已从 UniCR 中独立出去（见 §2.2.5.9 已知约束中关于 `uplift_ratio_1~6` 残留的说明）。当前 pGMV 与 Uplift 的关系：

| 维度 | 说明 |
|---|---|
| **历史集成** | UniCR 曾包含 `uplift_ratio` 相关 head，通过 `uplift_weight` / `uplift_zero_weight` 训练 |
| **当前状态** | Uplift 已独立，UniCR Seed 中仅保留 `pcr_0` 和 `uplift_ratio_1~6` 作为历史残留 |
| **交互方式** | pGMV 输出（`price * sold_cnt * CR_7d`）度量的是广告带来的总价值；Uplift 度量的是广告带来的增量价值（广告 vs 无广告的差值）。两者在出价公式中的使用方式不同 |
| **潜在冲突** | pGMV 高不等于 Uplift 高——对于用户本来就会购买的商品，pGMV 可能很高但 Uplift 接近 0 |

> 当前 KB 中**未记录 pGMV 和 Uplift 在竞价侧的具体交互公式和权重配比**，该部分需结合 `§2.3 竞价产品和算法` 理解。

**预估目标与业务目标的 Gap/Gap Between Prediction Target and Business Objective：**

UniCR 的预估目标（`pGMV = price * sold_cnt * CR_7d`）与业务最终目标之间存在结构性 Gap：

| 维度 | 预估目标 | 业务目标 | Gap |
|---|---|---|---|
| 时间口径 | 7d 归因窗口 | 实际用户生命周期价值 | 7d 窗口截断了长期价值 |
| 价值口径 | GMV（成交金额） | ROI（广告主回报率） | GMV 高不等于 ROI 高，需结合广告成本 |
| 归因口径 | Direct + Shop 点击归因 | 全渠道真实贡献 | 忽略了 View-through、跨设备等间接影响 |
| 用户价值 | 单次点击价值 | 用户终身价值（LTV） | 未建模复购和长期关系 |

这些 Gap 是模型设计中的有意简化，通过限定预估范围来保证可建模性和可评估性。

| 现象 | 优先排查 |
|---|---|
| PCOC 突然偏高或偏低 | Label 回流、归因窗口、真实 GMV 口径、SIR 分桶统计 |
| 某 region 异常 | region-specific model / cali 权重、5 桶 / 10 桶策略、大促 offset、FSE region slot |
| Search 与非 Search 差异大 | OrgPredict 仅 Search 有效、domain mapping、入口特征覆盖 |
| pGMV 分桶不单调 | 模型排序能力、SIR 合桶、样本量不足、特征漂移 |
| cali 修正幅度异常 | SIR 1h/24h 融合、ItemCali order gate、`scale_3d`、大促 `prom_ratio`、限幅阈值 |
| 线上延时上涨 | EGO Predict、FeatureProcess、Rank latency 和特征请求链路 |

**Sparse Embedding / Dense Weight 过拟合与欠拟合判断/Over- and Under-fitting Detection：**

- **过拟合**：mask 后 val AUC 上升，或 train-val AUC gap > 0.01，或低频 ID embedding norm 异常偏大
- **欠拟合**：mask 后 AUC diff ≈ 0，或 slot `zero_rate > 60%`，或该层梯度 norm 持续趋近 0
- Increment 阶段 backbone 梯度为 0 属 `stop_gradient` 设计行为，非欠拟合

**CVR 建模中点击信息的引入路径/How Click Information Enters CVR Modeling：**

UniCR 的 pCVR（`direct_pcr_7d` / `shop_pcr_7d`）是 post-click 转化率预估，即在点击已发生的前提下预估转化概率。点击信号在模型中通过以下路径传递：

| 路径 | 具体机制 | 说明 |
|---|---|---|
| **训练样本定义** | 仅对有 click 的样本训练 CVR | 样本过滤规则（§2.2.5.2）丢弃无 click 的 FeatureDump，CVR 模型只在点击后样本空间上训练 |
| **OrgPredict 特征** | slot 1003 `I_pctr_online` 和 slot 1004 `I_pcr_online` | 上游 pCTR/pCR 的预估分作为 UniCR 的输入特征，间接传递了"该 item 被点击的概率"信息 |
| **用户行为序列** | click 序列（500 条） | 用户的点击历史通过 `SimpleAttentionV3` 提取 target-aware 兴趣表达，反映用户的点击偏好模式 |
| **点击统计特征** | `I_ctr_click3d_bucket`(1058)、`I_s_ctr_click7d_bucket`(1132) 等 | 商品/店铺维度的点击统计分桶，反映 item 的点击热度 |
| **短期行为特征** | `clk_items_within_1h_mod`(2186)、`st_ub_click_active_level_d1`(32005) | 用户短期点击活跃度，辅助判断当前购买意愿 |

需要注意的是，UniCR 的 CVR head 不显式接收"当前这次点击是否发生"的二元信号——这是通过训练样本空间隐式保证的（所有训练样本都是点击后样本）。

**预估最小单元对比/Prediction Granularity Comparison：**

各预估模型的最小预估单元对比：

| 模型 | 预估粒度 | 输入粒度 | 说明 |
|---|---|---|---|
| **pCTR** | `(user, item, context)` | 请求级别 | 预估特定用户在特定上下文中点击特定广告的概率 |
| **pCVR (UniCR)** | `(user, item, context)` | 点击级别 | 在点击已发生前提下，预估转化概率 |
| **pGMV (UniCR)** | `(user, item, context)` | 点击级别 | `price * sold_cnt * CR_7d`，item 维度的价值预估 |
| **SIR cali** | `(region, entrance, placement, time_period)` | 聚合级别 | ALL 粒度校准，不区分具体 item |
| **ItemCali** | `(item_id, country)` | item 级别 | item 粒度的 GMV/pGMV 比值校准 |

**按实验号分桶校准/Experiment-Bucket Calibration：**

UniCR 校准系统**支持**按实验号（AB experiment bucket）分桶校准，其实现机制为：

校准特征在生产时，按**原始模型名字维度**分别独立生产各自的校准特征；上线时通过**实验参数**配置该实验组使用哪个模型产生的校准特征，从而实现不同实验桶之间的独立校准。

现有 SIR 校准的默认分桶维度为 `region x entrance x placement x time_period`（见 FSE 表 `ads.cali_segment_data_v3` 的 PrimaryKey）。实验号分桶校准在此基础上通过特征生产侧的**模型名区分**实现，无需改动 SIR FSE 表的 PrimaryKey 结构。

#### 2.2.6.1 Shop Ads 模型/Shop Ads Model

Shop Ads 推广的是整个店铺而非单个商品：一张广告卡片同时承载一个店铺及其最多 10 件商品，因此排序需要同时对**店铺维度**和**商品维度**建模。排序由两个独立推理模型驱动——**pCTR 模型**与 **pCR 模型**，二者输出由打分层合并。

**打分公式**

```
最终分数 = eCPM + α · eGMV = pCTR · bidPrice + α · pCTR · pCR · AOV
```

`pCTR` = 预估点击率；`pCR` = 预估点击后转化率；`AOV` = 店铺平均客单价（静态统计值）；`α` = 平衡收入与 GMV 贡献的权重。最终分数超过流量控制设定的 eCPM 阈值时该广告才展示。

**pCTR 模型**

双塔多任务模型，联合预测 `shop_ctr`（点击店铺卡片）与 `item{i}_ctr`（i = 1..10，点击卡片内各商品）；共享表征互相提升两个任务。

- **特征分组**：店铺 / 店铺多值（序列 5） / 店铺热销商品（≤20，注意力池化） / 商品（Top-N，ITEM_LEN=10） / 用户 / Query / 用户×店铺交叉统计 / 用户行为（UB）。
- **特征交互**：**SeNet**（特征域重加权）+ **FINT**（域间两两交互），作用于上下文 / 用户 / 商品三组。
- **UB 建模**：点击/加购/下单各跨 **6 个时间窗口（1h/3h/1d/3d/14d/60d）**，用 **DIN 多头**注意力，由融合后的 query embedding 引导；短期负反馈序列用对比 DIN（取反 Embedding）。
- **MMOE**：**2 个专家（商品 + 店铺）经软门控被两个塔共享**；店铺塔额外消费商品专家的池化输出，使商品级点击模式对店铺打分去偏（曝光/位置去偏）。
- **校准与输出**：事后校准 → `shop_ctr`、`item{i}_ctr`。

**pCR 模型**

针对 点击→（加购）→下单 漏斗的 **MMOE-STAR** 模型，显式建模两条路径——直接（`pCR2`：点击→下单）与间接（`pCR1`：点击→加购→下单），按用户加权融合：

```
pCVR = 直接权重 · (1 − pATC) · pCR2 + 间接权重 · pATC · pCR1
```

权重由一个轻量用户条件塔（user_id + 国家）输出。

- **特征分组**：店铺 / 用户 / keyword+交叉 / 国家（域指示器） / 商品（≤10） / UB 点击(500) / 加购(128，时间衰减) / 下单(128) / 短期负反馈(1d/3d/7d)。
- **特征交互**：SeNet 作用于全部组；FINT 仅用于店铺+用户（在大体量的上下文/商品组上跳过，避免 O(L²) 开销）。
- **UB 建模**：每种行为用单条合并长序列，DIN 多头；短期负反馈用对比 DIN。
- **域自适应**：**EpNet** 基于国家 Embedding 的门控——单模型服务 8 个市场（ID/MY/SG/TH/PH/VN/TW/BR），无需按国家维护独立权重。
- **联合任务**：pCTR / pATC / pCTATC / pCR1 / pCR2 / pCVR / pCTCVR；`final_loss = pCTR + pATC + pCTATC + pCTCVR`（pCR1/pCR2/pCVR 用 GAUC 监控，梯度经 pCTCVR 回传）。
- **校准与输出**：按国家校准表（从 HDFS 加载）→ `shop_broad_cr`（校准后 pCVR）、`pCVR`（原始）。

**训练数据**

- **FeatureDump**（原始按小时，FP 前）：Hive `mkplpaidads_offline.ssp_raw_sample_shop_ads_hourly_reg_live`。
- **训练数据**（FP 后，EGO parquet）：`hdfs://R2/projects/mkplpaidads_offline/hdfs/prod/alg/shop_ads/train_data_parquet/{region}/{dt}/{hh}`；就绪标记 `mkplpaidads_offline.shop_ads_{region}_gentraindata`。
- **标签延迟**：CTR 1–2 小时（近实时）；CR 7 天（归因窗口）。BR 流量单独产出，7 天窗口结束后同步至 SG 集群。

**线上服务**

EGO + AFP 推理，经 URank 对外服务，权重每日更新；**模型路由按国家区分**，由 AB feature（`shopAdsPCtrURankerModel` 3288 / `shopAdsPCrURankerModel` 3283）配置。pCTR 各国统一 `gpu_shopads_pCTR_base`（20505）；pCR 按国家区分（`gpu_shopads_pCR_base` 21743 / `gpu_shopads_pCR_new_labels` 24088 / `gpu_shopads_pCR_all_features_satt` 23681）—— 逐国路由见 team KB §10 serving 矩阵（配置经常变化）。流程：AFP 实时抽特征 → EGO 加载 Checkpoint 推理 → URank 统筹 → 返回 `pCTR` + `pCR` 给排序服务。
