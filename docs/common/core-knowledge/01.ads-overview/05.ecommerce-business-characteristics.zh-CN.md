## 1.5 电商广告的业务特性与产品创新 / Business Characteristics and Product Innovation in E-commerce Advertising

### 1.5.1 电商广告业务特性 / E-Commerce Advertising Business Characteristics


电商广告与通用广告（品牌展示广告、信息流广告等）虽然共享"竞价、投放、归因"的基本框架，但由于电商平台自身的业务特性，两者在多个核心维度上存在本质差异。理解这些差异，有助于理解后续章节中 Shopee Paid Ads 的产品设计和技术方案为什么是这样的。


| 维度               | 电商广告                                                                   | 通用广告（品牌/信息流）                    |
| ---------------- | ---------------------------------------------------------------------- | ------------------------------- |
| **离交易的距离**       | 直接嵌入购物场景（搜索结果、商品推荐页），"看到广告→下单"链路极短                                     | 更多是"曝光→认知→后续转化"，归因路径长且模糊        |
| **效果可衡量性**       | 平台天然拥有交易闭环数据，广告效果可精确归因到 GMV/ROAS                                       | 效果（品牌认知提升、线下到店等）难以直接量化          |
| **供给规模与动态性**     | 需处理百万级 SKU，每个 SKU 的库存、价格、促销状态实时变化                                      | "创意"相对稳定，不会像 SKU 一样频繁上下架        |
| **流量季节性**        | 流量高度集中在大促期间（双 11、年中促销），流量和预算可激增数倍                                      | 季节波动相对平缓                        |
| **自然流量与广告流量的博弈** | 平台同时拥有自然推荐流量和广告流量，两者共享同一批用户和商品池（参见 [§1.4.6](04.strategy-mechanisms.zh-CN.md#146-广告混排) 混排），存在复杂的流量分配博弈 | 独立 DSP 等平台不存在自然流量，无此博弈          |
| **广告主生态**        | 广告主以海量中小卖家（SME）为主，缺乏专业投放团队和经验，对操作复杂度敏感                                 | 广告主以品牌/代理商为主，有专业投放团队，能接受复杂的投放配置 |


这些差异直接影响了电商广告系统的技术选型和产品形态：

- **离交易近 + 效果可衡量** → oCPX（[§1.4.3.2](04.strategy-mechanisms.zh-CN.md#1432-智能出价 smart-bidding-ocpx)）等按转化效果出价的模式在电商广告中率先大规模落地，因为平台能精确衡量每一笔转化
- **SKU 海量且动态变化** → 召回和排序系统需要处理实时变化的商品池（库存不足、价格变动、促销上下架），这在通用广告中较少遇到
- **大促驱动** → 出价调控（[§1.4.3.3](04.strategy-mechanisms.zh-CN.md#1433-λ-调价系数)）和预算 pacing 需要应对流量数倍波动的极端场景
- **自然流量与广告流量博弈** → 催生了全站推广（[§1.5.2](#152-全站推广)）这类将付费与自然流量统一优化的产品形态
- **广告主长尾 + 缺乏投放经验** → 产品设计必须走向自动化和托管化：从手动 CPC 到 oCPX（[§1.4.3.2](04.strategy-mechanisms.zh-CN.md#1432-智能出价 smart-bidding-ocpx)）再到全站推广（[§1.5.2](#152-全站推广)），每一步都在降低广告主的操作门槛
- **效果可衡量 + 交易闭环** → 平台可精确计算补贴的 ROI，催生了 QCPX（[§1.5.3](#153-qcpx 智能优惠券出价)）等平台主动出资补贴转化的产品形态——这在效果难以量化的品牌广告中几乎不可能实现

### 1.5.2 全站推广 / Full-Site Promotion

#### 1.5.2.1 什么是全站推广 / What Is Full-Site Promotion


全站推广（Full-site Promotion）是广告平台将**付费流量与自然流量统一优化**的广告产品形态。广告主只需设定预算（+ 可选 ROI 目标），平台在全站流量池（搜索 + 推荐 + 各频道）中统一分配付费与自然曝光，最大化广告主的整体 GMV。

全站推广与传统广告的核心区别如下：


| 维度    | 传统广告（独立链路）                                          | 全站推广（融合链路）                                   |
| ----- | --------------------------------------------------- | -------------------------------------------- |
| 流量范围  | 广告主购买广告坑位，自然流量独立分配                                  | 平台在付费 + 自然流量池中统一分配曝光                         |
| 广告主设定 | 出价（CPC/CPA/ROAS）+ 预算 + 定向                           | 预算 + 可选 ROI 目标（NoBid 或 tROAS）                |
| 系统架构  | 广告独立召回排序，最终阶段插入自然结果（[§1.4.6.2](04.strategy-mechanisms.zh-CN.md#1462-独立链路-vs-融合链路)） | 广告与自然内容统一召回、统一排序（[§1.3.1](03.system-pipeline-modules.zh-CN.md#131-系统链路全景) 融合链路） |
| 优化目标  | 广告流量内的转化/GMV                                        | 全站（付费 + 自然）整体 GMV                            |
| 考核口径  | 广告带来的 GMV（Direct 归因）                                | 全站整体 GMV 增量（Broad 归因，付费 + 自然）                |


全站推广支持两种出价模式（[§1.4.4](04.strategy-mechanisms.zh-CN.md#144-nobid 预算出价) 已提及）：

- **GMVMAX-NoBid**：仅设日预算，平台全权决定出价
- **GMVMAX-TargetROAS**：设日预算 + 目标 ROAS，平台在 ROI 约束下优化

底层仍然使用 [§1.4.3](04.strategy-mechanisms.zh-CN.md#143-基础出价与智能出价)-[§1.4.5](04.strategy-mechanisms.zh-CN.md#145-双出价) 的出价机制（λ 调价、eCPM 竞价），区别在于优化目标从"广告流量内效果最大化"扩展到"全站流量效果最大化"。

> 融合链路架构图见 [§1.3.1](03.system-pipeline-modules.zh-CN.md#131-系统链路全景)，独立链路 vs 融合链路对比见 [§1.4.6.2](04.strategy-mechanisms.zh-CN.md#1462-独立链路-vs-融合链路)。

#### 1.5.2.2 为什么全站推广能驱动广告收入增长 / Why Full-Site Promotion Drives Advertising Revenue Growth


全站推广之所以成为各大电商平台的增长引擎，是因为它在广告系统的四大核心模块——**流量定向、效果预估、售卖机制、出价策略**——上都实现了范式升级，每个模块的变化都直接贡献于收入增长。

**流量定向：从规则走向模型，触达范围扩大**


| 子模块   | 传统模式               | 全站推广模式            |
| ----- | ------------------ | ----------------- |
| 召回定向  | 规则定向（广告主手动选关键词/人群） | 模型定向（平台自动匹配用户与商品） |
| 召回/粗排 | 广告与自然内容各自独立的召回链路   | 广告与自然（原生）供给链路统一   |


收入增长驱动：

- **召回定向**：模型定向扩大广告触达范围，减少因定向过窄导致的预算花不出去
- **召回/粗排**：统一供给池使广告能参与更多流量的竞争

**效果预估：模型统一，预估精度提升**


| 子模块  | 传统模式                 | 全站推广模式       |
| ---- | -------------------- | ------------ |
| 排序模型 | 广告和自然各自独立的样本、特征、优化目标 | 样本/特征/目标统一复用 |


收入增长驱动：

- **排序模型**：训练数据量级更大、信号更丰富，预估更准确 → eCPM 估值更精确 → 广告主愿意为更准确的效果付费

**售卖机制：从固定坑位到统一混排，流量价值被充分释放**

传统模式下广告在固定坑位展示，全站推广将其升级为**统一排序混排**（参见 [§1.4.6.2](04.strategy-mechanisms.zh-CN.md#1462-独立链路-vs-融合链路) 混排公式 `RankScore = α × eCPM + β × OrgScore`），带来两个直接的收入增长效应：

- **广告对流量的撬动范围和杠杆更大**：广告不再局限于固定坑位，而是可以在全站任意位置与自然内容竞争展示。付费流量池从"广告坑位"扩展到"全站流量"，单个广告主的可触达流量大幅增加。
- **计费机制更合理，避免流量贱卖**：全站推广采用全域计费，并以自然 item 的 OrgScore 作为底价（对比 [§1.4.7.3](04.strategy-mechanisms.zh-CN.md#1473-gsp-扣费公式推导) 的 GSP 扣费公式）：

```
actual_deduction = (next_RankScore - β × OrgScore) / (α × pCTR) + δ
```

自然内容参与竞价（以 OrgScore 托底），流量竞争更充分，计费价格更接近广告主的真实价值，避免了传统模式下低竞争坑位被低价售出的问题。

**出价策略：广告主价值与平台价值目标对齐**


| 子模块  | 传统模式                              | 全站推广模式                              |
| ---- | --------------------------------- | ----------------------------------- |
| 出价表达 | Manual CPC/CPA（手动出价）              | oCPX 自动出价                           |
| 归因口径 | Direct 归因（仅统计广告直接带来的转化）           | Broad 归因（统计付费 + 自然流量的转化）            |
| 出价调控 | PID 控制器（[§1.4.3.3](04.strategy-mechanisms.zh-CN.md#1433-λ-调价系数)） | MPC（Model Predictive Control）模型预测控制 |
| 预算分配 | 限定场景投放（仅搜索/仅推荐）                   | 全域通投 + 智能调控                         |


收入增长驱动：

- **出价表达**： eCPM 与 OrgScore 的"夹角"更小（详见下文），广告主价值和平台价值目标对齐
- **归因口径**： Broad 归因更贴合广告主的经营目标，广告主愿意投入更多预算
- **出价调控**： MPC 调控更精准，预算利用率更高，减少超成本导致的停投
- **预算分配**：预算不再受限于单一场景，平台可在全域中寻找最优流量，提升整体消耗

**理解"夹角"更小**

回顾 [§1.4.6.2](04.strategy-mechanisms.zh-CN.md#1462-独立链路-vs-融合链路) 的混排公式 `RankScore = α × eCPM + β × OrgScore`，其中 eCPM 代表商业价值， OrgScore 代表平台原生价值（用户体验、商品质量、生态健康）。可以把 eCPM 和 OrgScore 想象成**两个方向**：方向一致（"夹角"小）时，排序结果既能提升商业收入又能保障用户体验；方向冲突（"夹角"大）时，平台被迫在收入和体验之间艰难取舍。

传统 CPC 手动出价下：

```
eCPM = CPC × pCTR
```

CPC 是广告主手动设定的出价，反映的是广告主的"竞价意愿"而非"商品对用户的真实价值"。一个质量一般但出价激进的广告主可以用高 CPC 买到好位置，此时 eCPM 高但 OrgScore 低——两个方向冲突，"夹角"大。平台被迫在"高收入但伤体验"和"好体验但少收入"之间取舍，广告加载率（Ad Load）受限，流量变现存在天花板。

全站推广的 oCPX 出价下：

```
eCPM = pGMV × λ / Target_ROAS
```

其中 `pGMV = pCTR × pCVR × pAOV`（[§1.4.3.4](04.strategy-mechanisms.zh-CN.md#1434-两种典型的成本出价表达模式)）。eCPM 的核心驱动因子变成了 **pGMV（预估 GMV）**——模型预估这个商品在这个用户面前能产生多少成交额。而 OrgScore 衡量的也是商品对用户的价值（好评率、相关性、服务质量等）。pGMV 高的商品，通常也是用户喜欢、愿意购买的商品， OrgScore 往往也高——两个方向趋于一致，"夹角"变小。

"夹角"变小带来的直接收入增长效应：

- **广告加载率可以安全提升**： eCPM 和 OrgScore 方向一致时，展示更多广告不会显著损害用户体验，平台可以提高广告加载率（更多流量被商业化）
- **排序效率更高**：不再需要通过 α/β 权重在收入与体验之间艰难取舍，两个目标自然兼容，每次曝光的 RPM 提升
- **正向循环形成**：广告质量高 → 用户体验好 → 用户活跃度不下降 → 流量池不萎缩 → 可变现流量持续增长

**四个模块的协同效应**

四个模块的升级并非孤立生效，而是形成正向循环：

- **效果预估更准** → 广告主获得更好的 ROI → 愿意提高预算
- **售卖机制更高效** → 每单位流量产生更高收入 → 平台 RPM（Revenue Per Mille）提升
- **出价策略更智能** → 预算利用率更高、广告主投放更高效 → 广告主整体消耗增加

这解释了为什么拼多多、阿里妈妈、巨量引擎、Shopee 等平台在推出全站推广后，广告收入均出现显著增长——全站推广不是简单的"多卖了几个坑位"，而是对广告系统从效果预估到售卖到出价的**全链路升级**。

从广告主的角度看，全站推广的核心价值是：

- **操作极简**：只需设预算（+ 可选 ROI 目标），无需设定出价、定向、关键词
- **付费撬动自然流量**：广告投入不仅带来付费曝光，还通过提升商品热度/权重间接增加自然流量
- **整体 ROI 可能优于纯付费**：考核全站 GMV 而非仅广告 GMV， Broad 归因口径更宽
- **适合缺乏投放经验的商家**：中小商家、新店铺、新品推广等场景尤其适用

### 1.5.3 QCPX：智能优惠券出价 / QCPX: Smart Voucher Bidding

#### 1.5.3.1 什么是 QCPX / What Is QCPX


QCPX = 券(Q) + oCPX。"Q"取自中文"券"的首字母，表示在 oCPX 智能出价的基础上叠加**智能优惠券**。

QCPX 是广告平台在 oCPX 智能出价的基础上，由**平台出资**向用户发放智能优惠券，通过降低用户支付门槛来提升转化率的广告产品形态。与 oCPX 只调整"出价"不同， QCPX 在"出价"之外增加了"补贴"这一维度。

QCPX 与 oCPX 的核心区别如下：


| 维度      | oCPX（[§1.4.3.2](04.strategy-mechanisms.zh-CN.md#1432-智能出价 smart-bidding-ocpx)） | QCPX                                  |
| ------- | ----------------------------------------------- | ------------------------------------- |
| 优化手段    | 调整出价（bid）                                       | 调整出价 + 发放优惠券（bid + voucher）           |
| 费用承担    | 广告主支付全部广告费用                                     | 广告主支付广告费 + 平台出资承担优惠券费用                |
| 转化提升机制  | 通过 pCTR/pCVR 模型找到高转化用户                          | 在模型选人基础上，通过券降低支付门槛进一步提升 CVR           |
| eCPM 影响 | `eCPM = Target_CPA × pCVR × pCTR × λ`           | pCVR 因发券而提升 → eCPM 提升 → 广告竞争力增强       |
| 核心模型    | pCTR、pCVR、λ 调价                                  | 在 oCPX 模型基础上增加 uplift 模型（预估发券带来的增量转化） |


> oCPX 的定义和 eCPM 公式见 [§1.4.3.2](04.strategy-mechanisms.zh-CN.md#1432-智能出价 smart-bidding-ocpx)，λ 调价系数见 [§1.4.3.3](04.strategy-mechanisms.zh-CN.md#1433-λ-调价系数)， QCPX 的实现细节见 [§2.5](../02.ads-strategy/05.ads-smart-voucher.zh-CN.md#25-广告智能优惠券) 广告智能优惠券。

#### 1.5.3.2 为什么平台愿意自己出钱发券 / Why the Platform Is Willing to Fund Vouchers Itself


核心逻辑：对平台而言，成本是 `voucher_cost`（券成本），发券收益是 `rev_uplift`（发券带来的广告收入增量），净收益 = `rev_uplift - voucher_cost`。只要净收益 > 0，发券就是**正 ROI 的平台投资**。

**平台视角（为什么赚钱）：**

- **发券提升 CVR → eCPM 提升 → 广告消耗增加**：发券降低用户支付门槛 → pCVR 提升 → eCPM 公式中的 pCVR 分量增大 → 广告在混排中更有竞争力 → 赢得更多曝光 → 广告主预算消耗更快 → 平台广告收入增加（即 `rev_uplift`）
- **发券扩大广告主可投放范围**：一些 ROI 偏低的广告主在纯 oCPX 下效果不达标而停投；发券补贴后效果达标，重新激活投放 → 平台广告主规模和消耗同时增长
- **平台可精准控制券的 ROI**：通过 uplift 模型预估每张券的增量转化贡献，只在 `rev_uplift > voucher_cost`（净收益为正）时才发券，确保平台发券行为整体正 ROI

**广告主视角（为什么受益）：**

- **无额外成本**：优惠券由平台出资，广告主不需要额外付费
- **转化率提升**：用户看到优惠券后下单意愿增强，广告主的广告效果（GMV/ROAS）提升
- **降低冷启动门槛**：新品/新店广告主在积累转化数据阶段，券的补贴帮助快速起量

#### 1.5.3.3 QCPX 的技术框架 / QCPX Technical Framework


QCPX 包含三个核心模块（概要介绍，实现细节见 [§2.5](../02.ads-strategy/05.ads-smart-voucher.zh-CN.md#25-广告智能优惠券)）：

**一、Uplift 模型：决定"给谁发、发多少"**

- 核心问题：预估对某个用户发券后的**增量转化率**（而非绝对转化率）
- 与 oCPX 的 pCVR 模型的区别： pCVR 预估"用户是否会转化"， uplift 模型预估"发券是否能让原本不会转化的用户转化"
- 只对 uplift 值足够高的用户发券，避免给"不发券也会买"的用户浪费补贴

**二、发券调控：决定"花多少预算发券"**

- 长窗口调控：基于历史"预算→ROI"关系预估最优券预算分配
- 短窗口调控：实时监控券消耗 pacing，平衡发券速度与效果

**三、排序与计费分离：厘清平台价值与广告主价值**

- 排序阶段：按照对平台的综合收益排序，排序 eCPM = `eCPM_0 + rev_uplift - voucher_cost`，其中 `eCPM_0` 为原始 eCPM， `rev_uplift` 为发券带来的收入增量， `voucher_cost` 为券成本
- 计费阶段：和广告主的计费始终按照 ADVV（Ads Value to Advertiser）结算，即计费 eCPM = `eCPM_0 + rev_uplift`，不扣除券成本——券是平台的投资，不应转嫁给广告主
