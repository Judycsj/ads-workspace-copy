## 1.3 广告系统链路模块 / Advertising System Pipeline Modules

### 1.3.1 系统链路全景 / System Pipeline Overview

#### 1.3.1.1 广告链路架构图 / Ad Pipeline Architecture Diagram

<!-- last_translated: 2026-06-08T04:41:23.144619+00:00 -->

The general complete processing chain of ad requests is as follows:

```
                                            General complete processing chain of ad requests

  ┌─ org ──────────────────────────────────────────────────────────────────────────────────────────────────────┐
  │                                                                                                            │
  │  req ──────────▶ recall ──────────────▶ prerank ──▶ ranking ──────────▶ mix rank ──────▶ dispatch to app   │
  │                                                                         ^                                  │
  └─────────────────────────────────────────────────────────────────────────|──────────────────────────────────┘
                                                                            |
  ┌─ ads ───────────────────────────────────────────────────────────────────|──────────────────────────────────┐
  │                                                                         |                                  │

  └────────────────────────────────────────────────────────────────────────────────────────────────────────────┘
```

In the above diagram, the ad and native chains are independent, only merging at the final mix rank stage.

For e-commerce ad GMV MAX, the ad and native chains are deeply integrated; ads provide the required ad information to the native traffic chain via API0-API3.

#### 1.3.1.2 广告链路模块简介 / Ad Pipeline Module Overview

<!-- last_translated: 2026-06-08T04:41:12.705457+00:00 -->

| Phase             | Responsibility                                      | Input                                                     | Core Processing                                                                                                                                                | Output                                                       |
| ----------------- | --------------------------------------------------- | --------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------ |
| **Recall**        | Retrieve candidate sets that users may be interested in from the full ad inventory | Full ad inventory (millions) + user/query/context features | Multi-channel parallel: dual-tower KNN, collaborative filtering I2I, inverted text matching, U2U2I, etc.; filtered by AdsInfoFilter + Zigzag merge truncation | ~ thousand-level candidates, with recall source and business tags |
| **Prerank**       | Quickly filter using a lightweight model to reduce the ranking computation scope | Recall results (thousands) + basic features               | Lightweight DNN / MMoE multi-task scoring (complexity between dual-tower and ranking); supports quota reservation (reserveQuota) forced insertion for boosting candidates | ~ hundred-level candidates, with prerank scores              |
| **Rank**          | Accurately estimate user behavior probabilities, providing value signals for bidding | Prerank results (hundreds) + full features (behavior sequences, context, price, etc.) | UniCR (MMOE-STAR multi-task multi-domain) ranking model; pGMV = item_price × sold_cnt × CR, calibrated via SIR + ItemCali                                      | pCTR, pCVR, pGMV multi-task scores, ~ dozens of candidates   |
| **Bidding**       | Compute ad value eCPM based on advertiser bidding strategy | Ranking scores (pCTR/pCVR/pGMV) + advertiser bid settings + lambda/ratio coefficients | Compute eCPM by bid type (manual CPC / oCPX / tROAS); lambda PID for cost control, ratio calibration for model bias; Pacing for budget consumption rhythm      | eCPM / bidPrice, rank_score = α×eCPM + porg                 |
| **Mix Rank**      | Fuse ads and organic results to generate the final display list | Ad candidates (with eCPM) + organic results (with OrgScore) + experience constraint configuration | RankScore = α×eCPM + β×OrgScore for auction ranking; enforce experience hard constraints such as ad density cap, minimum spacing, same-store frequency limit  | Final display sequence (ad + organic blending), each ad with billing parameters |
| **Billing**       | Charge based on auction mechanism, ensuring fair and credible billing | Billing trigger event (click/impression) + current and next RankScore + anti-fraud signals | GSP billing: deduction = second price derived from next_RankScore; upper/lower bound clipping (min_cap, max_cap); real-time anti-fraud filtering + offline adjustment refund | Actual deducted amount, billing logs (for attribution and feedback systems) |

> The detailed strategies and model implementations for each stage are respectively covered in: Recall [§2.1](../02.ads-strategy/01.recall-and-supply-strategy.md#21-召回通路和供给策略), Ranking Model [§2.2](../02.ads-strategy/02.cxr-pgmv-models-and-calibration.md#22-cxr--pgmv-模型和校准), Bidding Algorithm [§2.3](../02.ads-strategy/03.bidding-products-and-algorithms.md#23-出价产品和算法), Traffic Strategy and Billing [§2.4](../02.ads-strategy/04.traffic-strategy-and-billing.md#24-流量策略和计费).

### 1.3.2 核心策略模块 / Core Strategy Modules

#### 1.3.2.1 流量定向 / Traffic Targeting

<!-- last_translated: 2026-06-08T04:40:47.927890+00:00 -->

- From the perspective of traffic: recall a set of ads that users are interested in
- From the perspective of ads: target user traffic potentially interested in the ad
- Targeting methods include: keyword targeting, audience targeting, contextual targeting, retargeting, etc.
- Core challenge: striking a balance between targeting precision and traffic scale

> For detailed targeting strategies and model implementation, see [§2.1](../02.ads-strategy/01.recall-and-supply-strategy.md#21-召回通路和供给策略) (ad recall strategy).

#### 1.3.2.2 价值预估 / Value Estimation

<!-- last_translated: 2026-06-08T04:40:42.881880+00:00 -->

Estimated traffic × ad value points, where value points include the probability scores of various user actions towards the ad (click/conversion/payment, etc.). Core models:


| Model | Meaning                             | Description                                         |
| ----- | ----------------------------------- | --------------------------------------------------- |
| pCTR  | Estimated Click-Through Rate        | Probability of user clicking the ad                 |
| pCVR  | Estimated Conversion Rate           | Probability of conversion after clicking            |
| pGMV  | Estimated Gross Merchandise Volume  | Expected transaction amount resulting from conversion |


> For detailed strategies and model implementation of value estimation, see [§2.2](../02.ads-strategy/02.cxr-pgmv-models-and-calibration.md#22-cxr--pgmv-模型和校准) (CxR & PGMV model and calibration)

#### 1.3.2.3 出价策略 / Bidding Strategy

<!-- last_translated: 2026-06-08T04:40:51.286982+00:00 -->

Based on the predicted value score and the advertiser's bid expression, calculate the ad value eCPM for each impression (traffic × ad).

- Basic bidding: The advertiser manually sets a bid; eCPM is converted from bid × predicted probability
- Smart bidding (oCPX): The advertiser sets a target cost, and the platform automatically calculates eCPM using pCTR/pCVR/λ
- Core objective: Maximize delivery performance (clicks/conversions/GMV) under the advertiser's budget constraint

> For bid formulas and strategies, see [§1.4.2](04.strategy-mechanisms.md#142-广告出价和售卖的核心概念)-[§1.4.5](04.strategy-mechanisms.md#145-双出价)

#### 1.3.2.4 售卖机制 / Selling Mechanism

<!-- last_translated: 2026-06-08T04:40:57.377930+00:00 -->

Based on ad value (eCPM) and platform native value (OrgScore), the bidding and ranking mechanism decides which ad the traffic is sold to, along with the corresponding charging rules:

- Bidding and ranking: `RankScore = α × eCPM + β × OrgScore`
- Mainstream mechanism: GSP (Generalized Second-Price auction) — charge based on the next bidder’s price to incentivize truthful bidding
- Charging formula (taking CPC as an example): `Actual CPC = (next_RankScore - β × OrgScore) / (α × pCTR) + 0.01`
- Core trade-off: balancing platform revenue, advertiser ROI, and user experience

> For detailed explanation of mixing mechanism and billing formula, see [§1.4.6](04.strategy-mechanisms.md#146-ad-mixing)-[§1.4.7](04.strategy-mechanisms.md#147-ad-billing).
