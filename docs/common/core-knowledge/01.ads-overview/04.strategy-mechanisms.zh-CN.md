## 1.4 广告系统策略机制 / Advertising System Strategy Mechanisms

### 1.4.1 规则与战术：机制 vs. 策略 / Rules and Tactics: Mechanisms vs. Strategies




核心比喻：**机制 = 游戏规则 | 策略 = 游戏战术**


| 特性   | 机制 (Mechanism)                                                                              | 策略 (Strategy)                                                                |
| ---- | ------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| 定义   | 系统的底层框架和基础规则，决定"能做什么"和"如何结算"。它是系统的"物理定律"。                                                   | 在机制框架内，为达成特定目标而设计的动态算法和优化逻辑。它是系统的"智能决策"。                                     |
| 目的   | 确保市场公平、透明、稳定地运行，奠定系统长期健康的基础，引导参与者行为。                                                        | 在规则约束下，最大化特定目标（如平台收入、广告主 ROI、用户体验）。                                          |
| 设计要点 | **一视同仁**，稳定性、公平性、可预测性、激励相容（如 GSP 鼓励真实出价）。                                                   | **个性化**，准确性（预估）、实时性（决策）、自适应（调优）、多目标平衡。                                       |
| 广告举例 | 计费公式： GSP（广义二价）、GFP（广义一价）；计费方式： CPM、CPC、oCPX；排序因子：排序公式包含哪些变量（如出价、pCTR、质量分）和参数权重；准入规则：广告审核标准 | 出价表达：广告主如何表达目标出价；智能出价： oCPX 的动态调价逻辑；预算控制：预算平滑（Pacing）的出价算法；预算分配：时序和流量场域的预算分配 |
| 变动影响 | 影响深远，修改频率低，如同修改宪法。                                                                          | 持续迭代， A/B 测试频繁，如同调整战术。                                                       |

### 1.4.2 广告出价和售卖的核心概念 / Core Concepts of Ad Bidding and Selling

#### 1.4.2.1 常见计费模型 / Common Billing Models





| 计费模型    | 全称              | 广告主付费时机 | 风险承担方                       |
| ------- | --------------- | ------- | --------------------------- |
| **CPM** | Cost Per Mille  | 每千次曝光   | 广告主承担效率风险                   |
| **CPC** | Cost Per Click  | 每次点击    | 平台承担点击效率风险（CTR 低平台少计费）      |
| **CPA** | Cost Per Action | 每次转化    | 平台承担点击及转化效率风险（CTCVR 低平台少计费） |


四个关键”点”中，**竞价点**几乎固定为 impression（按 eCPM 排序），广告系统设计基本不会改变竞价点；**考核点**是广告主客观存在的经营目标（如 ROAS、GMV），由广告主自身的商业模式决定，不随平台的系统设计而改变。因此，**计费点**和**出价点**才是广告系统机制策略设计的核心变量，下文不同广告产品（基础出价 vs 智能出价）的差异主要体现在这两者的选择上。

#### 1.4.2.2 为什么竞价点始终是 impression / Why the Ranking Point Is Always Impression




- **流量分配的最小决策单元**：每一次曝光机会是平台分配流量的最小粒度，平台需要在每次曝光时决定展示哪条广告，因此排序必须在 impression 级别进行
- **统一比较的公平基准**：不同出价模式（CPC、CPA、CPM）的广告需要在同一个坑位竞争，必须转换到统一维度才能公平比较。impression 是所有广告都必然经历的环节， eCPM（每千次曝光价值）是唯一能让不同出价模式的广告可比的统一度量
- **平台收入最大化的直接抓手**：平台的广告收入 = Σ 每次曝光的变现价值，按 eCPM 排序直接等价于最大化每次曝光机会的收入，是平台收入最优的排序策略
- **无需依赖后续不确定事件**：曝光是确定性事件，点击/转化是概率事件， impression 在广告下发时即刻确定，不依赖用户是否点击或转化等后续行为，排序决策可以实时完成，不存在延迟和不确定性
- 总结：曝光是广告系统中唯一同时满足以下条件的事件：是平台可控的原子资源、是确定性事件、发生在决策时刻、可作为统一比较基准。这就是为什么竞价点几乎不会改变——它不是一个设计选择，而是由广告交易的本质决定的。

#### 1.4.2.3 出价点与考核点的差距 / The Gap Between Bid Point and Evaluation Point




出价点是广告主向平台传达的优化目标，考核点是广告主衡量自身经营效果的最终标准。**理想情况下两者应该统一**——广告主按什么考核，就按什么出价，平台直接优化广告主最终关心的目标。

但在实际中，两者可能仍存在差距，主要受限于以下技术和业务约束：

- **可预估性**：出价点必须是平台模型能够实时预估的目标。部分考核指标（如 LTV、长期复购 GMV）依赖长周期数据，当前模型精度不足以支撑实时出价决策
- **可归因性**：出价点对应的转化事件需要明确可归因到单次广告交互。部分考核指标涉及跨周期、跨渠道的综合效果（如品牌心智提升），归因边界模糊
- **数据稀疏性**：越深层的转化事件（如成交、复购）样本越稀疏，模型训练难度越大，预估方差越高

> 随着模型能力提升和数据基建完善，出价点与考核点的差距会持续缩小。当平台能准确预估广告主的最终考核目标时，两者就能真正统一。

为了加强平台优化目标（出价点）和广告主最终关心目标（考核点）的一致性，广告产品的演进主要有三个并行方向：

- **出价点不断向考核点靠拢**： CPC（出价点=点击）→ oCPA（出价点=转化）→ GMV MAX（出价点≈GMV），让平台直接优化广告主的最终经营目标。
- **引入 Enhance 模式（加强点）[过渡方案]**：当出价点尚未完全对齐考核点时，平台在现有出价模式基础上叠加更深层的优化信号作为"加强点"。例如广告主按 CPC 出价，但平台在竞价排序时额外引入 pCVR 信号，在不改变出价方式的前提下，倾斜流量给转化率更高的广告，这种出价模式称之为 eCPC（Enhanced CPC）。Enhance 模式的核心价值在于：不改变广告主的出价习惯和成本结构，同时让平台的流量分配更贴近广告主的深层目标，是从当前出价点向最终考核点演进过程中的过渡方案。
- **双出价（Dual Bidding）**：广告主同时设定浅层和深层两个出价目标（如同时对点击和成交出价），平台在一次竞价中联合优化两个目标。与方向一不同，双出价不是用深层目标替换浅层出价点，而是让广告主显式表达多层优化意图；与 Enhance 模式不同，深层目标不是平台隐式叠加的信号，而是广告主主动设定的约束。双出价适用于广告主既关注浅层效率（如点击成本）又关注深层效果（如转化成本）的场景，在出价点尚未完全统一到考核点之前，提供了一种兼顾多层目标的显式表达机制。

### 1.4.3 基础出价与智能出价 / Manual Bidding and Smart Bidding

#### 1.4.3.1 基础出价 / Manual Bidding




基础出价的核心特征是**出价点与计费点统一**——广告主直接按计费事件设定出价金额，平台按该金额扣费。


| 出价模式   | 出价点 | 计费点 | 广告主设定           | eCPM 转换（用于竞价排序）   | 实际扣费                           |
| ------ | --- | --- | --------------- | ----------------- | ------------------------------ |
| CPM 出价 | 曝光  | 曝光  | CPM 价格（每千次曝光出价） | eCPM = CPM 价格     | 按曝光扣费， Cost = CPM × 曝光数 / 1000 |
| CPC 出价 | 点击  | 点击  | CPC 价格（每次点击出价）  | eCPM = CPC × pCTR | 按点击扣费， Cost = CPC × 点击数        |


基础出价的特点：

- **透明可控**：广告主明确知道每次曝光/点击的最高成本，预算消耗完全可预期
- **优化责任在广告主侧**：平台只负责按 eCPM 排序和扣费，不主动优化转化效果。广告主需要自行判断合理出价、选择定向人群、优化素材
- **适用场景**：品牌曝光（CPM）、有成熟投放经验的广告主（CPC）、需要精确控制单次成本的场景

> 基础出价模式下，平台的 eCPM 排序公式直接由广告主出价决定： CPM 出价无需转换， CPC 出价通过 `eCPM = CPC × pCTR` 转换。平台唯一引入的模型预估是 pCTR（用于 CPC→eCPM 转换），优化深度有限。

#### 1.4.3.2 智能出价（Smart Bidding / oCPX） / Smart Bidding (oCPX)




智能出价的核心特征是**出价点与计费点分离**——出价点后移到更深层的转化事件（如 CPA、GMV），而计费点仍保持在曝光或点击。广告主只需设定业务层面的目标成本（如 Target CPA），平台通过模型预估自动计算每次竞价的出价。


| 出价模式 | 出价点 | 计费点 | 广告主设定      | eCPM 转换（用于竞价排序）                     | 实际扣费  |
| ---- | --- | --- | ---------- | ----------------------------------- | ----- |
| oCPC | 转化  | 点击  | Target CPA | eCPM = Target_CPA × pCVR × pCTR × λ | 按点击扣费 |
| oCPM | 转化  | 曝光  | Target CPA | eCPM = Target_CPA × pCVR × pCTR × λ | 按曝光扣费 |


智能出价与基础出价的核心区别：


| 对比维度    | 基础出价                | 智能出价（oCPX）              |
| ------- | ------------------- | ----------------------- |
| 出价点与计费点 | 统一（出价即计费）           | 分离（出价点更深，计费点不变）         |
| 广告主设定   | 每次曝光/点击的具体价格        | 业务目标成本（Target CPA）      |
| 模型依赖    | 仅 pCTR（CPC→eCPM 转换） | pCTR + pCVR + λ 调价系数    |
| 优化责任    | 广告主自行优化出价和转化        | 平台承担转化优化责任              |
| 风险分配    | 转化风险由广告主承担          | 转化风险部分转移给平台             |
| 适用场景    | 品牌曝光、成熟投放团队         | 追求转化效果的效果广告主（Shopee 主流） |


> 智能出价的本质是**平台用模型预估能力换取更深层的优化空间**：基础出价中平台只引入 pCTR，智能出价进一步引入 pCVR 和 λ 调价系数，让平台能够在整个曝光→点击→转化漏斗中进行全局优化。广告主从"手动调价"转变为"设定目标，让平台自动优化"，投放门槛降低的同时，平台也获得了更大的流量分配自由度。

#### 1.4.3.3 λ 调价系数 / The λ Repricing Coefficient




在上述 oCPX/tROAS 公式中， `Target_CPA × pCVR × pCTR` 是基于广告主目标和模型预估的"理论出价"，但模型预估不完美、且存在转换随机性等现实约束，λ 是弥合理论与现实差距的**反馈控制旋钮**，其核心调控目标是**成本达成**——确保实际 CPA/ROAS 逼近广告主设定的目标值，因此 oCPX/tROAS 又称为“成本出价”模式（与下文预算出价模式对应区分）：


| 目标                      | λ 的作用            | 机制                                            |
| ----------------------- | ---------------- | --------------------------------------------- |
| **预算控制（Budget Pacing）** | 控制日预算的消耗节奏       | 消耗过快 → λ < 1 压价减速；消耗不足 → λ > 1 提价加速           |
| **成本控制（Cost Control）**  | 保证实际 CPA 达成广告主目标 | 实际 CPA > Target → λ 下调；实际 CPA < Target → λ 上调 |
| **冷启动探索（Cold Start）**   | 新广告缺少历史数据时给予曝光机会 | 初始阶段 λ 适当偏高，积累数据后逐步回归                         |


λ 由离线竞价系统（如 ultrav-core）通过 PID 等反馈控制机制动态调整，作用是让实际投放效果（消耗速度、CPA 达成）不断逼近广告主设定的目标。

#### 1.4.3.4 两种典型的成本出价表达模式 / Two Typical Cost Bidding Expression Modes





| 出价模式                  | 广告主设定             | 平台优化目标                 | eCPM 公式                                     | 说明                          |
| --------------------- | ----------------- | ---------------------- | ------------------------------------------- | --------------------------- |
| **oCPX（目标成本出价）**      | Target CPA + 日预算  | 在达成目标 CPA 的约束下最大化转化数   | eCPM = Target_CPA × pCVR × pCTR × λ         | 最基础的智能出价模式，广告主明确设定单次转化的目标成本 |
| **tROAS（目标 ROAS 出价）** | Target ROAS + 日预算 | 在达成目标 ROAS 的约束下最大化 GMV | eCPM = pAOV × pCVR × pCTR × λ / Target_ROAS | 出价点从转化数后移到 GMV，适合关注成交回报的广告主 |

#### 1.4.3.5 为什么演进方向是”计费点前移 vs 出价点后移” / Why the Evolution Direction Is "Billing Point Shifts Forward vs. Bid Point Shifts Backward"




在广告漏斗中，事件顺序为：下发 → 曝光 → 点击 → 下单 → 支付 → 成交。从基础出价到智能出价，计费点和出价点呈相反的演进方向：

```
Billing point shift left ◀──────────────────────────────────▶ Bid point shift right

下发 ← 曝光(imp) ← 点击(click) ← 下单(order)    下单 → 支付 → 成交 → LTV
```

**(1) 计费点为什么尽可能前移（order → click → imp → 下发）？**

核心考量：**平台收入确定性和风险控制**

- **确定性高**：越前端的事件（曝光/下发）越确定会发生，平台收入越稳定。按曝光计费时，广告只要展示就产生收入；按转化计费时，平台收入依赖于不可控的用户后续行为
- **反作弊能力强**：前端事件（曝光/点击）发生在平台侧，平台可直接验证真实性；后端事件（下单/支付）涉及站外或延迟行为，作弊检测更困难
- **现金流及时**：计费点越靠前，平台回款周期越短，现金流越健康
- **系统复杂度低**：前端事件实时可得，无需等待漫长的归因窗口和转化回传

**(2) 出价点为什么尽可能后移（imp → click → 下单 → 支付 → 成交）？**

核心考量：**广告主 ROI 可控性和平台优化空间**

- **广告主视角**：出价点越后移，广告主的成本越接近真实业务价值。按 CPC 出价时广告主承担"点击不转化"的风险；按 CPA/GMV 出价时，这部分风险转移给平台，广告主的 ROI 更可控
- **平台优化空间**：出价点越后移，平台能优化的漏斗环节越多。按 CPC 出价时平台只优化曝光→点击；按 CPA 出价时平台可以同时优化曝光→点击→转化，整体效率更高
- **广告主投放门槛降低**：后移的出价点让广告主无需理解 CTR/CVR 等中间指标，只需要关注最终的经营成本，降低了投放的专业门槛

> **本质上是平台与广告主的风险分配博弈**：计费点前移让平台锁定收入、降低风险；出价点后移让广告主锁定 ROI、降低风险。两者的差距就是平台承担的优化责任——平台通过 pCTR/pCVR 等模型预估来弥合这个差距，模型越准确，平台承担的风险越小，同时广告主的体验越好。

### 1.4.4 Nobid/预算出价 / NoBid / Budget Bidding

#### 1.4.4.1 成本出价 VS 预算出价 / Cost Bidding vs. Budget Bidding




智能出价从 λ 调价系数的调控目标上可分为成本出价和预算出价：

- 成本出价（Cost-based Bidding）是指广告主设定一个业务层面的**目标成本**（如目标 CPA 或目标 ROAS），由平台根据模型预估（pCTR、pCVR 等）和调价系数 λ 自动计算每次竞价的 eCPM。
  - λ 的核心调控目标是**成本达成**——确保实际 CPA/ROAS 逼近广告主设定的目标值，同时兼顾预算平滑。
  - 但这两个目标可能冲突：成本约束和预算约束是两个独立约束，却共享同一个控制变量 λ。当广告主的目标成本相对市场价格偏紧时（即满足成本约束的流量总量不足以消耗完预算），守住成本就花不完预算，花完预算就超成本，反之，当广告主的目标成本相对市场价格偏松时（即满足成本约束的流量总量的消耗超过设定的日预算），守住成本就提前预算撞线，在投放周期内平滑花完就欠成本。实践中大多数平台采用**成本优先**策略——宁可预算花不完或者提前撞线也不突破成本目标，因为设定了 Target CPA 的广告主对单次转化成本的确定性要求高于对预算消耗的要求。工程上常见做法是将 λ 拆分为两个独立分量 `λ = λ_cost × λ_pacing`，分别跟踪成本偏差和预算消耗进度，当两者冲突时通过优先级权重决定最终行为（通常 λ_cost 优先级更高）。
- 预算出价（Budget-based Bidding / NoBid）是指广告主**仅设定日预算**，不设定任何目标成本，将出价决策完全交给平台。平台在预算约束下自主决定每次竞价的 eCPM，目标是最大化转化数或 GMV。
  - λ 的核心调控目标是**预算消耗**——确保预算在投放周期内平滑花完，同时最大化整体效果。
  - 这两个目标本质上是统一的：预算未花完意味着放弃了本可获得的转化，因此"花完预算"是最大化转化的必要条件；而给定预算总额固定，最大化转化等价于让每一块钱花在边际转化价值最高的流量上——如果某个时段集中花费过多，会因竞争加剧而推高单次转化成本，如果某个时段花费不足，则错失了低价转化机会。因此最优预算分配策略天然要求按流量价值分布平滑消耗，这正是 λ 作为预算约束的拉格朗日乘子所实现的：λ 动态调整出价水平，使边际转化成本在各时段/流量间趋于均衡，从而同时实现"花完"和"花好"。


| 对比维度   | 成本出价（oCPX / tROAS）           | 预算出价（NoBid / MCB / BCB）           |
| ------ | ---------------------------- | --------------------------------- |
| 广告主设定  | 目标成本（Target CPA / ROAS）+ 日预算 | 仅日预算（无需出价）                        |
| λ 核心目标 | 成本达成优先，兼顾预算平滑                | 预算消耗优先，最大化效果                      |
| 平台优化目标 | 在目标成本约束下最大化转化/GMV            | 在预算约束下最大化转化/GMV                   |
| 广告主控制力 | 中等——广告主通过目标成本约束平台的出价范围       | 最低——广告主仅控制花多少钱，不控制怎么花             |
| 适用场景   | 对单次转化成本 / ROI 有明确要求的广告主      | 追求最大化效果、或者不关心单次成本的广告主；投放经验较少的新广告主 |
| 典型产品   | oCPX（目标 CPA）、tROAS（目标 ROAS）  | MCB（最大转化出价）、BCB（预算控制出价）           |


> 从成本出价到预算出价，广告主的设定越来越简单（从设目标成本到只设预算），平台承担的优化责任越来越大（从在成本约束下优化到全权决策出价）。两者的核心差异在于 λ 的调控目标：成本出价中 λ 优先保证成本达标，预算出价中 λ 优先保证预算平滑花完。
>
> 值得注意的是，两种出价模式的优化目标都是”最大化转化/GMV”，只是约束条件不同，因此在一些场景，二者分别叫做 GMVMAX-TargetROAS 和 GMVMAX-NoBid，所以这两种出价模式的考核点是相同的，都是转化量或者 GMV。

#### 1.4.4.2 NoBid 适用场景 / Applicable Scenarios for NoBid




Nobid 的核心前提是"广告主只设预算，不设目标成本"，因此适用场景本质上取决于：**什么情况下广告主的核心约束是预算而非单次成本**（即"预算确定、成本可变"）。


| 适用场景          | 说明                                                                            | 典型案例                                                |
| ------------- | ----------------------------------------------------------------------------- | --------------------------------------------------- |
| **预算刚性、成本弹性** | 广告主有明确的预算上限，但对单次转化成本有一定容忍空间，核心诉求是"这笔钱花完、花好"                                   | 中小卖家、预算有限的新品牌                                       |
| **短周期投放**     | 投放窗口短（几小时到一天），成本出价的 λ 没有足够时间收敛到稳态， Nobid 的预算 pacing 机制更契合                     | 直播推广（2-4 小时）、大促限时活动（双 11、Flash Sale）、短剧/内容首发        |
| **缺乏成本基准**    | 没有历史数据判断合理的 Target_CPA，强行设定大概率不准，不如交给平台在预算约束下自动探索                             | 新广告主首次投放、新品/新市场/新区域、首次尝试新广告形式（Video Ads / Live Ads） |
| **追求最大化量级**   | 处于增长期，核心目标是快速获取用户/订单规模，对单次成本敏感度低于对总量的要求                                       | 新品冲销量打爆品、抢占市场份额、冷启动期快速积累模型样本                        |
| **代理商预算执行**   | 代理商受客户委托管理投放，预算是硬约束（花不完要退款），单次成本是软约束， Nobid 天然契合"给定预算、最大化产出"的委托关系             | 代理商/服务商代投场景                                         |
| **多计划组合调控**   | 成熟广告主同时运行多个计划，每个计划内部用 Nobid 最大化产出，在计划间层面通过预算分配做整体 ROI 调控，将成本控制从单计划维度提升到投放组合维度 | 大广告主多计划并行投放                                         |

#### 1.4.4.3 Nobid 预算消耗规划 / NoBid Budget Consumption Planning




Nobid 的调控目标是在投放周期内**平滑花完预算并最大化转化**。实现方式分为两步：

- 第一步，**制定消耗计划**：将总预算拆分到每个时段，确定每个时段应花多少钱
- 第二步，**实时跟踪执行**：通过 λ（出价乘数）跟踪消耗计划——实际消耗落后于计划时提高 λ，出价上升，加速消耗；实际消耗超前时降低 λ，出价下降，减速消耗

第 2 步是通用的控制机制，因此核心问题变为：**如何制定消耗计划？**

下表按策略质量从低到高排列，每种策略的问题恰好引出下一种策略的改进动机：


| 策略           | 做法                                | 问题                                                   |
| ------------ | --------------------------------- | ---------------------------------------------------- |
| **① 提前花完**   | 不做规划，有流量就买，预算花完即停                 | 后半段投放窗口的优质流量完全无法购买，整体转化效率低                           |
| **② 随机波动**   | 消耗忽高忽低，无明确分配规则                    | 效果不可预期，无法进行有意义的 A/B 测试或效果归因                          |
| **③ 均匀分配**   | 将预算按时间均匀分配（如日预算 ÷ 24 小时）          | 未考虑流量分布差异——凌晨流量可能只占全天 5%，却分配了与晚高峰相同的预算，导致低流量时段购买比例畸高 |
| **④ 按流量分布**  | 按各时段的历史流量占比分配预算，使每个时段的购买比例与大盘流量一致 | 未考虑各时段竞争强度差异——所有时段以相同比例购买，忽略了竞争弱的时段性价比更高这一事实         |
| **⑤ 按性价比分布** | 综合考虑流量规模和竞争强度，在性价比高（竞争弱）的时段多分配预算  | 理论最优但实操最难——性价比受竞争对手出价影响，难以提前准确预测                     |


业界主流的 Nobid 策略基于策略④或⑤，结合 λ 实时跟踪机制形成”规划 → 跟踪 → 调整”的闭环。

#### 1.4.4.4 预算出价和成本出价优劣势对比 / Comparison of Advantages and Disadvantages: Budget Bidding vs. Cost Bidding





| 对比维度         | 成本出价（oCPX / tROAS）                                       | 预算出价（NoBid）                                    |
| ------------ | -------------------------------------------------------- | ---------------------------------------------- |
| **冷启动激励**    | 优势：平台补贴+赔付，广告主冷启动门槛低                                     | 优势：无赔付，广告主自担成本，激励精选素材、减少盲目堆量                   |
|              | 劣势：广告主无需为低质素材买单，易引发逆向选择（堆量骗补贴）                           | 劣势：经验不足的广告主失去补贴后冷启动成本可能上升                      |
| **eCPM 控制力** | 优势： Target_CPA 是 eCPM 公式中的一阶乘法因子，修改后直接改变 eCPM，竞价能力变化即时可控 | 劣势：只能通过调整预算间接影响 λ，再由 λ 影响 eCPM，属于二阶间接影响，幅度不确定  |
| **意图表达**     | 优势：直接表达”CPA/ROAS 必须达标”的诉求                                | 优势：直接表达”花好这笔预算”的诉求，无需猜测合适的目标成本                 |
|              | 劣势：预算有限的广告主需要反向试错合适的 Target_CPA 来花完预算，试错本身是效率损失          | 劣势：无法直接约束单次转化成本，成本不可控                          |
| **风控与出价激进度** | 优势：成本保护机制明确，单次转化成本波动可控                                   | 优势：无成本约束的保守压价，出价更激进，有机会获取更多流量和转化               |
|              | 劣势：为保成本，平台倾向保守压价（宁可少花预算也不超成本），可能错失优质流量                   | 劣势： pacing 仍面临延迟回传挑战，风控问题从”成本维度”转移到”预算维度”，并未消失 |
| **投放门槛**     | 优势：设定目标成本即可，无需过分关注预算分配，平台自动优化保证成本达成                      | 优势：只需设定预算，无需猜测合适的目标成本，投放设置更简单                  |
|              | 劣势：需要根据自身营销诉求和预算设定最合适的 Target_CPA，设定不当会导致花不完预算或 ROI 过低   | 劣势：需要自行判断素材质量、制定预算分配策略、把控风险敞口，对优化师经验要求高        |


> 两种模式是**互补关系**而非替代关系，服务的核心诉求不同：成本出价保障单次转化成本的确定性，预算出价保障预算利用的最大化效率。实践中可结合使用，例如用预算出价做冷启动阶段积累数据，再切换成本出价铺量。

#### 1.4.4.5 NoBid 的增长困境 / NoBid's Growth Dilemma




NoBid 缺乏 ROI 锚点，导致广告主 ROI 分布两极化，而两端都缺乏扩预算动力——形成"双向锁死"：


| 对比维度          | NoBid                                       | Target ROAS                                |
| ------------- | ------------------------------------------- | ------------------------------------------ |
| **低 ROI 广告主** | 无成本约束兜底， ROI 低于经营底线 → 停投或缩预算，流失存量收入         | ROI 锚定在目标值，成本可控，留存率高                       |
| **高 ROI 广告主** | ROI 远超经营需求，但预期"加预算 = λ 上升 = ROI 下降" → 不愿扩预算 | 加预算后平台自动调 λ 维持 ROI 不变 → 扩预算阻力小             |
| **增长飞轮**      | ROI 不可控 → 流失 + 锁死 → 预算池停滞 → 负反馈             | ROI 可控 → 扩预算 → 更多数据 → 模型更准 → ROI 更稳 → 正向飞轮 |


> NoBid 增长困难的根本原因：低 ROI 广告主因成本失控而流失，高 ROI 广告主因"加预算降 ROI"的预期而锁死预算，两端同时受阻导致收入池难以扩张。Target ROAS 通过显式 ROI 约束打破困局——扩预算从"ROI 赌博"变为"确定性投资"。

#### 1.4.4.6 业界解决方案 / Industry Solutions




针对以上增长困境，各主流广告平台围绕"给 NoBid 叠加 ROI 约束"提出了不同形式的解法：


| 方案                    | 代表平台                                                                     | 核心思路                                      | 解决的问题                    |
| --------------------- | ------------------------------------------------------------------------ | ----------------------------------------- | ------------------------ |
| **NoBid + 可选 ROI 下限** | Google（Maximize Conversion Value + optional Target ROAS）、拼多多（全站推广设目标投产比） | 在 NoBid 基础上叠加可选的 ROAS 约束，不设则纯花预算，设了则保 ROI | 低 ROI 广告主流失——给安全网        |
| **分阶段演进**             | TikTok（Maximum Delivery → Cost Cap / Target ROAS）                        | 冷启动用 NoBid 积累 50+ 转化数据，数据稳定后切换到成本出价       | 新广告主缺乏数据基准，无法设合理 ROAS    |
| **成本保护 / 赔付**         | TikTok Smart+（Incentive Offer）、Meta（Minimum ROAS）                        | 未达成成本目标则返还广告费，或设 ROAS 下限仅在预测达标时竞价         | 新广告主首投不确定性高，尝试意愿低        |
| **ROI 内化为优化目标**       | Meta（Maximize ROAS， 2025 年更名）                                            | 算法目标从"最大化转化价值总量"转为"最大化每美元回报"              | 从根本上将 ROI 效率从约束条件升级为优化目标 |


> 核心规律：解法殊途同归——在 NoBid 的预算消耗逻辑上叠加 ROI 维度的约束或激励。区别仅在于约束形式：可选 ROAS 下限、阶段性切换、自动加预算、成本赔付、或将 ROI 直接内化为优化目标。
>
> 值得注意的是，以上方案主要解决"低 ROI 广告主流失"的问题，但对"高 ROI 广告主不愿加预算"的困境并未真正解决。在纯 NoBid 下，"加预算 = ROI 下降"是数学必然——预算增加 → λ 上升 → 买入边际流量质量下降 → ROI 降低。没有 ROI 约束时系统的目标是花完预算而非维持 ROI，因此这一问题在 NoBid 框架内无解。所有方案的本质都是将 NoBid 变成"带 ROI 约束的 NoBid"，从而绕开而非解决困境。唯一能让高 ROI 广告主安心加预算的前提是系统承诺"加预算后 ROI 不变"——而这恰好是 Target ROAS 的定义。

### 1.4.5 双出价 / Dual Bidding

#### 1.4.5.1 为什么需要双出价 / Why Dual Bidding Is Needed




**从广告主视角：单出价无法表达真实诉求**

在双出价出现之前，广告主只能二选一：


| 方案                | 做法               | 问题                                            | 广告主痛点                   |
| ----------------- | ---------------- | --------------------------------------------- | ----------------------- |
| **浅层出价**（oCPA-激活） | 只约束激活成本，系统只优化激活量 | 系统倾向于找"容易激活但不付费"的低质用户，深层转化效果差                 | 流量充足，但深层转化收益低           |
| **深层出价**（oCPA-付费） | 只约束付费成本，系统直接优化付费 | 深层转化事件极度稀疏（付费率可能 <1%），模型预估不准、起量困难，且浅层成本可能飙升失控 | 深层效果好但难以起量，或者激活成本过高导致亏损 |


> **双出价解决的核心矛盾**：广告主既要浅层成本可控（控制亏损底线），又要深层效果达标（保证 ROI）。单一出价只能顾一头，双出价让广告主完整表达了业务约束。

**从平台视角：提升广告生态健康度和收入天花板**

- **留住深转广告主，撬动预算**：深转广告主（游戏、电商、金融等）预算大但对效果要求高。浅层出价效果差导致降预算，深层出价难以起量导致预算花不出去。双出价让这类广告主既能起量又能保效果，愿意持续投放并提升预算
- **提升流量分配效率**：单浅层出价下系统无法区分"高质量激活"和"低质量激活"。双出价引入深层信号后，系统可以把流量分配给真正能产生深层价值的广告，提升整体流量变现效率
- **缓解模型稀疏性问题**：纯深层出价面临样本极度稀疏。双出价框架下，浅层目标提供充足样本支撑模型学习，深层目标在此基础上做精细化挑量，兼顾模型可学性和优化精度

#### 1.4.5.2 竞价机制 / Auction Mechanism




**基础 eCPM 计算**

双出价下，每个广告有两套独立的 eCPM：

```
eCPM_浅 = bid_浅 × pCTR × pCVR_浅
eCPM_深 = bid_深 × pCTR × pCVR_浅 × pDVR
```

其中 pDVR（Deep Conversion Rate）= 浅层转化到深层转化的条件概率。两套 eCPM 分别代表该流量在两个约束下的期望价值上限。

**竞价打分**

竞价打分需要解决三个不同性质的问题：**模型校准**（ratio）、**成本达成调控**（λ）、**信号融合**（排序），加上尾部风控过滤。三者逻辑独立，实现上是一次打分计算：

```
eCPM_浅' = eCPM_浅 × ratio_浅 × λ_浅
eCPM_深' = eCPM_深 × ratio_深 × λ_深
eCPM_final = f(eCPM_浅', eCPM_深') × I(pDVR ≥ threshold)
```

ratio 和 λ 都分别作用于各侧 eCPM（融合前），但解决的是两个本质不同的问题，必须严格区分。

**(1) 模型校准（ratio）：让未来的预估更准**

目标：修正模型预估的系统性偏差，使未来每一次预估的 pCoC（predicted CVR over actual CVR）趋近于 1。ratio 是一个**前向校准系数**，只关心"未来的预估准不准"，不关心"过去花多了还是花少了"。

```
ratio_浅 = actual_CVR_浅 / predicted_CVR_浅    // 浅层模型校准
ratio_深 = actual_DVR / predicted_DVR          // 深层模型校准
```

- 模型高估（pCoC > 1）→ ratio < 1 → 压低该侧 eCPM
- 模型低估（pCoC < 1）→ ratio > 1 → 抬高该侧 eCPM
- 更新频率较慢（小时级），基于累积统计数据平滑计算，各侧独立校准

**(2) 成本达成调控（λ_浅、λ_深）：保证全天成本达标**

目标：在全天维度上保证浅层和深层的实际成本分别不超出广告主出价约束，需要对过去已经发生的超收或欠收做补偿。λ 是一个**后向补偿系数**，不仅关心"未来出价是否合理"，还要为"过去的历史包袱"买单。

```
浅层 PID：监控 actual_cost_浅 vs bid_浅 的累积偏差 → 输出 λ_浅
深层 PID：监控 actual_cost_深 vs bid_深 的累积偏差 → 输出 λ_深
```

- 更新频率较快（分钟级），基于实时成本反馈通过 PID 控制器调节
- λ_浅 和 λ_深 各自独立，分别跟踪各自的成本偏差

> **ratio 和 λ 都放在融合前**，使融合函数在校准且调控后的准确值上操作。当某侧被融合函数"屏蔽"时（如 min 融合下非瓶颈侧），恰恰说明该侧约束不紧、不需要调控。

**(3) ratio vs λ 的本质区别**


| 维度       | ratio（模型校准）         | λ（成本达成调控）         |
| -------- | ------------------- | ----------------- |
| 解决的问题    | 未来每次预估的准确性          | 全天累积成本的达标性        |
| 时间方向     | **前向**：让未来预估准       | **后向**：补偿过去的偏差    |
| 是否承担历史包袱 | 否，只校准预估本身           | 是，需要为超收/欠收做补偿     |
| 数据来源     | pCoC 统计（预估值 vs 真实值） | 实际成本 vs 目标成本的累积偏差 |
| 更新频率     | 慢（小时级）              | 快（分钟级）            |
| 收敛目标     | pCoC → 1            | 全天成本 → bid × 转化数  |


两者不可替代的例子：

- **ratio 修正了但 λ 不可少**：上午 ratio_浅 不准导致浅层超收 500 元，中午 ratio_浅 已修正（pCoC ≈ 1），未来预估准了，但 500 元超收是历史事实 → 需要 λ_浅 < 1 下午补偿
- **λ 调控了但 ratio 不可少**：模型系统性高估 pCVR 20%，λ_浅 通过压价确实能控住浅层成本，但排序是错的——高估的广告排在前面挤掉了本该胜出的广告 → 需要 ratio_浅 先校准预估让排序合理

**(4) 尾部过滤：剔除极端低质流量**

当 pDVR 极低时（如 0.001%），预估本身方差极大，且深层转化延迟回传（可能数天），成本调控来不及响应。对这类流量直接置零：

`pDVR < threshold → eCPM_final = 0（不参与竞价）` 

threshold 确定方式：**静态** `threshold = bid_浅 / bid_深` （两侧 eCPM 相等的临界点）；**动态**：基于实时深层成本反馈动态调整。

#### 1.4.5.3 eCPM 融合策略 / eCPM Fusion Strategies




核心问题：如何将校准调控后的两个 eCPM 融合为一个最终竞价分数。


| 方案                  | 公式                              | 优点                   | 缺点                          |
| ------------------- | ------------------------------- | -------------------- | --------------------------- |
| **取最小值**            | `min(eCPM_浅', eCPM_深')`         | 成本控制严格，双成本达标率高       | 过于保守，竞价能力被较差一侧拖累，起量困难       |
| **加权融合**            | `α × eCPM_浅' + (1-α) × eCPM_深'` | 灵活，起量和效果之间可调         | α 与 λ_浅/λ_深 形成多层反馈环路，容易耦合振荡 |
| **浅层 × 深层调节**（业界主流） | `eCPM_浅' × g(pDVR)`             | 起量由浅层兜底，效果由深层调节，职责清晰 | 需精细调参， g 函数依赖实时统计           |


> 方案三中典型的 g 函数实现： `g(pDVR) = (pDVR / avg(pDVR)) ^ β`，β 控制调节力度。pDVR 高于均值的流量被扶持，低于均值的被打压。深层成本调控（ratio_深、λ_深）通过影响 g() 的参数或 threshold 间接实现。

**融合策略与约束冲突的关系**

双出价的核心矛盾是浅层和深层两个成本约束的方向性冲突：保深层效果需要挑量（缩量），保浅层起量需要放宽深层筛选。不同融合策略处理冲突的方式不同：

- **min()** 天然避免冲突（始终取较紧一侧），但竞价力永远被弱侧拖累
- **加权融合**中 α 与 λ_浅/λ_深 形成多层反馈环路，可能出现耦合振荡：深层超标 → α↓ → 整体出价降 → 浅层消耗不足 → λ_浅↑ → 整体出价回升 → 深层再次超标。缓解方案包括限制调节幅度、设置优先级（深层优先）、α 和 λ 使用不同时间尺度
- **浅层 × g(pDVR)** 职责正交天然解耦：浅层侧（含 ratio_浅 × λ_浅）管起量和浅层成本， g(pDVR) 只做流量间相对排序，不存在耦合问题。这也是该方案成为业界主流的原因之一

#### 1.4.5.4 完整竞价流程 / Complete Auction Process




```
请求到达
  │
  ├─ 1. Recall candidate ad set
  │
  ├─ 2. Model prediction: pCTR, pCVR_shallow, pDVR
  │
  ├─ 3. Auction scoring (single computation)
  │     a. Model calibration + cost control:
  │        eCPM_shallow' = eCPM_shallow × ratio_shallow × λ_shallow
  │        eCPM_deep' = eCPM_deep × ratio_deep × λ_deep
  │     b. Tail filtering: pDVR < threshold → eCPM_final = 0
  │     c. Fusion ranking: eCPM_final = f(eCPM_shallow', eCPM_deep')
  │
  ├─ 4. Unified ranking, winner gets impression
  │
  └─ 5. Post-hoc attribution
        a. 更新 pCoC 统计 → 调整 ratio_浅/ratio_深（模型校准）
        b. 更新各侧累积成本偏差 → PID 调整 λ_浅/λ_深（成本达成调控）
```

#### 1.4.5.5 核心难点 / Core Challenges




- **深层信号延迟**：深层转化（如付费）可能发生在点击后数小时甚至数天， ratio_深 和 λ_深 拿到的反馈都是滞后的， ratio_深 统计窗口需要足够长以平滑噪声，λ_深 的 PID 控制器需要考虑延迟补偿
- **样本稀疏**： pDVR 模型的正样本极少（付费率可能 <1%）， ratio_深 的统计量不足导致校准本身不稳定
- **两侧博弈**：过度挑量保深层 → 浅层拿不到量；放松挑量保量级 → 深层成本超标。ratio 保证各侧排序合理性，λ 保证各侧成本可控，两者在各侧独立配合缓解博弈

#### 1.4.5.6 双出价 vs 单出价总结 / Dual Bidding vs. Single Bidding Summary





| 维度   | 单浅层出价 | 单深层出价 | 双出价         |
| ---- | ----- | ----- | ----------- |
| 起量能力 | 强     | 弱     | 强           |
| 深层效果 | 不可控   | 好     | 可控          |
| 浅层成本 | 可控    | 不可控   | 可控          |
| 模型学习 | 样本充足  | 样本稀疏  | 浅层兜底 + 深层精选 |


> 双出价本质上是在**起量（exploration）和效果（exploitation）之间找到平衡点**，让广告主能完整表达业务约束，让平台能更高效地分配流量。

### 1.4.6 广告混排 / Ad Blending

#### 1.4.6.1 什么是混排 / What Is Ad Blending




**广告混排（Ad Blending / Ad Mixing）** 是指将竞价胜出的广告与自然内容（Organic Results）合并为统一的展示列表，最终呈现给用户的过程。它是 [§1.3.1](03.system-pipeline-modules.zh-CN.md#131-系统链路全景) 广告链路中 **"出价 & 混排"** 阶段的核心环节。

混排的本质是一个 **三方博弈** 问题：


| 参与方 | 目标        | 混排中的诉求           |
| --- | --------- | ---------------- |
| 平台  | 最大化广告收入   | 尽可能多地展示高 eCPM 广告 |
| 广告主 | 最大化投放 ROI | 广告出现在高转化潜力的位置    |
| 用户  | 最佳浏览体验    | 广告不干扰内容消费，且具备相关性 |


> 混排的目标不是"展示尽可能多的广告"，而是在 **收入、ROI 和体验** 之间找到帕累托最优。

#### 1.4.6.2 独立链路 vs 融合链路 / Independent Pipeline vs. Integrated Pipeline




Shopee 广告系统存在两种混排架构，对应 [§1.3.1](03.system-pipeline-modules.zh-CN.md#131-系统链路全景) 中的两条链路：


| 维度        | 独立链路（标准模式）            | 融合链路（GMV MAX）               |
| --------- | --------------------- | --------------------------- |
| 召回排序      | 广告独立召回、独立排序           | 广告与自然内容统一召回、统一排序（API0-API3） |
| 混排方式      | 在最终展示阶段将广告插入自然结果      | 排序阶段已完成融合，无需额外插入            |
| RankScore | 广告内部排序使用，混排阶段做坑位/插入决策 | 广告与自然内容使用统一排序分              |
| 优势        | 架构简单，广告与自然解耦，迭代独立     | 全局最优排序，用户体验更一致              |
| 劣势        | 插入位置可能不是全局最优          | 架构复杂，广告与自然耦合度高              |

#### 1.4.6.3 混排策略：固定坑位 vs 动态插入 / Blending Strategies: Fixed Slots vs. Dynamic Insertion




根据广告类型（参考 [§1.2.3.1](02.online-advertising-fundamentals.zh-CN.md#1231-按投放机制分类) 的分类），混排策略可分为两大类：


| 维度           | 固定坑位（Reserved Slot）                  | 动态插入（Dynamic Insertion）              |
| ------------ | ------------------------------------ | ------------------------------------ |
| 机制           | 页面预留特定位置给广告，不参与排序竞争                  | 广告按 RankScore 与自然内容竞争展示位置            |
| RankScore 作用 | 仅决定该坑位内的广告选择                         | 决定广告是否插入以及插入位置                       |
| 广告负载控制       | 坑位数量固定，负载天然可控                        | 需要额外的密度约束和频控规则                       |
| 适用广告类型       | 展示广告、品牌广告（[§1.2.3.1](02.online-advertising-fundamentals.zh-CN.md#1231-按投放机制分类)） | 效果广告、搜索广告（[§1.2.3.1](02.online-advertising-fundamentals.zh-CN.md#1231-按投放机制分类)） |

#### 1.4.6.4 广告负载与体验约束 / Ad Load and Experience Constraints




为保障用户体验，混排阶段会施加一系列 **体验约束（Experience Constraints）**：


| 约束类型                     | 说明                    | 示例               |
| ------------------------ | --------------------- | ---------------- |
| **广告密度上限（Ads Load）**     | 单页/单屏广告数量占比不超过阈值      | 搜索结果页广告密度 ≤ 20%  |
| **最小自然间距（Min Gap）**      | 两条广告之间至少间隔 N 条自然结果    | 相邻广告间至少 2 条自然内容  |
| **同店频控（Same-Shop Cap）**  | 同一店铺的广告在单次请求中最多展示 N 条 | 同店铺广告 ≤ 2 条      |
| **会话级曝光上限（Session Cap）** | 同一广告在单次用户会话中的曝光次数上限   | 同一广告同次会话最多曝光 3 次 |
| **位置约束（Position Rule）**  | 特定广告类型只能出现在特定位置范围     | 品牌广告仅出现在首屏前 3 位  |


这些约束在混排决策时作为 **硬约束（Hard Constraints）** 执行——即使广告 RankScore 很高，违反体验约束的广告也不会被展示。

#### 1.4.6.5 排序公式与多目标优化 / Ranking Formula and Multi-Objective Optimization




混排的核心排序依据是 [§1.3.2.4](03.system-pipeline-modules.zh-CN.md#1324-售卖机制) 中的 **RankScore 公式**：

```
RankScore = α × eCPM + β × OrgScore
```

两个分项的策略含义：

- **eCPM（有效千次曝光价值）**：来自广告出价（[§1.4.3](#143-基础出价与智能出价)~[§1.4.5](#145-双出价)），反映广告的 **商业价值**——广告主愿意为该流量支付多少
- **OrgScore（原生价值分）**：反映广告的 **平台原生价值**，综合了生态价值（如广告商品的好评率、店铺服务质量、用户留存贡献）和内容质量（如标题相关性、图片质量、落地页体验）

权重参数 **α / β** 的调整体现了平台在不同阶段的策略倾向：

- 偏重 α → 倾向收入最大化
- 偏重 β → 倾向生态健康与用户体验

> 混排是平衡收入、ROI 和体验的 **"最终守门人"**——它决定了用户最终看到什么，是广告系统所有上游优化的最终落地点。各广告类型的混排实现细节见 Chapter 2 [§2.4.3](../02.ads-strategy/04.traffic-strategy-and-billing.zh-CN.md#243-混排和计费)。

### 1.4.7 广告计费 / Ad Billing

#### 1.4.7.1 计费的定位 / The Role of Billing




**广告计费（Ads Billing/Deduction）** 是广告系统向广告主实际收取费用的环节。在 [§1.3.1](03.system-pipeline-modules.zh-CN.md#131-系统链路全景) 广告链路中，它位于 **"计费 & 展示"** 阶段；在 GMV MAX 融合链路中，对应 API3 的 Deduction 模块。

计费与 [§1.4.2](#142-广告出价和售卖的核心概念) 中的 **"计费点（Billing Point）"** 概念直接相关：当用户行为触发计费事件（如点击、曝光）时，系统执行扣费计算，从广告主预算中扣除相应金额。

#### 1.4.7.2 拍卖机制： GSP vs GFP / Auction Mechanisms: GSP vs. GFP




广告系统的扣费金额由拍卖机制决定。业界主流的两种拍卖机制：

**GFP（Generalized First-Price，广义一价拍卖）**：竞价胜出者按自己的出价支付。

**GSP（Generalized Second-Price，广义二价拍卖）**：竞价胜出者按下一名的价格（加最小增量 δ）支付。


| 维度      | GFP（广义一价）         | GSP（广义二价）                           |
| ------- | ----------------- | ----------------------------------- |
| 扣费规则    | 赢家支付自己的出价         | 赢家支付下一名价格 + 最小增量 δ                  |
| 广告主激励   | 鼓励压价博弈（出价 < 真实估值） | 鼓励真实出价（出价 ≈ 真实估值）                   |
| 均衡稳定性   | 不稳定，广告主持续试探最低胜出价  | 较稳定，真实出价是弱占优策略                      |
| 平台收入稳定性 | 波动大，受博弈行为影响       | 较稳定，扣费由竞争格局决定                       |
| 业界采用    | 部分 DSP、程序化展示广告    | Google Ads、Meta Ads、Shopee Paid Ads |


> **Shopee Paid Ads 采用 GSP（广义二价拍卖）作为主要计费机制**，鼓励广告主真实出价，降低博弈成本，提升市场效率。

#### 1.4.7.3 GSP 扣费公式推导 / GSP Deduction Formula Derivation




从 [§1.3.2.4](03.system-pipeline-modules.zh-CN.md#1324-售卖机制) 的 RankScore 公式出发，推导 GSP 下的实际 CPC 扣费：

**排序公式：**

```
RankScore_i = α × eCPM_i + β × OrgScore_i
```

其中 `eCPM_i = Bid_i × pCTR_i`（CPC 出价模式下）。

**GSP 扣费条件：** 第 i 名广告的扣费恰好使其 RankScore 等于第 i+1 名：

```
α × (actual_CPC_i × pCTR_i) + β × OrgScore_i = RankScore_{i+1}
```

**求解实际 CPC：**

```
actual_CPC_i = (RankScore_{i+1} - β × OrgScore_i) / (α × pCTR_i) + δ
```

其中 **δ** 为最小增量（通常为 0.01），确保胜出者的 RankScore 严格高于下一名。

**关键洞察：**

- GSP 下实际扣费 **仅取决于竞争对手的 RankScore**，不取决于自身出价高低——出价更高不会导致扣费更多，只会提升胜出概率
- oCPX 智能出价下， GSP 扣费逻辑不变——oCPX 的差异体现在上游出价阶段（[§1.4.3](#143-基础出价与智能出价)~[§1.4.5](#145-双出价)），计费点层面仍然执行标准 GSP

#### 1.4.7.4 底价与扣费边界 / Reserve Price and Deduction Boundaries




在实际系统中， GSP 扣费还需要考虑多种边界条件：

> **关于底价（Reserve Price）：** 底价是 **出价/竞价环节** 的准入门槛，而非计费环节的扣费下限。出价低于底价的广告直接不进入竞价排序，从而避免"低出价赢得排序、却按高底价计费"的不一致——排序和计费使用的价格信号应当统一。

**扣费上下限（Min Cap / Max Cap）：** 分别基于一价（GFP，广告主出价）和二价（GSP）设定扣费边界，防止极端扣费：

- **Min Cap**： `min_cap = bid × gfp_min_ratio`（ `gfp_min_ratio < 1`）——基于一价打折，当 GSP 扣费过低时以此兜底，保护平台收入
- **Max Cap**： `max_cap = min(GSP_price × gsp_max_ratio, bid)`（ `gsp_max_ratio > 1`）——取二价上浮与一价的较小值。相比仅用 `bid` 做上限，额外引入 `GSP_price × gsp_max_ratio` 可以防止模型预估异常（如 pCTR 预估值异常偏高）导致 `bid` 过高时计费出极值

设计思路：用 **一价（广告主出价）控制下限**，用 **二价（GSP 扣费）+ 一价双重控制上限**——下限锚定广告主的支付意愿，上限同时锚定竞争格局和出价意愿，两端分别防止"扣费过低伤平台"和"扣费过高伤广告主"。

**最终扣费公式：**

```
min_cap = bid × gfp_min_ratio                   // 一价兜底（gfp_min_ratio < 1）
max_cap = min(GSP_price × gsp_max_ratio, bid)   // 二价封顶 + 一价硬上限（gsp_max_ratio > 1）
actual_charge = clip(GSP_price, min_cap, max_cap)
```

其中 `clip(x, lo, hi) = max(lo, min(x, hi))`。

- 当竞争充分时， `GSP_price` 落在 `[min_cap, max_cap]` 区间内，实际扣费 = GSP 标准二价
- 当竞争不足、GSP 扣费过低时，实际扣费被 `min_cap` 兜底，等效于一价的折扣价
- 当竞争激烈、GSP 扣费偏高时，实际扣费被 `max_cap` 封顶——优先被 `GSP_price × gsp_max_ratio` 约束，极端情况下再被 `bid` 硬兜底
- 当模型预估异常、`bid` 异常偏高时， `GSP_price × gsp_max_ratio` 仍基于真实竞争的二价，不会跟随 `bid` 一起飙升，从而有效防止极端扣费

#### 1.4.7.5 智能出价下的计费特殊性 / Special Characteristics of Billing Under Smart Bidding




在 oCPX 智能出价（[§1.4.3.2](#1432-智能出价 smart-bidding-ocpx)）模式下，计费具有一些与基础出价不同的特征：

**单次扣费波动大：** oCPX 通过 λ 调价系数动态调整出价（[§1.4.3.3](#1433-λ-调价系数)），导致单次 CPC 扣费在不同流量上差异显著。广告主应以 **聚合 CPA/ROAS** 而非单次 CPC 来衡量效果。

**成本保障与赔付机制：** 平台对 oCPX 广告主提供成本保障承诺——在冷启动学习期内，若平均 CPA 超过目标值，平台将补偿超出部分：

```
compensation = actual_cost - target_CPA × conversions  （若结果为正则触发赔付）
```


| 维度     | 基础出价（Manual CPC） | 智能出价（oCPX）          |
| ------ | ---------------- | ------------------- |
| 单次扣费行为 | 稳定，与出价差距可预期      | 波动大，受 λ 动态调整影响      |
| 成本控制机制 | 广告主通过出价直接控制      | 平台通过 λ 算法自动控制聚合成本   |
| 风险承担方  | 广告主（出价即最大成本）     | 平台（承诺目标 CPA，提供赔付保障） |
| 效果衡量粒度 | 单次点击成本           | 聚合转化成本（CPA / ROAS）  |


**Q: 智能出价时代，二价计费（GSP）相比一价计费（GFP）的优劣势分别是什么？**

[§1.4.7.2](#1472-拍卖机制 gsp-vs-gfp) 从传统视角对比了 GSP 与 GFP。但在智能出价（oCPX）+ 统一混排（[§1.4.6.2](#1462-独立链路-vs-融合链路)）时代， GSP 的两个经典优势被削弱：① oCPX 下出价由平台 λ 算法生成（[§1.4.3.3](#1433-λ-调价系数)），广告主不直接控制出价， GSP"鼓励真实出价"失去作用对象；② 统一混排下压价 → eCPM 下降 → RankScore 下滑 → 拿量能力大幅下降，这种机制本身已替代 GSP 的防压价作用，不管 GSP 还是 GFP 都如此。


| 维度         | GSP（广义二价）                                  | GFP（广义一价）              |
| ---------- | ------------------------------------------ | ---------------------- |
| 智能出价下的激励意义 | 削弱——出价由平台 λ 生成，真实出价激励失去对象                  | 不受影响——一价无需激励机制         |
| 防压价能力      | 传统优势，但统一混排下两者差异缩小                          | 依赖统一混排天然抑制 + oCPX 平台控价 |
| 广告主成本感知    | 更友好（扣费 < 出价，且随竞争程度变化）                      | 较高（扣费 = 出价），可能抑制出价意愿   |
| 竞争不充分时的收入  | 损失，需 min_cap 兜底（[§1.4.7.4](#1474-底价与扣费边界)） | 无损失，出价即扣费              |
| 平台成本保障压力   | 较小（二价天然低于一价）                               | 较大（一价扣费更高，赔付风险增加）      |
| 系统复杂度      | 高（二价公式 + min/max cap + 下一名 RankScore）      | 低（出价即扣费）               |
| 业界趋势       | Google/Meta 在智能出价占比提升后逐步转向 GFP             | ←                      |


> **小结**：在智能出价 + 统一混排时代， GSP 的经典优势（激励真实出价、防压价）被显著削弱。GFP 凭借扣费逻辑的简洁性成为越来越有吸引力的选择，但 GSP 在广告主成本感知和平台赔付压力方面仍有优势，迁移决策需综合考虑业务阶段和广告主生态。业界演进路线： Google Ads 于 2019 年将搜索广告从 GSP 切换为 GFP； Meta Ads 同期跟进，对自动出价广告采用 GFP； Amazon Ads 于 2021 年转向 GFP；国内方面，字节跳动（巨量引擎）较早采用 GFP，百度凤巢和腾讯广告仍以 GSP 为主。

#### 1.4.7.6 反作弊与计费修正 / Anti-Fraud and Billing Correction




广告计费需要配合 **反作弊系统（Anti-Fraud System）** 过滤无效流量（Invalid Traffic, IVT），确保广告主只为真实有效的用户行为付费：

**实时过滤（Pre-Billing）：** 在计费前，基于点击模式、时间间隔、设备指纹、IP 特征等实时识别并过滤无效流量，被过滤的点击/曝光不触发扣费。

**事后修正（Post-Billing）：** 通过离线回溯分析，识别实时阶段未能捕获的漏网无效流量，对已扣费用进行退款。


| 维度   | 实时过滤（Pre-Billing）      | 事后修正（Post-Billing）      |
| ---- | ---------------------- | ----------------------- |
| 执行时机 | 计费前（毫秒级）               | 计费后（小时/天级）              |
| 检测方法 | 规则引擎 + 实时模型（点击频率、设备指纹） | 离线模型 + 大数据分析（行为序列、转化漏斗） |
| 处理结果 | 过滤无效点击，不触发扣费           | 识别无效扣费，执行退款             |
| 覆盖率  | 高（覆盖大部分简单作弊）           | 补充（捕获复杂/隐蔽作弊）           |


> 反作弊与计费修正的系统实现详见 Chapter 3 [§3.6](../03.ads-engine/06.ads-data.zh-CN.md#36-广告数据ads-data)（Ads Data）。
