## Introduction

`ads-db-lib` (imported as `adsdblib`) is the **shared Go library** used by all Paid Ads platform services to access the ads-DB layer. It provides a unified, type-safe, region-aware abstraction over the Shopee Ads databases (ads-DB), covering all ad-domain entities: accounts, campaigns, advertisements, keywords, creatives, billing, rebates, SRM, CRM, and booking.

Rather than having each consuming service write its own MySQL access code, they import `adsdblib` to obtain a pooled `DBManager` that handles connection lifecycle, sharding routing (via SDDL and Hardy), Config Center-driven dynamic reconfiguration, and Prometheus metrics export.

PICs: Chao, Yuhang, Zhining — under the Data Support team card of Advertiser Platform.

> Original README note: please review the implementation before fully replacing service-local DB access code with `adsdblib`. Minor human errors can still exist, so treat rollout as a migration that still needs verification.

## Features

- **Unified DB Access Layer** — single library imports for all ads-DB operations across 7 logical databases (Ads Core, SRM, Ads Marketing, Rebate, Booking, Buyer Segment, CRM).
- **Region-aware sharding** — all query methods accept a `region` string (`"SG"`, `"MY"`, `"ID"`, `"TH"`, `"PH"`, `"TW"`, `"VN"`, `"BR"`, `"MX"`, `"CO"`, `"CL"`, `"AR"`). Routing to the physical DB cluster is done automatically.
- **SDDL & Hardy integration** — transparent physical shard management via Shopee's SDDL (Shopee Distributed Database Layer) and the `goorm`/Hardy ORM.
- **Config Center-driven dynamic configuration** — DB credentials, shard split configuration, and downgrade routing are subscribed from Shopee Config Center at runtime and applied without service restart.
- **Client pool pattern** — each database client type (`AdsClient`, `SRMClient`, `AdsMarketingClient`, `RebateClient`, `BookingClient`, `CRMClient`, `BuyerSegmentClient`) is managed via `sync.Pool` to reduce allocation overhead.
- **Hot/cold audit table routing** — audit tables are split by month (and for high-volume regions by configurable thresholds). The library automatically selects the correct shard based on `ctime` range.
- **Prometheus metrics** — exposes `paidads_ads_db_manager_latency` (histogram) and `paidads_ads_db_manager_count` (counter) per country, query name, caller, DB name, and shard.
- **Generated mocks** — all client interfaces have corresponding `mocked_*.go` files generated by `script/mocked_generator.py`, enabling easy unit-test injection.
- **Bundled config files** — environment config YAML files (`live`, `liveish`, `stable`, `staging`, `uat`, `test`) are embedded in the binary via `pkger`.
- **ads-db-ss sidecar service** — an embedded SPEX service (`cmd/ads_db_ss/`) that allows services to call DB operations remotely via the `AdsdblibProcessor` interface, rather than directly embedding the library.
- **Redis-backed ID mapping** — `IDMappingClient` provides CampaignID→UserID, AdsID→UserID, and AdsID→CampaignID lookups via Redis, solving the `GetCampaignXXX` shard-scan problem without DB fan-out. Use `NewIDMappingClient(rdb)` to create an instance, and `NewRedisClientWithKMS` for KMS-authenticated Redis setup.
- **Auto Escrow Orders** — manages the full escrow order lifecycle (`AddAdsAutoEscrowOrder`, `UpdateAdsAutoEscrowOrder`, `GetAdsAutoEscrowOrders`, `ScanAdsAutoEscrowOrdersV2`, `ScanAdsAutoEscrowOrdersV3`) and aggregate escrow orders (`AddAdsAutoEscrowAggregateOrder`, `GetAdsAutoEscrowAggregateOrders`, `ScanAdsAutoEscrowAggregateOrdersV2`) via `auto_escrow.go` / `auto_escrow_v3.go`. Both order types support cursor-based pagination for time-range scans against sharded tables (`ads_auto_escrow_order_tab`, `ads_auto_escrow_aggregate_order_tab`). `ScanAdsAutoEscrowOrdersV3` uses a `BusinessFn` callback pattern for streaming parallel shard scans instead of returning a cursor slice.
- **Campaign Accelerator Packages** — manages campaign accelerator package definitions stored in the central (non-sharded) DB (`campaign_accelerator_package_tab`) and per-user package assignments stored in sharded tables (`campaign_accelerator_package_user_tab`) via `campaign_accelerator.go`. Includes `ScanCampaignAcceleratorPackageUsersV3` for sharded parallel scanning.

## Architecture

### Service Topology

`ads-db-lib` operates in two modes: as an **embedded Go library** imported directly by consuming services, and as an **ads-db-ss SPEX sidecar** that exposes a subset of DB operations over RPC to remote callers (e.g., Indexer).

```mermaid

    subgraph Upstream["Upstream Consumers"]
        UAS[ultimate_ads_service]
        AS[ads_service]
        STATUS[ads-status-syncer]
        RES[ads-resharder]
        MKTG[ads-marketing]
        ADMIN[paidadsbackendadmin]
        OTHER[ads-crm / ads-srm / uber-srm / auto-rebate / ...]
        IDX[Indexer / remote callers]
    end

    subgraph LIB["ads-db-lib"]
        CORE[adsdblib<br/>DBManager + Client pool<br/>AdsClient / SRMClient / ...]
        SIDECAR[ads-db-ss<br/>SPEX sidecar]
    end

    subgraph Downstream["Downstream Dependencies"]
        MYSQL[(MySQL sharded DB<br/>via SDDL / Hardy)]
        REDIS[(Redis<br/>IDMappingClient)]
        CC[Config Center<br/>adsdblib_{env}_{tag}_default]
    end

    UAS -- "Go import" --> CORE
    AS -- "Go import" --> CORE
    STATUS -- "Go import" --> CORE
    RES -- "Go import" --> CORE
    MKTG -- "Go import" --> CORE
    ADMIN -- "Go import" --> CORE
    OTHER -- "Go import" --> CORE
    IDX -- "SPEX RPC" --> SIDECAR
    CORE --> SIDECAR
    CORE -- "goorm/Hardy" --> MYSQL
    CORE -- "go-redis" --> REDIS
```

| Direction | Name | Protocol | Description |
|-----------|------|----------|-------------|
| Upstream | `ultimate_ads_service`, `ads_service`, and others | Go import | Direct consumers; initialize `DBManager` and use client pool |
| Upstream | Indexer and remote callers | SPEX RPC | Call `deep.paidads.platform.ads_db_ss` over SPEX without embedding the library |
| Downstream | MySQL sharded DB clusters | goorm/Hardy ORM | 7 logical DB domains (Ads Core, SRM, Marketing, Rebate, Booking, Buyer Segment, CRM) across 12 regions |
| Downstream | Redis | go-redis | `IDMappingClient`: resolves campaign/ad→user ID without full-shard scans |
| Downstream | Config Center | Subscription | Namespace `adsdblib_{env}_{tag}_default`; delivers ORM config, shard-split DSNs, downgrade routes, audit cold-hot thresholds |

## Consumers and Usage

### Known downstream services

Based on the Google Docs knowledge base and code references, services that import `adsdblib` include:

- `ultimate_ads_service` — the primary consumer; uses `AdsClient` for nearly all ads-DB reads/writes
- `ads_service` — legacy service; also a direct consumer
- `ads-status-syncer` — reads campaign and account status; uses `AdsClient`
- `ads-resharder` — reads and resharders DB data; accesses the library directly
- `auto-rebate` — uses `RebateClient`
- `ads-crm` — uses `CRMClient`
- `ads-srm` / `uber-srm` — uses `SRMClient`
- `ads-marketing` — uses `AdsMarketingClient`
- `paidadsbackendadmin` — uses `AdsClient` for admin queries
- `ads-db-ss` (embedded, see below) — SPEX sidecar exposing select DB operations over RPC to Indexer and other callers

The Indexer is being migrated from direct `adsdblib` import to calling `ads-db-ss` SPEX interfaces, as listed in the knowledge base.

### Normal usage

If you do not need additional customization or service-specific raw queries, initialize a `DBManager`, get the required client, use it, and return it to the pool.

```go
import adsdblib "git.garena.com/shopee/deep/ads-db-lib"
import adsdblibConfig "git.garena.com/shopee/deep/ads-db-lib/config"

dbMgr, dispose, err := adsdblib.NewDBManagerV2WithConfigCenter(ctx,
    adsdblib.ManagerV2WithConfigCenterConfig{
        ConfigCenterClient: configCenterClient,
        ConfigCenterSecret: "your-secret",
        Option: adsdblibConfig.DBOption{
            DBSelector: adsdblibConfig.DBSelector{Ads: true},
            Conf:       adsdblibConfig.DBConfig{Parallelism: 16},
            Env:        "live",
        },
    },
    adsdblib.WithServiceName("your-service-name"),
)
if err != nil {
    return err
}
defer dispose()

// get + use + return client
cli, err := dbMgr.GetAdsClient()
if err != nil {
    return err
}
defer dbMgr.PutAdsClient(cli)

campaign, err := cli.GetCampaign(campaignID, userID, "SG")
```

### DBSelector — selectively enable client pools

`DBSelector` controls which client pools are initialised. Set only what your service needs to avoid unnecessary connections:

```go
DBSelector: adsdblibConfig.DBSelector{
    All:          false, // enables all of the below
    Ads:          true,
    SRM:          false,
    AdsMarketing: false,
    Rebate:       false,
    Booking:      false,
    CRM:          false,
    BuyerSegment:   false,
    IDGenerator:    true,  // requires Ads = true
    IDMappingCache: true,  // requires Ads = true; enables Redis-backed shard-key cache
}
```

### ORM config overrides

```go
// override timeout for all DBs
Conf: adsdblibConfig.DBConfig{
    ORMCommon: &adsdblibConfig.ORMConfig{Timeout: 5 * time.Second},
}

// override timeout for a specific DB only
Conf: adsdblibConfig.DBConfig{
    ORM: []adsdblibConfig.ORMConfig{{DBName: "shopee_ads_sg_db", Timeout: 5 * time.Second}},
}
```

The merge priority is: `Lib ORMCommon < UserDefined ORMCommon < Lib ORM < UserDefined ORM`.

If the bundled config already fits your use case, you can leave `ORMCommon` and `ORM` nil. Empty values inherit from the library defaults rather than overriding them.

### ID mapping via Redis

`IDMappingClient` resolves shard keys without scanning all DB shards:

```go
import adsdblib "git.garena.com/shopee/deep/ads-db-lib"

// Create a KMS-authenticated Redis client
rdb, err := adsdblib.NewRedisClientWithKMS(ctx, adsdblib.RedisConfig{
    Addr:           "redis-host:6379",
    UserKMSKey:     "kms-key-for-redis-user",
    PasswordKMSKey: "kms-key-for-redis-password",
})
if err != nil {
    return err
}
defer rdb.Close()

idMapper := adsdblib.NewIDMappingClient(rdb)

// Look up UserID from CampaignID — avoids full-shard scan
userID, err := idMapper.GetUserIDByCampaignID(ctx, campaignID, "SG")

// Batch lookups are also supported
userIDs, err := idMapper.BatchGetUserIDByCampaignIDs(ctx, campaignIDs, "SG")
```

Redis key formats (for reference):
- `ads:{region}:campaign_user:{campaignID}` — CampaignID → UserID
- `ads:{region}:ads_user:{adsID}` — AdsID → UserID
- `ads:{region}:ads_campaign:{adsID}` — AdsID → CampaignID

### Custom queries

If your query does not exist in the library, implement it in your own service using the raw `*goorm.Orm` that can be extracted from the client via `cli.GetROrm(region)`, `cli.GetWOrm(region)`, etc. Reusable queries should still be added back into `ads-db-lib`; service-local implementations are best reserved for logic that is too specific to generalise. See `example/config_center/` for a concrete example.

### Using mocks in tests

```go
import "git.garena.com/shopee/deep/ads-db-lib"

var mockCli adsdblib.AdsClient = &adsdblib.MockedAdsClient{
    GetCampaignFunc: func(campaignID, userID int64, region string) (*Campaign, error) {
        return &Campaign{CampaignID: campaignID}, nil
    },
}
```

To regenerate mocks after adding interface methods, run `make gen-mock`. This target requires `goimports`:

```bash
go install golang.org/x/tools/cmd/goimports@latest
```

## Development Guidelines

### Code Style

- Follow standard Go conventions (`gofmt`, `go vet`).
- Run `make fmt` and `make vet` before committing. `make ci` (runs vet + fmt + test + validate-hardy-convertors) mirrors the GitLab CI pipeline.
- **Naming conventions for query methods:**
  - `Add*` — `INSERT`, errors on duplicate; returns `(id int64, err error)`.
  - `Add*Batch` — batched INSERT; returns `(affectRows int64, err error)`.
  - `Audit*` — audit-log `INSERT`; returns `(id int64, err error)`.
  - `Set*` — deprecated; `INSERT OR UPDATE` (use `Add` + `Update` instead).
  - `Update*` — `UPDATE` by primary/unique key; returns `(affectRows int64, err error)`.
  - `Get*` — `SELECT` by primary key; returns a single concrete proto struct.
  - `GetX*` — `SELECT … FOR UPDATE` (exclusive lock) variant of `Get*`.
  - `Get*s` — `SELECT … WHERE` with a param struct; returns a slice.
  - `GetX*s` — `SELECT … FOR UPDATE` variant of `Get*s`.
  - `Load*s` — full-table scan without WHERE; returns a slice.
  - `Check*` — existence check; returns `(exist bool, err error)`.
  - `Count*` — `SELECT COUNT()`; returns `(totalCount int64, err error)`.
- Always override `Ctime`/`Mtime` with current time in write operations (exception: `ColdStartAds` uses `CreateTime`/`UpdateTime`; Archive DB tables skip the override).
- **Scan params with status filtering** — `CampaignScanParam` now supports a `Statuses []int32` field so callers can filter by campaign status in shard scans without post-filtering.
- **Shard routing helpers** — `CampaignsParam.ShardHintIndexes()` and `AdsParam.ShardHintIndexes()` compute DB and table index pairs from shard keys for Hardy's routing-only read path. `AdsParam.RouteShardKeys()` resolves routing-level user/campaign IDs from `PrimaryKeys`, `CampaignUserKeys`, or plain `UserIDs`/`CampaignIDs` fields.
- **`TranslogsByDateParam`** — a companion to `TranslogsParam` that accepts a single `Timestamp` used only for table-suffix routing (not injected into WHERE). Adds `MinID` for cursor-based pagination, `ExcludeSellerUserIDInQuery` to optionally suppress the `acc_user_id` filter, and `DeductUniqueID` to filter by a specific deduction event ID.
- Do **not** add new database-specific logic directly in consuming services; propose a new method in `ads-db-lib` instead.

#### Query group quick reference

The original README grouped query APIs by naming pattern. The reference below preserves that guidance, with examples updated to current method signatures.

| Group | Semantics | Current example |
|------|-----------|-----------------|
| `Add*` | `orm.Add()` / `INSERT` with duplicate error; usually returns `(id int64, err error)` | `AddAdvertisement(advertisement *bsads.Advertisement, region string) (id int64, err error)` |
| `Add*Batch` | batched `orm.Add()`; returns `(affectRows int64, err error)`; `affectRows` can be non-zero even when `err != nil` because some batches may already have succeeded; requires `batchSize` | `AddSegmentWBLActionEntryBatch(entries []*pblib.SegmentWhiteBlacklistActionEntry, actionID int64, batchSize int, region string) (affectRows int64, err error)` |
| `Audit*` | `orm.Add()` for audit data, where the input is an audit param struct instead of the final DB model | `AuditAdvertisementV2(param AuditAdvertisementV2Param) (id int64, err error)` |
| `Set*` | deprecated `orm.Set()` style `INSERT if not exists else UPDATE`; prefer `Add*` + `Update*` | `SetAdvertisement(advertisement *bsads.Advertisement, region string) (id int64, err error)` |
| `Update*` | `orm.Update()` / `UPDATE` keyed by primary, secondary, or unique key; usually returns `(affectRows int64, err error)` | `UpdateAdvertisement(advertisement *bsads.Advertisement, region string) (affectRows int64, err error)` |
| `Get*` | `orm.Get()` / `SELECT` by primary key; arguments usually include the primary key, split key when needed, and `region` | `GetAdvertisement(adsID int64, campaignID int64, userID int64, region string, opts ...GetOption) (advertisement *bsads.Advertisement, err error)` |
| `GetX*` | `orm.GetX()` / `SELECT ... FOR UPDATE`; same usage pattern as `Get*`, but with locking | `GetXAdvertisement(userID int64, adsID int64, campaignID int64, region string) (advertisement *bsads.Advertisement, err error)` |
| `Get*s` | `orm.ReadRaw()` / `SELECT` with `WHERE` driven by a param struct; usually returns a slice | `GetAdvertisements(param AdsParam, opts ...GetOption) (advertisements []*bsads.Advertisement, err error)` |
| `GetX*s` | locked `orm.ReadRaw()` / `SELECT ... FOR UPDATE` version of `Get*s` | `GetXTargetAdsBuyerSegmentTypes(region string, param BuyerSegmentTypeByRegionParam) (segmentTypes []*pblib.TargetAdsBuyerSegmentTypeByRegionDBModel, err error)` |
| `Load*s` | `orm.ReadRaw()` without a `WHERE` clause; usually returns a full slice and may accept `LimitParam` or `SortParam` in related APIs | `LoadCampaigns(region string) (campaigns []*bsads.Campaign, err error)` |
| `Check*` | existence check; returns `(exist bool, err error)` | `CheckAdvertisement(adsID int64, campaignID int64, region string) (exist bool, err error)` |
| `Count*` | `orm.Count()` / `SELECT COUNT()` | `CountSegmentWBLModels(param SegmentWBLModelsParam) (totalCount int64, err error)` |

### Versioning

- `ads-db-lib` is versioned as a Go module at `git.garena.com/shopee/deep/ads-db-lib`.
- Downstream services pin to a specific tag or commit SHA in their `go.mod`.
- Breaking interface changes (adding required parameters to existing methods) must be coordinated with all known consumers **before** merging.
- Prefer adding new `*WithCtx` variants of existing methods rather than changing existing method signatures.
- After every interface change, regenerate mocks: `make gen-mock` (requires `goimports`).
- After every config file change, regenerate the embedded binary: `make gen-config` (requires `pkger`).
- After every proto change, regenerate protobuf: `make proto-compile` (requires `spcli`).

### Unit Testing Standards

- Run tests: `make test` (verbose) or `make test-nv` (without verbose).
- Use the generated `mocked_*.go` files (`MockedAdsClient`, `MockedSRMClient`, etc.) for unit tests — do not call real DB in unit tests.
- Test files colocate with the implementation files (`*_test.go`).
- The `example/config_center/` directory contains integration-style examples; do not treat them as unit tests.

### Code Review & Git Workflow

- Commit message format: `(Feat|Fix|Docs|Style|Refactor|Test|Chore): [JIRA-ID] description`
- Branch naming: `dev/$username` or `feature/$feature_name`
- All changes go through Merge Requests (squash commits, delete source branch after merge).
- Library changes that affect downstream services should only merge after the consuming service has been tested or after coordinating the upgrade path.

| `liveish.yml` | Shadow production (stress-test, DB migration) |

If `pkger` is not installed yet, install it first:

```bash
go install github.com/markbates/pkger/cmd/pkger@latest
```

### Config Center integration

The library subscribes to the Shopee Config Center namespace `adsdblib_{env}_{tag}_default` (live currently uses `adsdblib_live_temp_default`) for:

- `ORMGroup` — ORM connection configs and SDDL-supported DB list.
- `AdsDBSplit` — central/shard split DSN mapping per region (drives `RegionAdsDSN` → `SplitDSN`).
- `SbmDowngrade` — shadow DB routing (original → destination DB downgrade/migration path).
- `AuditColdHotThreshold` — per-region configurable threshold (in months) for hot/cold audit table selection.

### SPEX and spcli Setup

- SPEX service name: `deep.paidads.platform.ads_db_ss`

### Upgrading downstream services

2. In each downstream service, bump the dependency:
   ```bash
   go get git.garena.com/shopee/deep/ads-db-lib@v1.x.y
   go mod tidy
   ```
3. If the interface changed (new methods added), regenerate mocks in the downstream service if it re-exposes the interface.
4. Re-run tests in downstream services before deploying.
5. For breaking changes (rare), coordinate with all teams consuming the library **before** tagging.

## Frequently Asked Questions

**Q1. How do I add a new DB query to the library?**
Implement the method on the appropriate concrete client type (e.g., `adsClient` in `ads.go`) and add the method signature to the matching interface in `ads_client_interface.go`. Then run `make gen-mock` to regenerate mocks.

**Q2. How do I avoid accidentally scanning too many shard tables?**
Always pass the split key (`userid`, `campaignid`, `shopid`, etc.) in your query params. The `SplitParam` in query structs drives the shard selection. If only a non-shard ID is available (e.g., only `campaignid` with no `userid`), use the `IDMappingClient` to resolve the UserID from Redis via `GetUserIDByCampaignID` — this avoids the full-shard scan. Initialize `IDMappingClient` with `NewIDMappingClient(rdb)` and `NewRedisClientWithKMS` for Redis creation (see `id_mapping.go` and `redis_client.go`).

**Q3. When do I use `GetX*` (exclusive lock) vs `Get*`?**
Use `GetX*` only when you need to update the row in the same transaction immediately after reading it (optimistic/pessimistic locking). For read-only queries always use `Get*` to avoid unnecessary lock contention.

**Q4. What is the difference between `live` and `liveish` environments?**
`live` is the production environment with real regional DBs. `liveish` is a shadow environment used for stress testing and DB migration; it routes to a synthetic `XX` region DB (`shopee_ads_xx_shard_db_00000000`). Clients in `liveish` + `delta` tag skip all non-XX regions.

**Q5. How are audit tables routed to the correct monthly shard?**
The `hot_cold_util.go` helper extracts the `ctime` range from the query condition, computes the `YYYYMM` suffix, and selects only table shards within the hot window (configurable per-region via Config Center `AuditColdHotThreshold`). Archive queries spanning beyond the hot window must go to cold storage.

**Q6. How do I update embedded config files?**
Edit the appropriate `config/files/*.yml` file, then run `make gen-config` (requires `pkger` installed: `go get github.com/markbates/pkger/cmd/pkger`). This regenerates `pkged.go`, which must also be committed.

**Q7. How does the downgrade routing (sbm_downgrade) work?**
The Config Center publishes a `SbmDowngrade` config mapping original DB names to destination DB names. When a double-write or read-from-destination flag is set, `sbm_downgrade.go` transparently redirects ORM calls to the destination (e.g., during a DB split migration).

**Q8. How do I run the ads-db-ss sidecar locally?**
Build: `make ads_db_ss`. Run with a config pointing to your test Config Center credentials. The service listens on an HTTP port (for `/ping`, `/metrics`, `/debug/pprof`) and registers to SPEX for RPC.

**Q9. Where do I add new table constants?**
In `const.go`, following the existing naming convention: `<Entity>Table = "<physical_table_name_%08d>"` for sharded tables, or just the table name string for non-sharded tables.

**Q10. I added a new interface method — what else do I need to update?**
(1) Add method to the interface in `ads_client_interface.go`. (2) Implement the method on the concrete type. (3) Run `make gen-mock` to regenerate `mocked_*.go`. (4) Bump the library version tag. (5) Notify downstream teams to upgrade.
