# ROI3 分析框架设计/ROI3 Analysis Framework Design

> **Contributors**: roger.li ｜ **最后更新**：2026-06-13 ｜ [GitLab](https://git.garena.com/shopee/search_recommend/ai-copilot/ads-workspace/-/blob/master/skills/team/04.product-algo/ads-roi3-analysis/references/framework-design.md)

本文是 ROI3 数据分析 skill 体系（总-分结构）的设计蓝本。第一阶段讨论的全部结论沉淀于此；后续所有 hub / spoke skill 的实现以本文为准，迭代时改本文再改实现。

## 0. 一句话定位/Positioning

一个**总-分结构**的 ROI3 分析工具体系：总（hub）负责把模糊的分析诉求引导成一张明确的分析计划卡，分（spoke）按计划卡执行并产出统一骨架的报告；每次分析沉淀方法与定律，让下一次引导更聪明。

## 1. 第一性原理/First Principles

### 1.1 分析为决策服务/Analysis Buys Information for Decisions

分析存在的唯一理由是改变决策。每次分析的本质 = 花成本（时间/算力/机会）购买信息，以降低某个决策的不确定性。由此推出三条判据，贯穿全流程：

| 判据 | 问法 | 用在哪 |
|---|---|---|
| 立项判据 | 这个分析改变什么决策？答案不同会导致不同动作吗？ | 计划卡第一个字段；答不出就不立项 |
| 排序判据 | 哪个证据"对决策影响大 × 获取便宜"？ | 父问题分解后剪枝，先做关键少数（80/20） |
| 停止判据 | 不确定性是否已低于决策所需精度？ | 防止追求完美读数；够用即停 |

### 1.2 ROI3 系统的本质/The System Being Analyzed

剥掉所有工具和表，ROI3 域只有三样东西：

- **一个目标函数**：利润 ≈ 价值 − 成本（guardrail 公式 `gmv_uplift/4 + advv_uplift − cost_uplift` 是其当前形态；口径选择本身是分析的一部分）。
- **四类杠杆**：发多少（预算/强度系数）、发给谁（人群/商品/时段/区域）、怎么发（券型/面额/机制）、怎么控（pacing/校准/gating）。
- **一个响应系统**：杠杆经过"模型 + 调控 + 市场"作用到指标，响应有形状——单调性、边际递减、饱和、滞后、噪声。

一切分析都是在弄清"杠杆 → 响应"这张映射的某个局部，弄清到足以做决策的程度。

### 1.3 决策闭环：六类问题/The Decision Loop: Six Question Types

六类分析问题不是平行清单，而是决策闭环上的六个站点，环环相扣：

```
校验 → 读数 → 诊断 → 探索 → 评估 → 决策 ─┐
 ↑（数据可信吗）（现在在哪）（为什么）（杠杆怎么响应）（动了有效吗）（调到哪）
 └──────────────────────────────────────────┘
```

| 类型 | 回答的问题 | 典型例子 |
|---|---|---|
| 校验 | 数据/口径/两侧对得上吗，可信吗 | 预估 vs 后验、控制器记录 vs 真实消耗、跨表口径对账、实验分流比例检查（SRM） |
| 读数 | 现状/趋势是什么 | 日报、实验读数、漏斗、达成进度 |
| 诊断 | 为什么是这样/为什么异常 | coverage 掉了、guardrail 没涨、四层证据归因 |
| 探索 | X 和 Y 什么关系 | 强度-成本弹性、响应曲线、单调性、饱和点 |
| 评估 | 这个动作有没有效/谁更优（含对比） | 实验效果、MP vs Ads 券效率、该不该全量 |
| 决策 | 该调到哪/怎么分 | 系数寻优、分时段调控、预算分配 |

闭环顺序自带纪律：**诊断前先校验**（BR 读数低先查数据残缺，再谈策略问题）；**决策前先评估或探索**（没有响应曲线就定系数是拍脑袋）。老板级问题（"赚不赚""值不值"）= 闭环健康度，由合成层回答（见 2）。

### 1.4 知识 = 方法 + 定律/Knowledge = Methods + Laws

分析产出三种东西，复用规则截然不同：

- **方法**（SQL 口径、取证路径、字段映射、检验手段）——可复用，沉淀的主体。
- **定律**（对系统的稳定信念，带置信度/适用范围/最后验证时间）——可复用但须定期重验，进定律台账（见 6）。
- **数字**（某时间窗的读数）——不可复用，只能作带时间戳的快照示例。

## 2. 分层架构/Architecture

```
事实层(第0层)  机制/口径/链路澄清 → ads-knowledge-qa + roi3 FAQ/playbook（双向路由：
              KB 拒收的"研究分析任务"流入本框架；本框架的事实问题流出到 KB）
   ↓
分解层        老板/PM 父问题 → 合成格子 → 子格子清单（对决策影响大、取数便宜的先做）
   ↓
执行层        五轴定位 → 路由矩阵 → spoke 执行（成熟度三档：手工 / playbook / skill）
   ↓
合成层        子结论按合成规则向上聚合；矛盾时报矛盾，不硬合
   ↓
输出层        同一分析按受众出版本：全量版 / 决策版 / 老板三句话版
   ⟲
飞轮          收尾沉淀：方法（强制）+ 定律（强制）+ 报告归档；喂给下一次 初始假设
```

## 3. 五轴与路由矩阵/Five Axes & Routing Matrix

### 3.1 五轴定义/Axis Definitions

一次分析 = 五轴各取一值。路由主要看 ①×②；诊断/校验类再加 ③；④⑤是传给 spoke 的参数。杠杆和链路层分开，是因为它们回答不同的问题——杠杆是"决策要动什么"，链路层是"证据去哪个环节找"。

| 轴 | 取值 | 备注 |
|---|---|---|
| ① 问题类型 | 校验/读数/诊断/探索/评估/决策 | 见 1.3；"对比"并入评估 |
| ② 决策杠杆 | 发多少（预算、发券强度）/ 发给谁（选券、人群商品策略）/ 怎么发（券型、面额、机制）/ 怎么控（控制器、投放节奏） | 与 1.2 的四类杠杆一一对应；探索/评估/决策类必填 |
| ③ 链路层 | 效果指标层（券成本、advv、GMV、guardrail、券效率）/ 控制器层 / 模型层（预估与校准）/ 策略层（选券逻辑）/ 数据口径层 | 诊断/校验类必填，其余默认效果指标层 |
| ④ 切分维度 | region/时段/人群/商品·品类/价格带/渠道/漏斗节点 | 可多选 |
| ⑤ 证据来源 | AB 实验/观测对比（差分法 DiD、共同商品控制）/线上 trace/模型外推 | 默认规则：有实验用实验；外推仅限标定区（见"深档饱和"定律） |

各轴取值一律用通俗说法，不用内部代号；系统术语对照放 hub 名词速查，熟手可直打术语。

### 3.2 路由矩阵 v1/Routing Matrix v1

矩阵 = 框架的核心活资产，落地为机器可读的 `routing-matrix.yaml`（schema 见 4.2）。每格标成熟度三档：**skill**（成熟技能，全自动）/ **playbook**（方法论已文档化，半自动）/ **手工**（hub 引导 + ads-text2da 跑数 + 报告骨架）。不用字母编号表示成熟度——ROI3 语境里 L 系编号已被类目层级和既有分析框架占用，必混。

| 格子（类型 × 杠杆/链路层） | 现有承接 | 成熟度 |
|---|---|---|
| 读数 × 效果指标层 | ads-roi3-monitoring-report（日报/趋势）、ads-roi3-weekly-sync（周报） | skill |
| 读数 × 发多少 | 预算转移实验读数（口径快照现存会话记忆，落地后以 data-sources.md 为准） | playbook |
| 诊断 × 全链路 | ads-roi3-rootcause-diagnosis、ads-roi3-diagnosis-v2（默认 v2） | skill |
| 诊断 × 控制器层 | ads-roi3-budget-control-analysis（控制器 trace 证据） | skill |
| 评估 × 实验 | **ads-roi3-experiment-analysis（v1 样板 spoke）**；格式参考 ads-rollout-generate | skill |
| 评估·探索 × 发给谁（维度边际利润率） | **ads-roi3-profitability-analysis（新建 spoke）**：利润率/边际利润率/维度分解/动作落地验证；方法源自 kr3-kp6 边际报告 + kr3-kp9 维度重塑 | skill（目标） |
| 评估 × 券效率 | playbook：[voucher-efficiency-mp-vs-ads-2026-06-10.md](../../../../../docs/personal/roger.li/roi3/analysis/voucher-efficiency-mp-vs-ads-2026-06-10.md) 的五维+因果方法 | playbook |
| 探索 × 发多少 | playbook：发券强度边际利润率报告（kr3-kp6）的方法（响应曲线/边际/稳定性） | playbook |
| 探索·评估 × 人群/商品切 | playbook：切片异质性方法（guardrail 分品类/价格带/性别） | playbook |
| 校验 × 数据口径层（对账各层） | playbook：roi3_definition_consistency_audit + questions.md 中 6 题对齐类 | 手工→playbook |
| 决策 × 发多少 | playbook：强度系数调整交付（coef_arrays_v1）+ 预算转移目标推算方法 | playbook |
| 合成：赚不赚/值不值/扩不扩 | 子格子组合 + 合成规则（冲突分类见 4.2）；产物级先例：monitoring 日报、weekly-sync、ads-roi3-epic-report | playbook |
| 兜底（任意格） | ads-text2da + 报告骨架 | 手工 |

## 4. 三契约/Three Contracts

契约固定，spoke 并行迭代互不影响。三者均带 `version` 字段。

### 4.1 分析计划卡/Analysis Plan Card

hub 的唯一输出、所有 spoke 的统一输入。字段分两档，按流程分级启用（见 5.1）：

**核心字段（所有流程必填）**

| 字段 | 说明 |
|---|---|
| decision | 这个分析改变什么决策（立项判据；答不出→不立项或降为事实澄清） |
| question + 五轴 | 一句话问题 + ①–⑤ 取值（③链路层可由类型默认推断） |
| scope | 时间窗/region/实验桶（exp_tag↔bucket 映射须显式写出） |
| caliber | value 口径（advv/broad_gmv/platform_gmv/guardrail）强制确认，多口径并行时分别给结论 |
| audience + output | 受众（自己/PM/老板）→ 报告版本；归档路径 |

**完整流程附加字段（探索/决策类启用）**

| 字段 | 说明 |
|---|---|
| hypothesis | 初始假设（从定律台账+历史沉淀自动起草）+ 反证条件：什么数据会推翻它 |
| facts-base | 事实底座：本次依赖的机制/口径事实，已确认 vs 待验证；取证刷新协议四步（KB→AB 配置→代码→最新数据） |
| sub-analyses | 父问题的子格子清单 + 优先级排序（对决策影响大、取数便宜的先做） |
| checkpoints | 中期读数节点（长分析必设） |

### 4.2 路由注册表/Routing Registry

落地为 `routing-matrix.yaml`，hub 只读注册表路由、不靠现场理解文档。每个能力一条，字段：

- `id` / `match`（类型 × 杠杆/链路层）/ `maturity`（手工/playbook/skill）/ `entrypoint`（skill 名或 playbook 路径）/ `owner`
- `required_inputs`（缺什么引导补什么）/ `preflight_checks`（前置自检：表就绪、口径已确认、实验桶映射存在）
- `output_contract`（产出物与归档路径）/ `known_failures`（已知坑：查询超时、表落库滞后 ~2h、SG 无数据等）/ `freshness_rule`（数据多旧算过期）

合成格子额外声明：子格子清单、合成函数、冲突处理。冲突必须分类显式处理，至少五类：**口径冲突**（advv 与 broad_gmv/platform_gmv 结论反向）、**证据层冲突**（品类 guardrail 法与边际利润法方向相反）、**新鲜度冲突**（两侧数据时间窗不一致）、**因果/关联冲突**（关联读数与因果估计相左）、**叠加效应冲突**（多维系数直接相乘导致重复抑制）。处理原则：报冲突 + 给口径前提，不硬合。**新增能力 = 加一行 yaml，hub 逻辑零改动。**

### 4.3 报告骨架/Report Skeleton

所有 spoke 输出遵循**总-分-附录**三段式。权威范本：[voucher-efficiency-mp-vs-ads-2026-06-10.md](../../../../../docs/personal/roger.li/roi3/analysis/voucher-efficiency-mp-vs-ads-2026-06-10.md)（结论速览一张表 + 三问直答 → 明细分析 → 附录 A–E）。

**总**
1. **结论速览**——整体信息 + 可直接拿走的结论，优先用表格；数字打头、方向判断、so-what；关键问题逐条直答（老板版只到这层）
2. **名词速查**——自创名词、非通用术语、内部代号集中解释（范本：发券强度边际报告的 15 词速查表）；正文不得裸用未解释的自创词和代号（如 KA/KP 编号）

**分**
3. **数据检验**——实验分流比例（SRM）、数据完整性、口径自检（校验不过，后文结论降级为"待定"）
4. **分层论证**——具体分析过程，金字塔展开；**故事线先行**：先用假设占位写故事线，数据逐格填充、证实或证伪

**附录**
5. **口径与局限**——多口径差异显式列出
6. **可复现附录**——中间数据、分析 SQL 清单、数据源、复跑入口，方便后人追溯

**硬规则（写作三约束 + 沉淀纪律）**：

- **无验证不结论**：每个结论必须有经过验证的确切数据支撑；未验证的判断只能标注"假设/待验证"，不得混入结论区。
- **通俗语言**：读者多、角色杂（算法/PM/老板），降低解释成本的唯一办法是写得通俗——几个角色读完都能立刻明白；专业术语带一句白话解释，自创术语必须进名词速查。
- **结论三分类**：每个结论标注类型（**实现事实/数据 snapshot/设计推断**）；snapshot 必须带时间窗。
- **指标分三层**：基础（advv/cost/gmv/rev，有波动）/ 效率（利润率=value/cost−1，抗波动）/ 边际（边际利润率=Δvalue/Δcost−1，决策真凭据）。**判断实验是否生效优先看边际>效率>基础**——基础指标波动大，绝对值对比易被噪声带偏。指标套餐按问题类型带默认（删减须说明），详见 hub `references/report-skeleton.md`。
- **施策类实验评估范式**（可迁移模板，适用任何"按维度施加差异化策略"——调系数/预算/强度，维度=region/entrance/品类/人群/价格带/时段）：**Step0 系数复合关系确认**（线上目标量常是多实验系数连乘/复合，先问清本实验是哪一层、和谁复合、是否正交——前置硬步骤；红利：正交叠加的 dose 实验可在本实验桶内切片实测"调整后工作点"边际）①落地验证（动作-响应闭环，没落地止步）②效率/边际读数 ③维度分解（边际×份额×CI）④合成判断（注意多维叠加重复抑制）。**提升类 vs 打平/趋同类**：提升类看均值上移 diff；打平类看维度间边际离散度是否下降+是否趋近共同 λ，且"调整后边际"需 dose 才能测（连乘红利或新基线叠 dose）；若响应近线性 b≈0，打平靠一阶移预算而非二阶边际趋同。详见 report-skeleton.md。

## 5. 流程与节奏/Process & Cadence

### 5.1 三级流程/Right-sized Tracks

| 流程 | 适用 | 步骤 |
|---|---|---|
| 快速 | 读数/校验 | 预填计划卡核心字段 → 一次确认 → 执行 → 报告 |
| 标准 | 评估/诊断 | + 事实底座 + 口径多选确认 → 执行 → 报告 + 沉淀 |
| 完整 | 探索/决策/合成 | + 初始假设与反证 + 子分析优先级剪枝 + 中期读数节点 → 终版 + 沉淀 |

### 5.2 三个交付节点/Three Checkpoints

借鉴咨询项目节奏：**kickoff**（计划卡确认，唯一的整体确认点）→ **interim**（方向性中读，长分析必有；结论形成即同步，不憋大招）→ **final**（终版报告 + 沉淀动作）。快速流程 kickoff 与 final 合并。

### 5.3 交互设计/Interaction Design

**三种入口，殊途同归到一张计划卡：**

| 入口 | 用户怎么说 | hub 怎么接 |
|---|---|---|
| 引导式（默认） | "帮我分析下 MY 实验怎么样"（模糊表达） | 复述理解 → 预填五轴+口径 → 一张计划卡一次确认 |
| 直通式（熟手） | `/ads-roi3-analysis 评估 发多少 roi3_exp_v1 MY 近7天 broad_gmv` | 参数直接填卡，只确认缺失项 |
| 场景词（高频） | "实验 readout""日报""边际还有空间吗" | 直接命中矩阵格子，跳过轴选择 |

**提问预算（硬约束）**：快速流程 ≤1 次确认，标准 ≤2 次，完整 ≤3 次。原则是"预填让用户改"而不是"逐项盘问"——预填来源：用户原话 + 定律台账 + 历史计划卡。超预算的问题写进计划卡标"待定"，执行中按需再补。

**菜单怎么出**：选项从路由矩阵动态生成，每项标三件事——成熟度（全自动/半自动/手工）、预计耗时（分钟级/小时级）、产出物（日报/诊断报告/响应曲线）。用户选之前就知道按下去会发生什么。

**计划卡 = 唯一整体确认点**：一屏表格（决策、问题、五轴、scope、口径、输出、预计耗时）。确认后执行不再追问；中途改需求（"换成 TH"）= 改卡重跑受影响的步骤，不从头引导。

**执行中**：完整流程在中期读数节点回贴方向性结论（一句话+关键数字），用户可就地纠偏；长查询结果落盘 `tmp/`，会话断了凭计划卡续跑（"继续上次分析"）。

**收尾**：结论速览直接贴在会话里（不是只给文件路径），报告全文落归档路径；末尾一句话完成沉淀提示（"方法已记入 xx 格子""该格子第 2 次手工，建议升级为 playbook，要吗？"），不打断主流程。

**路由透明**：分发到 spoke 前说一句"接下来用 xx skill 跑 xx"（符合 workspace 的 skill 确认规范）；spoke 失败按 known_failures 给降级方案（换 playbook 或手工兜底），不静默换路径。

## 6. 定律台账/Belief Ledger

对系统的稳定信念，每条带：陈述、**性质（耐久/快照）**、证据路径、置信度、适用范围、检验方法、**失效条件**、最后验证时间。**是初始假设的弹药库，也是必须定期重验的对象——hub 引用任何快照性质的条目做初始假设前，必须先核对失效条件，过期先重验。** 引用定律一律用名字、不用编号（避免与类目层级等 L 系编号混淆）。**已拆出独立维护：`laws.md`（每条带证据路径/失效条件/最后验证，供 hub/spoke 程序化引用）；下表为摘要：**

| 定律 | 陈述 | 性质·失效条件 | 适用范围/检验 |
|---|---|---|---|
| 深档饱和 | 幂律外推仅标定区（coef 0.85–1.15）可信，深档系统性高估（MY 档2 高估 9 倍为 2026-06 快照数字） | 耐久（现象）；模型重训/标定区扩大后重验 | 深档只认实测闭环；TH 为反例（未饱和） |
| 口径决定结论 | advv 与 broad_gmv 口径下边际利润率方向相反 | 耐久；口径有统一决议后失效 | 高风险决策须多口径并行 |
| 噪声下限 | 单日读数不可判（日内漂移大），满日累计为准绳，trailing 窗 ≥14 天收敛 | 耐久（统计性质）；流量结构大变后重验 | CV/bootstrap 检验 |
| 选择≠因果 | 高关联 GMV ≠ 撬动；广告券 $1 仅换 ~$0.6 增量 GMV（快照数字） | 耐久（机制）；数字逐季重验 | 同人群随机对照/差分法 DiD |
| 边际递减 | advv 对强度近平（±15% coef → ±1–2% advv），成本对强度陡（−10% coef → +25–60% cost） | **快照**（2026-06 响应曲线）；系数大调/大促季后失效 | 发券强度响应曲线报告（kr3-kp6） |
| 高频坑 | 发券≠领券；下发/发券/领券/核销是四个节点不能混；平台券体系≠ROI3 在线分支；seller_voucher 金额包含 ads_voucher（口径不互斥） | 耐久（机制事实）；链路改造后重验 | 漏斗分析/跨口径对比时强制自检 |

## 7. 沉淀飞轮/Flywheel

- **每次分析收尾**：方法沉淀（强制）——SQL 口径/取证路径/检验手段进对应 playbook 或矩阵格子；定律更新（强制）——新发现/被推翻的信念进台账；报告归档+矩阵格子标记（自动）。
- **不沉淀数字**：数值只作带时间窗的快照示例（KB FAQ 已验证此纪律）。
- **升级触发**：同一格子手工走过 2 次 → hub 主动提议升级：手工→playbook（沉淀方法论文档）或 playbook→skill（脚本化为 spoke）。
- **scope 升级**：personal → team → common，按工作区既有路径。

## 8. 边界/Boundaries

**ROI3 单域定义**（Round 2 压测收敛出的核心边界）：本体系做【**订单/桶级聚合 × 短期 7-14 天 × 发券→交易的 AB+DiD 因果**】。超出这三条任一的，不塞进 ROI3（会越界、ROI 低），而是**主动识别 → 诚实说不 → 指路**（见 routing-matrix 的 `out-of-scope-sentinel`）。

| 不做 | 去哪 |
|---|---|
| 事实/机制问答本身 | ads-knowledge-qa + roi3 FAQ/playbook（双向路由） |
| 实验设计（分流/轮转/样本量） | 未来独立 spoke；框架只供数据证据 |
| 方案论证/设计评审 | TD 流程；框架只供数据 |
| 进度跟踪/项目状态 | ads-okr-epic-report 系 |
| **用户ID纵向序列 / cohort / LTV / 复购率 / 留存曲线** | CRM / 商业智能（ROI3 是订单/桶级聚合，无用户粒度纵向追踪） |
| **6-12 周长期因果 / 撤券后衰减 / 习惯养成** | 预估模型 / 经济学反事实推断（**明确不做**；ROI3 诊断窗 7-14 天） |
| **自然推荐流量真隔离 / 对全站非广告 GMV 净影响** | 推荐系统（ROI3 无"去广告自然成交"口径） |
| **MP券 × Ads券 交叉归因** | 商务/平台政策层（voucher-efficiency 报告做单向对比，交叉归因超域） |
| **大促实时自适应 / 动态特征 / 供给侧预测** | 引擎 / 需求预测 / 供应链（ROI3 给边际快照+历史对标+保守基线+大促监测，实时自适应不做） |
