# 报告骨架/Report Skeleton

所有 spoke 产出统一遵循**总-分-附录**三段式。权威范本：`docs/personal/roger.li/roi3/analysis/voucher-efficiency-mp-vs-ads-2026-06-10.md`（结论速览一张表 + 关键问题直答 → 明细分析 → 附录 A–E）。

## 结构/Structure

**总**

1. **结论速览**——整体信息 + 可直接拿走的结论，优先用表格（指标表照下方"指标表标准格式"：每指标给 **打平流量绝对值 + 相对%** 双栏）；数字打头、带方向判断、说清 so-what；关键问题逐条直答。老板版（三句话版）只到这一层：赚不赚/达没达标/风险与下一步，每句带数字和日期。
2. **名词速查**——自创名词、非通用术语、内部代号集中解释（范本：发券强度边际报告的 15 词速查表）。正文不得裸用未解释的自创词和代号（KA/KP 编号等一律写通俗名称，代号只出现在文件路径里）。

**分**

3. **数据检验**——实验分流比例（SRM）、数据完整性（缺数 region、满日检查）、口径自检。检验不过，后文结论一律降级为"待定"。
4. **分层论证**——具体分析过程，金字塔展开。**故事线先行**：先用假设占位写故事线，数据逐格填充、证实或证伪；被证伪的假设保留并标注，不删。

**附录**

5. **口径与局限**——多口径差异显式列出（advv 与 broad_gmv 可能给出相反结论）；本次分析回答不了什么。
6. **可复现附录**——中间数据、数据源、复跑入口；正文引用 §案底。详见下方"案底/复现档硬规则"。

## 写作硬规则/Hard Rules

- **归档结构与命名（硬规则，每次分析都按此落盘）**：每个分析 = `docs/personal/<user>/roi3/experiments/` 下**一个独立文件夹**，**禁止再往 experiments/ 根目录平铺散文件**。
  - **文件夹名** = `<中文分析事项>-<YYYYMMDD>`（中文、简短点题，8 位日期无连字符）。例：`券消耗目标分地域达标-20260627`、`MY预算转移实验读数-20260613`、`KP10选券公式ecpmV影子实验-20260624`。
  - **文件夹内**：主报告 `<中文报告名>-<YYYYMMDD>.md`；伴生案底 `<同名>-repro.md`（同文件夹）；同一分析的多版/多角度报告（base-vs-exp、满日复核、不同口径）都放**同一文件夹**，不另起新文件夹。
  - 文件名用**中文 + 日期**，不用英文 slug。计划卡 `output.archive_path` 填到**文件夹层**（`.../experiments/<中文分析事项>-<YYYYMMDD>/`）；runner 在该文件夹内落报告 + 案底。若拿到的 `archive_path` 仍是 experiments/ 根目录或英文名，按本规范纠正为中文文件夹再落盘。
- **元信息头 + Git 链接（硬规则，每份报告与案底必带）**：标题 `#` 行的下一行（空一行后）必须是元信息行：
  `> **Contributors**: <user> ｜ **最后更新**：YYYY-MM-DD ｜ [GitLab](https://git.garena.com/shopee/search_recommend/ai-copilot/ads-workspace/-/blob/master/<repo相对路径>)`
  其中 `<repo相对路径>` = 文件在 repo 里的相对路径（如 `docs/personal/<user>/roi3/experiments/.../xxx.md`），`最后更新` = 本次出/改报告的日期。**报告和伴生案底都要加**，让人一眼点开直达 GitLab 源文件。这是 workspace markdown 标准（`rules/markdown-docs-standards.md`）对 `docs/` 下所有 md 的硬要求，ROI3 报告一律照办、不得遗漏；归档后用 grep `[GitLab](` 自检每个产物头部都有链接。
- **生成工具署名（硬规则，给 skill 做宣传）**：元信息行紧跟一行 skill 署名，让读者知道这报告是哪个 skill 产出的、可复用。格式（并入同一 blockquote）：
  `> 🛠️ 本报告由 **`/<入口 skill>`**（一句话定位）路由 → **`<spoke>`** spoke 生成。<可选：方法可复现/可沉淀的一句话宣传>`
  **如实写实际用到的 skill 链路**（hub → spoke → playbook），没用到的不硬安（如某 playbook 是分析后才沉淀的，就别回填说"用了它"）。例：`> 🛠️ 本报告由 **`/ads-roi3-analysis`**（Roger 的 ROI3 分析 hub）路由 → **`ads-roi3-experiment-analysis`** spoke 生成。` 既做溯源、也顺带宣传 skill 体系。
- **无验证不结论**：每个结论必须有经过验证的确切数据支撑；未验证的判断只能标"假设/待验证"，不得混入结论区。
- **通俗语言**：读者角色杂（算法/PM/老板），写到几个角色读完都立刻明白；专业术语带一句白话解释。
- **结论三分类**：每个结论标注类型——`[事实]`（实现事实）/ `[快照 YYYY-MM-DD]`（数据 snapshot，必须带时间窗）/ `[推断]`（设计推断）。
- **指标分三层，判断生效优先看上层**（核心原则）：基础指标有波动，绝对值对比易被噪声带偏；效率/边际指标抗波动，才是实验是否生效的真凭据。

| 层 | 指标 | 性质 | 用途 |
|---|---|---|---|
| 基础 | advv、voucher_cost、gmv_995_v2/broad_gmv、rev、曝光/点击/订单 | 有规模/季节/流量波动 | 看量级、看趋势、**落地验证**（看方向，不当效果） |
| 效率 | 利润率 = value/cost − 1、ROI、成本倍数 R | 比值，抗规模波动 | 判断水平好坏 |
| 边际 | 边际利润率 = Δvalue/Δcost − 1 | 导数，需响应曲线/多档拟合 | 该加还是该减——决策真凭据 |

**判断优先级：边际 > 效率 > 基础。** value 口径须显式（advv 单口径 vs advv+broad_gmv/4，结论可能反向）。

- **指标表标准格式（结论速览必备，最重要的一条呈现规则）**：每个指标**同时给两样，缺一不可**——
  1. **打平流量后的绝对值**：各实验臂归一到等流量再列绝对值（如 base 20%（两桶）÷2 对齐 exp 10%，或都缩放到 100%）。给**算法**看量级、看 sanity、看 AA 噪声底。
  2. **相对变化 %**（vs base）：给**老板**看结论（涨跌、达没达标）。

  只给 % → 丢了量级和噪声判断（算法没法 sanity）；只给绝对值 → 老板看不出结论。**范本 = AB 平台报表式样**：base 绝对值打头，各臂绝对值后跟 `(±x%)`。落地形态：结论速览第一张表 = 指标 × 实验臂 ×（归一绝对值 ｜ 相对%），高风险时再加 AA 噪声列。这是算法+老板都必看、必不可少的数据，所有 spoke 出数一律照此。**渲染纪律**：每个 markdown 表格前面留一空行（紧跟在 `**加粗标题**` 后无空行时，GitLab/部分渲染器不解析成表、会显示成裸 `|` 文本——2026-06-22 踩过）；表头/分隔行/数据行列数必须一致。

- **新模型必出 pcoc（硬规则）**：凡分析涉及**新模型 / 模型变体 / 模型 bake-off**，报告必须包含 pcoc 三件套——① **整体 pcoc**（各组 pcr_v vs 实际 cvr）② **各组 pcoc**（模型层单独、对其它叠加层混合）③ **分折扣档 pcoc 矩阵**（模型 × 折扣档；聚合会掩盖深档过预测，深档常是半数发券所在，必须分档看）。口径：pcoc=预测CR/实际CR，越低越不过预测、1.0=完美；用 1h order label 时绝对值偏高，**只看组间/档间相对与排序**；档=realized discount_ratio 分箱近似名义折扣档。**cr / uplift cr**：trace 字段在则一并出；若 `pcr_0`(uplift_pcr0) 已下线为空，标注"需 Spark/ego 解 `bid_rerank_trace`"，不要静默省略。
- **指标套餐**：按问题类型带默认套餐，删减须显式说明——

| 问题类型 | 默认套餐 |
|---|---|
| 评估/读数（实验） | 全漏斗（曝光/点击/订单/GMV）+ 券成本 + advv + **效率（利润率）+ 边际利润率**；禁止只看发券率或单一基础指标 |
| 评估（**新模型/模型变体**） | 在上一行基础上**必出 pcoc**（硬规则，见下）：① 整体 pcoc ② **各组 pcoc**（模型层单独、对其它层混合）③ **分折扣档 pcoc 矩阵**（模型×档）；trace 字段在则一并出 cr / uplift cr |
| 探索（响应） | 响应曲线 + 边际利润率 + 稳定性（trailing 窗 CV 收敛、bootstrap CI） |
| 评估（施策类，按维度调系数/预算） | 见 §施策类实验评估范式：①落地验证 ②效率/边际读数 ③维度分解（边际×份额×CI）④合成 |
| 校验（对账） | 两侧口径定义、diff 绝对/相对值、容差判断 |
| 诊断 | 异常指标 + 上游链路各层证据（支持/反驳/缺失三分） |

- **案底/复现档（硬规则，出报告必留）**：每份报告必须留一份**持久案底**，目的=任何人能照此**复现分析数据**。位置：报告**同目录**的伴生文件 `<报告名>-repro.md`（**不放 `tmp/`——tmp 会清**；SQL 也复制到同目录 `sql/` 或直接全文内联进 repro）。案底含三件，缺一不可：
  1. **SQL 全文**——每条实际执行的 query 原文（含表名、时间窗、过滤、剔除项），不写"见 tmp/xxx.sql"这种会失效的指针。
  2. **分析口径**——表 / 字段 / 过滤 / **桶↔exp_tag/ab_sign 映射** / 归一方式 / 单位 / 已知坑（引 `data-sources.md` 已登记口径，新口径补登记）。
  3. **整理后的分析 prompt**——把本次分析**蒸馏成一段自包含、可直接复跑的指令**（目标/决策、实验与桶映射、时间窗、口径、要算哪些指标、归一与输出格式）。让后人/Agent 拿这段 prompt + 上面的 SQL 与口径就能一键重跑。可由分析计划卡（`plan-card.schema.yaml`）扩展而来。
- **运行天数门槛（诚实降级，硬规则）**：边际/打平/增量结论需 trailing ≥14 满日才坐实。**数据不足时报告头部强制标注可信度**——坐实（≥14d，带 CI）/ 方向信号（7-13d，只说涨跌不下结论）/ 不足（<7d 或未放量稳态，仅记现象、显式标"数据不够、暂不知道"）。禁止把方向信号当坐实结论给决策者（尤其老板级合成）。

## 施策类实验评估范式/Policy-Experiment Evaluation Pattern

适用：任何"按维度施加差异化策略"的实验——调系数/预算/强度/规则，维度可为 region / entrance / 品类 / 人群 / 价格带 / 时段。这是个**可迁移模板**：

**Step 0 系数复合关系确认（前置硬步骤，像口径确认）**：线上目标量（强度/出价/预算系数）常是**多个实验系数复合**（连乘/相加/覆盖）。先问清：本实验是哪一层、和哪些实验复合、是否正交分流。不问清会判断错（如误把"被复合的某层系数"当固定值、误判"单点无 dose"）。**红利**：若有正交叠加的 dose 实验，可在本实验各桶内按它切片，**实测"调整后工作点"的边际**（二维交叉分桶），而非只能读平均利润率或离线外推。

1. **落地验证（动作-响应闭环：意图 → 动作 → 响应）**：施加的动作在维度基础指标上按预期方向发生了吗？（例：EL 边际负 → 系数调 1.13 抑制 → EL 券成本真的降了吗）。**没落地则止步**，先查执行。机制层证据，像 SRM 一样是门槛。
2. **效率/边际读数**：算利润率、边际利润率（带 CI），看效率层而非基础绝对值。
3. **维度分解（边际 × 份额 × 置信）**：边际定方向、份额定影响力（份额小的别费劲）、CI 定可靠性（CI 跨加权均值的不强动）。
4. **合成判断**：加权回全局 + 结论 + 动作。多维叠加注意**重复抑制**（系数相乘破坏预算中性，如 EL×ent29=1.36 超界）。

**提升类 vs 打平/趋同类（目标不同、看法不同）**：
- **提升类**：目标是某指标均值上移 → 看实验组 vs 对照的 diff。
- **打平/趋同类**（如"打平各品类边际 d(value)/d(cost)=λ"）：目标是**维度间趋同** → 看 ① 各维度边际的**离散度（极差/方差）调整后是否下降** ② 是否趋近共同 λ。**难点**：调整后的边际本身难测（单工作点测不出边际）——解法是 Step 0 的连乘 dose 红利（在新工作点周围有 dose 才能拟切线），或在新策略基线上再叠 dose 实验。⚠️ 若响应近线性（曲率 b≈0），移动工作点边际几乎不变，"打平"只能靠一阶移预算（把预算从绝对低边际维度移走），而非二阶边际趋同——需确认实验的真实机制。
