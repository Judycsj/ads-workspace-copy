# 评分标准/Scoring Rubric

本文件定义 `ads-kb-eval` 技能的 1-5 分评分标准。

---

## 评分量表/Scoring Scale

### 5 分 — 完全覆盖/Full Coverage

**定义**: 路由到的 KB 文件完整包含回答问题所需的全部信息，可以直接、准确、完整地回答问题。

**判断标准**:
- 问题涉及的所有概念、流程、数据在文件中都有明确描述
- 信息足够详细，无需查阅其他资源即可理解
- 包含具体的配置、参数、代码路径等可操作信息（如适用）

**示例**:
- 问 "召回有哪些队列" → 文件中有完整的队列清单表，含 Search/Discovery/Shop/Live/Video/Brand 全场景
- 问 "dws_advertise_performance_1d 表有哪些字段" → DataMap column_info.md 有完整字段列表

### 4 分 — 基本覆盖/Mostly Covered

**定义**: KB 文件包含回答问题的核心信息，但有小幅信息缺失，不影响理解问题的本质答案。

**判断标准**:
- 核心概念和主要流程有清晰描述
- 可能缺少部分细节（如某个边缘场景、某个可选参数）
- 回答的主干完整，只是不够"完美"

**示例**:
- 问 "召回双塔训练范式" → 文件有 LongSeq 双塔结构和 EGO Serving 描述，但缺少具体超参数值
- 问 "bidding 冷启动策略" → 文件有策略框架描述，但缺少某个特定广告类型的细节

### 3 分 — 部分覆盖/Partially Covered

**定义**: KB 文件包含与问题相关的方向性信息，能提供上下文和线索，但缺少回答问题的关键细节。

**判断标准**:
- 文件提到了问题相关的主题，但没有深入展开
- 只有概念性描述，缺少具体实现、配置或数据
- 需要查阅其他资源才能完整回答

**示例**:
- 问 "AdsInfoFilter 过滤链细节" → 文件提到过滤链存在，但没有详细的过滤条件列表
- 问 "AB 实验平台如何创建实验" → 文件有实验平台简介，但缺少操作步骤

### 2 分 — 有限覆盖/Limited Coverage

**定义**: KB 文件中只有零散的相关信息，无法形成有效回答。信息散落在不同段落，缺乏系统性。

**判断标准**:
- 仅在其他主题的描述中附带提到相关内容
- 没有专门的章节或段落讨论问题主题
- 信息碎片化，拼凑后也难以形成完整答案

**示例**:
- 问 "video ads bundle 是什么含义" → 文件中某处提到 video ads 但没有解释 bundle 概念
- 问 "某个 Hive 表的 SQL 查询模式" → DataMap 只有 table_info 没有 sql_patterns

### 1 分 — 未覆盖/Not Covered

**定义**: 路由到的 KB 文件中没有与问题相关的信息，或问题主题完全不在任何 KB 文件的覆盖范围内。

**判断标准**:
- 搜索关键词在文件中无任何匹配
- 路由失败：没有找到合适的目标文件
- 问题涉及的领域完全不在当前 KB 覆盖范围

**示例**:
- 问某个尚未建设的模块知识
- 问 KB 未覆盖的外部系统或跨团队系统细节

## 低分理由模板/Low Score Reason Templates

当评分非 5/5 时，**必须**提供以下信息：

### 格式

```
缺失: <具体缺少什么信息>
建议: 补充到 <§X.Y 文件名> 的 <H3/H4 章节标题>
```

### 常见低分理由类型

| 类型 | 理由模板 |
|------|---------|
| 概念缺失 | "缺失: 文件中未定义 `<术语>` 的含义和使用场景" |
| 流程缺失 | "缺失: 未描述 `<操作>` 的端到端流程步骤" |
| 配置缺失 | "缺失: 缺少 `<组件>` 的具体配置参数和取值" |
| 数据缺失 | "缺失: 未列出 `<表/字段>` 的完整字段定义或口径说明" |
| 代码缺失 | "缺失: 未提供 `<功能>` 对应的代码仓库路径和入口文件" |
| 场景缺失 | "缺失: 未覆盖 `<场景>` (shop/live/video 等) 的差异说明" |

## 指标查询类评分标准/Metric-Query Scoring Rubric

指标查询类问题评估 KB 文件是否同时提供**指标现状描述**和**查询方式**两个维度。

### 5 分 — 现状 + 查询方式均完整

**定义**: KB 文件完整描述了指标的当前状态、典型值范围、业务含义，**且**提供了明确的查询方式。

**判断标准**:
- 有指标的定义、计算公式、业务含义
- 有指标的典型值范围或当前状态描述
- 有明确的查询方式：dashboard 链接、Hive 表名 + SQL 示例、技能名（如 `/ads-text2da`）

### 4 分 — 现状基本完整 + 查询方式不够具体

**定义**: 现状描述基本覆盖，查询方式有提及但不够具体（如只提了表名没给 SQL，或只说"可在 Grafana 查看"但没给面板路径）。

### 3 分 — 仅有一半

**定义**: 仅有现状描述或仅有查询方式，缺另一半。

**示例**:
- 有 PCoC 的定义和计算公式，但没有查询方式 → 3 分
- 有查询用的 Hive 表名，但没有指标含义描述 → 3 分

### 2 分 — 两个维度都不完整

**定义**: 现状和查询方式都有零散信息，但都不成体系。

### 1 分 — 无相关信息

**定义**: KB 中无该指标的任何信息。

### 指标查询低分理由附加模板

| 类型 | 理由模板 |
|------|---------|
| 缺现状 | "缺少指标现状描述: 未说明 `<指标>` 的典型值范围和业务含义" |
| 缺查询方式 | "缺少查询方式: 建议补充 `<指标>` 的 dashboard 链接 / Hive 表名 / 查询 SQL" |
| 两者均缺 | "缺少指标现状描述和查询方式: 建议在 `<§X.Y 文件>` 新增 `<指标>` 专节" |

## 评分原则/Scoring Principles

1. **基于文件内容，非模型知识**: 只评估 KB 文件中是否有相关信息，不考虑模型自身是否能回答
2. **综合多文件**: 如果一个问题路由到多个文件，综合所有文件内容评分
3. **宽松路由，严格评分**: 路由阶段可以多匹配几个文件，但评分时严格按照文件实际内容判断
4. **可操作性加分**: 文件提供了具体的代码路径、配置参数、操作步骤 → 在同一档内偏高
5. **一致性**: 同类问题的评分标准一致，不因评测顺序不同而波动
