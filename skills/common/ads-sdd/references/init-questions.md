# init mode 引导问题

> 按开发类型分组的交互式引导问题，供 init mode Step 5/6 使用。

## 通用引导问题（01-scope-and-workflow）

### 权威边界

- 这个系统/模块的 spec 存放在本目录（Layer 1），实现层是什么？
  - skill → `skills/common/ads-{domain}/`
  - code → `projects/gitlab/{repo}/`
  - docs → `templates/{domain}/`
- 有没有用户指南层（Layer 3）的计划？

### 生命周期

- 这个系统/模块的核心生命周期是什么？列出主要阶段（用 -> 连接）
- 每个阶段的关键动作是什么？
- 有没有循环或条件分支？

### 工具链路

- 用户通过什么方式触发各阶段？（命令、UI、API）
- 各阶段之间的数据流是什么？（哪个阶段产出被哪个阶段消费）

### 接口表

- 这个系统/模块包含哪些组件/技能？
- 每个组件的阶段、输入、输出、上下游关系是什么？
- 请填写接口表（7 列：组件/阶段/输入/输出/上游/下游/Spec 关联）

## Skill 类型引导问题（02-core-concepts）

### 层级模型

- 这个领域有哪些核心概念？（列出 3-5 个）
- 它们之间的层级/包含关系是什么？

### 类型系统

- 有哪些需要枚举定义的类型？（状态、类别、模式等）
- 每个枚举的允许值和含义？

### 状态模型

- 系统中有哪些需要跟踪状态的实体？
- 每个实体的状态流转规则？（进入条件、退出条件）

### 评估模型（可选）

- 如何衡量这个模块的质量/效果？
- 有哪些关键指标？

## Code 类型引导问题（02-data-model）

### Schema 概览

- 数据存储在哪里？（Proto、JSON、SQL 等）
- 核心 schema 文件路径和用途？

### 实体定义

- 核心实体有哪些？
- 每个实体的关键字段、类型、约束？
- 实体之间的关联关系？

### 状态机

- 有哪些需要状态流转的实体？
- 状态枚举和转换规则？

### API 契约

- 对外提供哪些 API / RPC？
- 每个接口的请求/响应格式？

## Docs 类型引导问题（02-document-system）

### 文档结构

- 文档的核心章节有哪些？
- 每个章节的内容职责？
- 章节之间的依赖关系？

### 模板规则

- 哪些章节是必填的？哪些可选？
- 有没有格式约束（如字数、表格结构）？
- 有没有与其他系统的交互（如知识库索引）？
